# 内容生产 Agent 第一版 PRD 与用户故事

状态：阶段 2 已完成  
版本：v1.0  
日期：2026-07-30

## 1. 文档边界

本文档把已经确认的产品定义整理为 12 阶段流程中的阶段 2 交付物。

本文档不新增产品范围。详细业务事实以 `stage-1-product-definition.md` 为准；技术实现以阶段 5 技术方案为准。

## 2. 产品目标

为公司内部内容生产用户提供一个桌面网页 Agent，使用户能够从小说、非小说文本或热门漫剧视频出发，经过可查看、可编辑、可确认、可恢复的过程，得到分集剧本。

第一版最终输出：

```text
一部作品中的一个当前最终分集剧本
```

最终确认前，允许多个 Skill 和多个 Run 形成多个候选剧本，且历史版本必须保留。

## 3. 目标用户

- 公司内部内容生产业务用户；
- 熟悉聊天模型，但不熟悉复杂 Agent 操作；
- 需要从不同来源快速获得漫剧生产前剧本；
- 需要在生成过程中修改、确认和恢复，而不是只接收一次性回答。

## 4. 第一版范围

### 4.1 P0

- 作品入口和作品工作台；
- 一个通用 Agent Shell；
- 小说转剧本 Skill；
- 非小说文本转剧本 Skill；
- 视频参考创作 Skill；
- 通用文本、图片、文件和视频上传；
- 任务状态、暂停、恢复、重试和取消；
- Artifact 阅读、编辑、AI 修改、重新生成和版本历史；
- 主要步骤确认；
- Candidate 和唯一 Final Selection；
- TXT、DOCX 导出；
- 视频原文件 7 天保留。

### 4.2 第一版不做

- 登录、个人空间和复杂权限；
- 移动端和手机浏览器适配；
- 跨作品引用；
- 多部参考剧任意融合；
- 独立音频输入；
- 自动查重和自动版权结论；
- 独立 OCR/ASR 交叉验证管线；
- 分镜和视频片段生成；
- 任意安装第三方 Skill 的开放插件市场。

## 5. 核心用户故事

| ID | 优先级 | 用户故事 | 验收结果 |
|---|---|---|---|
| US-01 | P0 | 作为内部用户，我可以创建、打开、重命名和删除作品，以便长期管理不同创作任务。 | 作品数据隔离；刷新和重新打开后恢复当前状态 |
| US-02 | P0 | 作为用户，我可以直接描述需求或显式引用 Skill，以便用熟悉的聊天方式开始。 | 明确意图正确路由；模糊意图先追问；引用 Skill 不立即创建 Run |
| US-03 | P0 | 作为用户，我可以上传通用材料，以便 Agent 根据意图使用文本、图片或视频。 | 单纯上传不自动启动 Run；图片意图不明时追问 |
| US-04 | P0 | 作为小说用户，我可以上传小说并确认目标集数和时长，以便逐步生成分集剧本。 | 故事圣经、拆集、分集卡和剧本依次产生并确认 |
| US-05 | P0 | 作为非小说用户，我可以上传大纲、集纲或设定，以便补全为分集剧本。 | 材料事实与新增创作内容分开；关键缺口先询问 |
| US-06 | P0 | 作为视频用户，我可以分批上传同一部剧的视频，以便逐集解析后完成整剧分析和参考创作。 | 用户明确上传完成后才聚合；支持排序、缺集确认、单集失败重试 |
| US-07 | P0 | 作为用户，我可以阅读和编辑每个主要产物，以便控制生成方向。 | 手动编辑形成新版本；旧版本可追踪 |
| US-08 | P0 | 作为用户，我可以通过 Agent 要求修改当前产物或选区，以便减少复杂表单操作。 | 修改目标准确；AI 修改与手动编辑使用同一版本机制 |
| US-09 | P0 | 作为用户，我可以重新生成当前步骤或单集，以便获得不同版本。 | 重新生成不覆盖旧版本；下游影响先展示 |
| US-10 | P0 | 作为用户，我可以确认主要步骤后继续，以便明确控制每次关键推进。 | 只有明确确认才改变审批状态；整个剧本统一确认 |
| US-11 | P0 | 作为用户，我可以暂停、恢复、重试或取消 Run，以便应对长任务和失败。 | 四种操作语义分离；成功子任务不被无关重做 |
| US-12 | P0 | 作为用户，我可以在不同作品之间切换，以便等待任务时处理其他作品。 | 同一作品只有一个活动写 Run；不同作品允许并行 |
| US-13 | P0 | 作为用户，我可以保留多个候选剧本并选择一个最终稿，以便比较不同路径的结果。 | 候选不互相覆盖；改选最终稿需要确认 |
| US-14 | P0 | 作为用户，我可以导出最终剧本，以便进入后续漫剧生产。 | TXT、DOCX 内容来自同一确认版本 |
| US-15 | P1 | 作为用户，我可以查看来源和版本历史，以便判断当前内容从哪里生成。 | 上游版本、来源文件和修订记录可追踪 |
| US-16 | P1 | 作为没有匹配 Skill 的用户，我仍可以与通用 Agent 对话，以便理解当前能力缺口。 | Agent 不伪造不存在的执行能力，并说明需要什么能力 |

## 6. 三条主链

### 6.1 小说转剧本

```text
来源输入
-> 生成配置
-> 故事圣经
-> 原文拆集
-> 分集卡
-> 分集剧本
-> 质量审核
-> Candidate
```

### 6.2 非小说文本转剧本

```text
来源输入
-> 生成配置
-> 素材库
-> 故事种子
-> 整剧蓝图
-> 分集卡
-> 分集剧本
-> 质量审核
-> Candidate
```

### 6.3 视频参考创作

```text
分批上传视频
-> 逐集解析
-> 用户确认上传完成和完整度
-> 参考剧本
-> 整剧分析
-> 改编方案
-> Adaptation Brief
-> 复用非小说后续创作流程
-> 分集剧本
-> 质量审核
-> Candidate
```

## 7. 通用业务规则

1. 一部作品对应一个连续工作台和一个主对话。
2. 一个 Run 只选择一条主链，不做未定义的任意融合。
3. 同一作品同时只允许一个活动写 Run。
4. 运行中的当前作品输入框禁用，用户通过运行控件暂停或取消。
5. 不同作品允许并行，总并发上限配置化。
6. 模型回复不能代替确认、取消或最终稿选择。
7. 用户可见主要产物支持编辑、AI 修改和重新生成。
8. 修改已确认上游时，必须先展示下游影响。
9. 用户可以保留下游，也可以从最早受影响步骤重新生成。
10. 版本和依赖不能依赖聊天历史或模型记忆。
11. 视频未收到明确“上传完成”意图前，不进入整剧聚合。
12. 缺集继续必须由用户显式确认，并标记材料完整度。
13. 视频源文件 7 天后自动删除，派生产物和来源元数据随作品保留。
14. 作品只有一个当前最终稿，历史候选和历史最终版本不删除。

## 8. 异常与恢复

| 场景 | 产品行为 |
|---|---|
| 意图不明确 | Agent 提出最少必要问题，不启动 Run |
| 材料不足 | 说明缺口；关键设定不自行补写 |
| 配置缺失 | 补齐目标集数、时长等必需配置后再启动 |
| 模型超时或结构错误 | 当前任务失败，保留错误和重试 Cursor |
| 单集视频失败 | 只重试失败单集，不回滚成功单集 |
| 缺集或重复集号 | 阻止直接聚合，允许人工排序和显式不完整继续 |
| 上游修改 | 展示影响范围，等待用户选择保留或重新生成 |
| 版本冲突 | 拒绝静默覆盖，返回当前最新版本 |
| 服务或页面重启 | 从 Runtime 和事件序列恢复任务、审批和产物 |
| 视频源已到期 | 禁止重新解析，保留并允许使用已有派生产物 |
