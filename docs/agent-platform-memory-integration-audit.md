# Sandbox Memory 接入核对

日期：2026-09-14，G4.101。范围为原GAP-17/SDK-06及W5/W8，不新增产品方向。本报告不是功能验收通过记录。

## 初始核查事实（G4.101，后续变更见下文）

- `experiments/openai-agents-sidecar/src/content_agent_sidecar/native_capabilities.py` 的生产装配仅加入 Filesystem、Shell、Skills，没有 Memory。
- `native_runner.py` 的三模式共用工作区负责执行内恢复；新执行从项目工作文件及固定Skill源装配，不能据执行内快照恢复宣称跨执行长期记忆已存在。
- 用户规则通过原有指令快照和规则页面管理。Session管理上下文，Goal保存持续目标；三者不能代替SDK Sandbox Memory。
- 本地固定SDK `agents/sandbox/capabilities/memory.py` 声明Memory读取依赖Shell；默认live_update还依赖Filesystem。读取入口为相对目录下的`memory_summary.md`，不是平台规则数据库。
- SDK `memory/manager.py` 在会话关闭前flush，写rollout、提取并整合记忆；`_memory_run_config`新建仅含sandbox session的RunConfig，未继承调用者的完整配置。工作器及第二阶段存在捕获异常后记录日志的路径，关闭返回不能直接当作记忆生成成功。
- SDK `memory/phase_two.py` 创建独立SandboxAgent并调用Runner，max_turns=500；并未走本项目prepare_native_workspace的工具装配。
- `native_execution.py` 要求Shell有原审批调用身份。未通过平台包装器的整合Agent不能假定可调用Shell；这是待适配的不兼容边界，不是已经发生的未授权执行。
- 固定SDK无网络对象构造探针已执行：Memory类型为memory，依赖filesystem/shell，注册1个关闭钩子，默认提取模型gpt-5.4-mini、整合模型gpt-5.5。它们是依赖默认值，**不是当前平台实际使用模型**；本次没有调用模型或启动环境。

## 必须接通的原链路

1. 权限和生命周期：明确记忆所属用户/项目、启用与读取授权，独立于上传Skill资源及规则；撤权、停用、删除/遗忘后不能由旧执行再次写回。
2. SDK原生读取：从权威持久版本装入隔离工作区，由SDK Memory提供指令和读取能力；不可把规则文本改名为memory_summary来宣称完成。缺失、禁用和不可用分别处理，三模式一致。
3. SDK原生生成：明确使用现有获准模型对象和平台策略，不静默使用依赖默认模型。不另写模型执行循环；先验证公开SDK扩展点能让整合工具经过现有审批/审计/原执行身份，再接生产。若固定SDK无足够扩展点，记录具体兼容阻塞，不通过修改site-packages或绕开审批硬接。
4. 持久交付：生成的记忆、来源与版本进入权威存储，独立CAS/去重、当前权限、配额、审计及失败恢复；新执行读取同一确认版本。工作区关闭或生成最终文本均不是持久成功证据。
5. 用户操作：可查看、修改、停用及遗忘，明确确认后执行；失败/结果未知保留原请求，不自动重复生成。隐私范围不可因项目共享扩大。
6. 验收：实际固定SDK和模型替身的生成/读取/失败对照，三模式恢复、并发写入、撤权与遗忘防复活、受影响全量；之后真实Go/OCI/模型/用户入口联合。当前外部限制保留，不用替身关闭真实门禁。
