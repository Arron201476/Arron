# 内容生产 Agent 信息架构与低保真原型合同

状态：开发侧自测通过，等待产品负责人验收  
版本：v0.2  
日期：2026-07-30

## 1. 阶段目标

阶段 3 只回答：

- 用户从哪里进入；
- 页面如何组织；
- 信息放在哪里；
- 核心任务如何从入口走到结果；
- 不同状态如何被发现和处理。

阶段 3 不决定最终颜色、字体、阴影、动效和组件视觉细节，也不开始正式 React 实现。

## 2. 顶层页面

第一版只有两个主要页面：

```text
/projects
  作品入口页

/projects/{project_id}
  作品工作台
```

以下内容属于页面内视图、抽屉或对话框，不新增顶层页面：

- 新建、重命名、删除作品；
- Skill 菜单；
- 上传队列；
- 版本历史；
- Candidate 和最终稿选择；
- 运行记录；
- 下游影响预览；
- 服务和连接状态。

## 3. 作品入口页

### 3.1 页面职责

- 创建作品；
- 搜索和打开作品；
- 查看作品当前状态和待办；
- 通过自然语言或上传材料快速开始；
- 明确提示第一版为公司内部共享空间。

### 3.2 信息层级

```text
全局标题与共享空间提示
-> 快速开始输入
-> 新建作品主操作
-> 搜索与状态筛选
-> 最近作品列表
-> 删除、重命名等行级操作
```

### 3.3 作品列表最小字段

- 作品名称；
- 当前状态；
- 当前或最近 Skill；
- 最近更新时间；
- 当前待办，例如“确认故事圣经”；
- 打开操作；
- 更多菜单。

## 4. 作品工作台

### 4.1 页面职责

围绕一部作品持续承载：

- 材料；
- Skill 运行；
- 过程产物；
- 剧本；
- 审批和版本；
- Candidate 和最终稿；
- Agent 对话。

### 4.2 固定结构

```text
顶部 Project Header

左侧：流程与产物目录
中间：当前 Active Workspace
右侧：General Agent Panel
```

### 4.3 Project Header

必须包含：

- 返回作品入口；
- 作品名称；
- 当前 Skill；
- 当前 Run 状态；
- Candidate / 最终稿入口；
- 导出入口；
- 必要的服务状态。

不包含模型名、Prompt 调试和内部 Step ID。

## 5. 左侧流程与产物目录

左侧只负责定位，不直接执行生成。

固定分组：

```text
材料
当前流程
剧本
候选与最终稿
历史记录
```

每项显示：

- 用户可读名称；
- 状态；
- 是否待确认；
- 是否受上游影响；
- 是否存在失败；
- 是否为当前选中项。

内部 Artifact 默认不显示。

## 6. 中间 Active Workspace

中间区域只承载当前对象：

- 材料阅读和来源信息；
- 结构化过程产物；
- 剧本分集阅读与编辑；
- 视频批量任务表；
- 剧本分析；
- Adaptation Brief；
- Candidate 比较和最终稿阅读；
- 版本历史。

中间区域可以提供确定性操作：

- 编辑；
- 保存；
- 重新生成；
- 确认；
- 查看版本；
- 查看来源；
- 查看下游影响。

中间区域不新增第二个自由 AI 输入框。AI 修改统一从右侧 Agent 发起。

## 7. 右侧 General Agent Panel

右侧是唯一通用 AI 指令入口。

固定结构：

```text
Agent 状态
-> 对话时间线
-> 当前运行进度或审批提示
-> 上下文附件和 Skill 引用
-> 输入框
```

输入框上方提供 Skill 按钮：

- 小说转剧本；
- 非小说文本转剧本；
- 视频参考创作。

点击后只插入引用，不立即启动 Run。

当前作品存在活动写 Run 时：

- 输入框禁用；
- 显示当前步骤和批量进度；
- 提供暂停或取消；
- 不允许继续闲聊或启动冲突任务。

## 8. 核心导航关系

```text
作品入口
├─ 新建作品 -> 作品工作台 / 空状态
├─ 快速开始 -> 自动创建作品 -> Agent 识别意图
└─ 打开作品 -> 恢复上次视图和当前状态

作品工作台
├─ 左侧目录 -> 中间切换当前对象
├─ Agent 消息 -> 启动询问、修改或流程动作
├─ Approval -> 中间查看完整产物 -> 用户确认
├─ Candidate -> 候选比较 -> 最终稿选择
└─ 返回 -> 作品入口
```

## 9. 小说路径

```text
创建或打开作品
-> 上传小说或粘贴原文
-> 显式引用 Skill 或自动识别
-> 补齐目标集数和时长
-> 查看并确认故事圣经
-> 查看并确认原文拆集
-> 查看并确认分集卡
-> 逐集生成并统一确认剧本
-> 自动质量审核
-> 形成 Candidate
-> 选择最终稿或继续修改
```

原型至少需要覆盖：

- 小说材料已上传；
- 生成配置待确认；
- 过程产物待确认；
- 剧本生成中；
- 剧本可编辑；
- 质量审核需要返工；
- Candidate 已产生。

## 10. 非小说路径

```text
创建或打开作品
-> 上传大纲、集纲或设定
-> 显式引用 Skill 或自动识别
-> 判断材料完整度
-> 必要时确认扩写策略
-> 确认素材库
-> 确认故事种子
-> 确认整剧蓝图
-> 确认分集卡
-> 生成并确认剧本
-> 质量审核
-> Candidate
```

原型至少需要覆盖：

- 材料完整度提示；
- 关键缺口追问；
- 扩写策略确认；
- 与小说链共享的分集卡和剧本视图。

## 11. 视频参考创作路径

```text
创建或打开作品
-> 分批上传视频
-> 单集后台解析
-> 用户明确上传完成
-> 检查集号、重复、缺集和失败
-> 必要时人工排序或确认不完整继续
-> 统一确认参考剧本
-> 确认整剧分析
-> 选择或修改改编方案
-> 编辑并确认 Adaptation Brief
-> 补齐新剧本目标集数和时长
-> 进入共享非小说后续流程
-> 新剧本 Candidate
```

视频批量工作区必须显示：

- 文件名；
- 集号和顺序；
- 时长；
- 上传状态；
- 解析状态；
- 单集重试；
- 单集剧本入口；
- 缺集和重复诊断；
- 上传完成主操作。

## 12. 通用编辑与确认路径

```text
打开产物
-> 编辑或选择文本
├─ 手动编辑 -> 保存新版本 -> 待重新确认
├─ 要求 AI 修改 -> Agent 展示目标 -> 新版本 -> 待重新确认
└─ 重新生成 -> 影响预览 -> 新版本 -> 待重新确认
-> 查看完整版本
-> 明确确认
-> 进入下一步骤
```

“保存”“确认”“重新生成”必须是三个不同操作。

## 13. 页面状态矩阵

| 状态 | 入口页 | 工作台 |
|---|---|---|
| 无作品 | 快速开始和新建作品 | 不适用 |
| 空作品 | 显示等待添加材料 | 中间显示材料空状态，Agent 可对话 |
| 意图不明确 | 显示最近活动 | Agent 提出最少必要问题 |
| 等待配置 | 显示待确认 | 中间展示配置，Agent 提醒确认 |
| 运行中 | 显示步骤和进度 | 输入框禁用，显示暂停/取消 |
| 等待确认 | 显示待确认 | 中间展示完整产物和确认操作 |
| 已暂停 | 显示已暂停 | 显示恢复和修改入口 |
| 失败 | 显示失败 | 显示原因、失败位置和重试 |
| 上游已修改 | 显示待处理 | 显示影响范围和两个处理选择 |
| 已完成 | 显示剧本已完成 | 显示 Candidate、最终稿和导出 |
| 视频源已到期 | 保留作品 | 禁止重新解析，派生产物仍可用 |
| 服务断开 | 保留本地视图 | 禁用写操作并显示恢复状态 |

## 14. 低保真原型范围

低保真原型必须使用确定性模拟数据连接以下状态，不能只提供彼此孤立的可点击 Frame：

1. 作品入口；
2. 新建空作品；
3. 小说过程产物待确认；
4. 非小说材料完整度和扩写策略；
5. 视频分批上传和逐集解析；
6. 视频缺集确认；
7. 剧本分集编辑；
8. 运行中输入禁用；
9. 质量审核返工；
10. Candidate 和最终稿选择。

原型使用真实中文产品文案和合理长度样例，但不确定最终视觉风格。

所有可见控件必须可以执行并产生明确下一状态，或禁用并说明原因。阶段 3 的完整验收路径、异常分支和交互语义以 `stage-3-prototype-acceptance-matrix.md` 为准。
