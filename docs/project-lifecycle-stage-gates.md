# 内容生产 Agent 12 阶段总流程与准入门禁

状态：项目阶段唯一真源  
版本：v1.0  
日期：2026-07-30

## 1. 目的

本文档是内容生产 Agent 项目的唯一阶段编号真源。

项目统一采用以下 12 个阶段：

1. 需求澄清；
2. PRD / 用户故事；
3. 信息架构 / 原型；
4. UI / UE 规范；
5. 技术方案；
6. 前端实现；
7. 后端 / API / 数据库；
8. 测试计划；
9. E2E 验证；
10. 部署上线；
11. 监控维护；
12. 复盘迭代。

其他文档中的“阶段 1、阶段 2、阶段 3”属于此前形成的项目内批次名称，不能继续作为总项目阶段编号。

## 2. 阶段口径规则

1. 项目汇报中的“当前阶段”只引用本文档的 12 阶段编号。
2. Runtime、Capability 或迁移计划内部使用“步骤”“批次”或“里程碑”，不再称为项目阶段。
3. 后续阶段已经形成的代码和文档可以保留为提前资产，但不能据此宣称对应阶段已经完成。
4. 进入下一阶段前，必须同时满足：
   - 当前阶段交付物齐全；
   - 当前阶段门禁逐项通过；
   - 阶段遗留项已解决或明确转入后续阶段；
   - 产品负责人明确确认进入下一阶段。
5. 阶段可以存在调研和 Spike，但正式状态一次只能有一个“当前主阶段”。
6. 不因后续实现已经存在而跳过信息架构、原型、UI/UE 或测试准入。

## 8. 阶段 3 完成门禁

- 第一版页面数量和页面职责无冲突；
- 用户可以从入口页创建或打开作品；
- 用户可以在同一个工作台完成三条 Skill 的主要操作；
- 三栏工作台没有重复的 AI 指令入口；
- Skill 显式引用、自动路由和模糊追问有明确入口；
- 主要 Artifact、视频批量任务、Candidate 和最终稿均有稳定定位；
- 运行、等待确认、失败、暂停和完成状态可从原型中识别；
- 编辑、AI 修改、重新生成和确认没有互相混用；
- 原型覆盖桌面目标尺寸，不引入移动端范围；
- 产品负责人完成原型走查并明确确认进入阶段 4。

## 13. 阶段 5 完成门禁

- 阶段 4 已正式通过，关键状态和组件语义可作为技术输入；
- 新项目顶层目录是唯一生产代码边界，旧项目副本不参与编译、运行和线上数据读写；
- Agent Shell 在零 Domain Capability 时仍可对话、追问、理解通用输入、发现能力并说明能力缺口；
- 用户消息经过 Agent 决策和确定性 Guard，不能由模型回复直接修改 Runtime；
- 用户确认后的 Run 启动与普通聊天使用不同命令，审批点不能被 Agent 或 Eino 自动跳过；
- Runtime 是业务状态唯一真源，Eino 只承载 Agent 判断和单个执行节点内的模型/工具编排；
- Capability Manifest 是流程声明真源，新增测试 Capability 不需要修改 Runtime 核心流程分支；
- 启动时能发现缺失的 Runtime、Workflow、Provider 和 Tool Executor，并把对应 Capability 标记为不可用；
- 小说和非小说两条链有迁移回归证据，Prompt、Rules、Schema、批次、编辑和审批行为无回退；
- 视频链具备真实的媒体载荷、压缩/转码、逐集任务、排序、缺集确认、聚合、分析、Brief 和后续创作技术闭环；
- 所有 Manifest Executor 均有可发现实现，质量审核不会因 Worker 未订阅而永久排队；
- API、SSE、Schema、错误码和前端状态投影不存在同一概念多套真源；
- 数据迁移、备份、回滚和未完成 Run 处理策略完成 Dry Run 设计；
- 合同校验、Go 单元测试和最小集成测试能在受支持的开发环境完整执行；
- 阶段 5 风险清单中的 P0 问题全部关闭，P1 问题有明确实施工作包和验收方式；
- 产品负责人明确确认技术方案并同意进入阶段 6。
