# 过程产物工作台交互基线

状态：阶段 9 内部 Demo 已实现  
日期：2026-08-07

## 产品边界

过程产物不是模型调试数据，而是用户在生成剧本过程中需要阅读、确认、编辑和追溯的生产资产。主界面不得默认展示 JSON、ID、Hash、引用键或内部 Schema。

统一工作台采用三栏结构：

1. 左栏按主链实际顺序展示产物、集数和状态；
2. 中栏按 Artifact 类型渲染业务文档并承担人工编辑；
3. 右栏保留同一个 General Agent 的对话、运行状态和确认卡片。

## 展示规则

- 由 Artifact Renderer Registry 定义产物中文名称、用途、字段顺序和是否允许人工编辑。
- 对象按章节展示，数组按业务条目展示，单集剧本使用剧本文档视图。
- 内部来源、版本引用和运行字段归入折叠的“来源与技术信息”。
- 原始 JSON 只保留在默认关闭的“原始数据（调试）”中。
- 未知字段允许通用递归渲染，但真实 Schema 出现后必须补充业务名称，不允许长期暴露工程键名。

## 编辑与版本

- 可编辑产物进入结构化编辑态，保持原 Payload 的未展示字段不丢失。
- 保存产生新 Artifact Version，不覆盖旧版本。
- 未保存修改离开页面时必须提醒。
- 历史版本可在中栏预览，并明确标记“历史版本”；历史预览不能直接覆盖最新版。
- 单集剧本编辑后继续沿用 Runtime 的交接刷新、依赖影响和下游处理机制。

## 参考产品取舍

- OpenAI Canvas：借鉴直接编辑、选区协作和版本回看；
- Claude Artifacts：借鉴聊天与产物分区、独立产物窗口和版本选择；
- Gemini Canvas：借鉴手工编辑与 Agent 修改并存、版本前后切换；
- Flova：借鉴生产工作区、Agent 对话和过程资产并列，以及冲突需显式处理。

本项目不照搬任一产品。当前内部剧本生产场景更强调结构化 Artifact、逐步确认、下游依赖和版本一致性，因此 Runtime 仍是状态权威，界面只呈现并发起合法操作。
