# 原生工作区接入与验收边界

日期：2026-09-08。归属：原能力基线 GAP-08 / UX-04 / UX-05，不新增产品范围。

状态：工具层适配进行中。此文件是实现约束和验收清单，不是完成证明。完整进度及失败记录见 `agent-platform-goal-progress.md`。

## 责任边界

| 层 | 继续复用 | 平台需要补的部分 |
| --- | --- | --- |
| Agent 循环 | 固定版本 SDK Runner、SandboxAgent、RunState、Session、原生审批和暂停 | 三个生产执行入口配置同一受控工作区；不再写另一套工具循环 |
| 工作区能力 | SDK Filesystem、Shell、Skills、Manifest、快照生命周期 | Go 权威目录与执行身份、受控资源装载、审批和审计包装 |
| 文件编辑 | SDK 原生 CustomTool 补丁语法、路径校验、WorkspaceEditor | 原始补丁文本绑定、用户批准、大小和敏感内容检查、真实结果回执 |
| 命令执行 | SDK ExecCommandTool / WriteStdinTool | OCI 执行环境、租约、资源限制、会话隔离、取消和进程清理 |
| 文件持久化 | SDK Session/Snapshot 的公开协议 | 版本、哈希、二进制存储、并发发布、下载和删除清理 |

现有 `project_file_versions` 只保存版本化 UTF-8 文本；现有 Go `scriptsandbox.Sandbox.Execute` 是一次性脚本执行。两者都不能冒充通用持久工作区。

## 不变约束

- 宿主路径和执行环境只能由可信配置决定，模型输入、Skill 内容和序列化 checkpoint 不授予宿主访问权。
- 不启用 SDK Docker 默认自动拉取镜像路径，不安装 OCI，不引入宿主命令执行回退。实际环境缺失时明确不可用。
- 固定 SDK 的 CustomTool 使用 Responses 协议；Chat Completions 转换器会拒绝它。三入口装配前必须核对实际模型传输及网关能力，不能悄悄改成 JSON 函数工具并称为原生接入，也不能把确定性模型测试当作网关兼容证明。
- 复用 Go 已有 OCI 限制：固定镜像、禁止宿主挂载与网络、受限用户、能力集、CPU、内存、进程数、磁盘和临时文件配额。新原生会话不能削弱这些边界。
- 每个运行中的工作区归属于一个真实执行身份。后台、状态化及主对话不能因属于同一作品就共享可同时写入的执行目录。
- 以明确的项目文件版本/哈希建立执行快照，文件发布必须校验来源版本；并发修改不得静默覆盖。读取历史版本和恢复旧执行不得自动换成最新内容。
- Agent 编写 Skill 必须能够从该工作区继续进入已有的校验、批准安装、目录发现和调用链，不能另外建立每种 Skill 的流程。
- 保留 SDK 原生状态与回执。失败补丁可能已有部分写入，命令退出不代表产物已经发布；审计失败、取消和失联不能伪报回滚、成功或自动重放。
- 不把执行令牌、凭据、容器连接配置或宿主真实路径写入公开事件、模型上下文或可下载文件清单。

## Session 接线前检查

G4.26 已增加 Runtime 执行身份/代次绑定的持久租约、精确版本二进制快照、完整性与配额、删除预览及正文清理，相关 Runtime 扩大回归通过。上述 G4.24/G4.25 的“未接持久存储”描述保留为当时状态；当前仍未接 OCI 环境绑定、跨进程操作互斥/清理、SDK Session 和用户工具入口，不能把数据库租约视为执行 Shell 的完整授权或旧命令已经终止的证明。

G4.27 已增加 Runtime/OCI 生命周期桥接及跨实例在途操作记录、快照导出存储和内部有界清理入口，源码 schema 57。全后端构建及 Runtime/沙箱静态检查通过；修正后的 Go 测试程序被 Application Control 拦截，相关行为仍待运行验收。G4.26 的“未接环境绑定/互斥”是当时状态，不覆盖本批新增源码；本批也不等于生产入口开放、SDK Session 贯通或 Shell 可用。现有快照禁止隐式替换为空环境，明确选择版本后的重建/恢复、命令审批/PTY、生产清理调度仍需实现。

- 当前固定 SDK `BaseSandboxSession` 的持久化/恢复接口接受便携 tar 流，符合本批传输格式；SDK 原生 `SnapshotBase.persist/restore` 和状态序列化继续复用，平台提供受权持久存储，不另造 Agent 循环。
- SDK 默认 snapshot resume 会先清空工作目录。平台必须在持久版本、执行租约和原目录内容检查后决定恢复；不能因为原生默认逻辑存在，就自动删除未确认改动或覆盖另一个执行的文件。
- 固定 SDK 的路径解析和快照指纹助手默认装到临时目录并直接执行，当前平台 tmpfs 为 noexec。后续适配需验证这些原生脚本的解释执行/受控运行方式，不能擅自取消 noexec、改成 root 或删掉原生路径检查。
- SDK 的用户/端口/挂载接口不代表平台授权。当前只允许固定非 root 身份、固定工作目录、无宿主挂载/外露端口/网络；不支持的选项必须在产生副作用前拒绝，不能静默忽略。
- Linux pidfd 和实际 Docker/Podman 配置兼容性须在获授权的真实 OCI 环境验证；未验证时不把配置存在或模拟测试通过当成可用状态。

任意非空 manifest 或 `bootstrap=true` 都不是写权限；只有 Runtime 已保存的确切初始化清单授权对应操作，不能借助手命令扩大。未封存/失败的初始化禁止模型文件操作、命令及快照发布，未知结果不重放。SDK文件会话在保存开始后冻结新增文件与Shell操作，避免快照保存后发生未包含的写入再被关闭删除；文件请求未知时保留待核对身份并阻止自动保存/销毁，不能通过重建擦除该状态。

固定 SDK 的运行管理器可能在保存失败后继续调用 shutdown/delete，Runner 也可能只记清理警告而返回最终文本。适配层已保护未确认保存的环境，三个生产入口仍必须接 `RuntimeSandboxClient.require_confirmed_cleanup` 或对应受确认持久状态门禁，再接受工作区成果；用户拒绝/取消的清理与未知结果处理沿用 Runtime 权威生命周期，不能靠模型回复判定。

1. 受控执行环境适配：固定 SDK BaseSandboxClient/BaseSandboxSession 公开协议与 Go 执行环境管理接通；包含创建、使用、重连、租约轮换、取消、释放和配额失败。
2. 原生能力装配：通过 SDK `configure_tools` 包装运行时新建的 Filesystem/Shell 工具，不遗漏绑定之后才生成的工具；只读子任务不得因此获得写入或 Shell 权限。
3. 三入口接线：主对话、后台、状态化生成/修复均绑定真实执行身份。原生 checkpoint 恢复后重连正确工作区，不新建空目录掩盖快照丢失。
4. 文件与快照：二进制内容、目录、精确版本、输出发现、并发冲突、完整性校验、生命周期与删除配额；与现有工作文件/Skill 作者链统一。
5. 用户操作：实际执行状态、审批、文件树、预览/下载、原执行暂停/恢复、错误与冲突提示；只有真实可操作的状态才开放入口。
6. 同版验收：确定性跨进程联合、原有业务回归、真实 OCI/模型和浏览器验收分别记录，再纳入最终全局代码 review。

## 必须有的负向验收

- 拒绝或撤销授权、权限丢失、外部租户/作品/执行身份混用、旧租约重用。
- 绝对路径、目录穿越、符号链接和归档逃逸、非法文件名、超限/损坏的二进制及快照。
- 多文件补丁部分失败、命令执行超时、进程未退出、输出过大、敏感内容、完成回执丢失。
- 审批或暂停后进程重建、取消后迟到回执、模型故障恢复、并发发布冲突和作品删除。
- 任何模拟测试通过都不能替代实际环境验收；环境阻塞与未实现代码分别保留。
