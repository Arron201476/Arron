## 1. 测试目标

阶段 8 不负责证明业务已经运行成功，而是把阶段 9 如何验证定义完整。测试必须回答：

1. General Agent Shell 在不使用 Skill 时是否仍可对话、澄清和管理作品；
2. 小说、非小说、视频参考创作三条 Skill 是否使用同一 Runtime 完成真实生成；
3. 编辑、重新生成、逐步确认、暂停、恢复、重试和刷新恢复是否保持数据正确；
4. 视频解析、整剧分析、改编方案、Brief 和后续创作是否形成单一 Run 的完整闭环；
5. 最终剧本是否经过质量审核、形成 Candidate，且不会被自动设为最终稿；
6. 哪些结论属于 Demo，哪些生产门禁仍未执行。

机器套件真源：`../acceptance/stage-8-demo-suite.json`。原 96 项主矩阵继续作为完整测试目录，不复制第二套用例定义。

## 3. 环境策略

### 3.1 本机编译环境

当前 Windows 企业 WDAC 阻止新生成且未签名的 Go EXE。该环境只执行：

- Capability、Schema 和测试计划合同校验；
- Go 全量编译与测试二进制编译；
- 前端单元测试与生产构建；
- 不依赖 Go 进程的静态检查。

本机编译成功不能替代 Runtime 测试或真实链路执行。

### 3.2 受信 Demo Runtime

阶段 9 开始前必须具备一个可运行当前 Go 源码构建的环境。优先顺序：

1. 公司签名或 WDAC 允许的当前 Windows 构建；
2. 公司批准的 WSL/Linux 或容器环境；
3. 公司受信 Linux 开发或测试机。

环境必须使用独立临时 SQLite、Blob 和日志目录，不读写旧 Novel2Script 项目数据。

### 3.3 真实 Provider 环境

- 模型、MediaKit 和网关凭据只从服务端环境变量注入；
- 测试报告只记录 Provider ID、模型名和调用时间，不记录 Key；
- Mock Provider 验证流程确定性，真实 Provider 只负责内容可用性检查；
- 模型输出变化不得导致状态机测试随机失败。

## 5. 执行顺序

阶段 9 固定按以下顺序执行，前一层失败时不继续消耗真实模型：

1. 合同：主矩阵、Capability、Stage 8 套件、Schema；
2. 单元与集成：Runtime、数据库、API、SSE、Context、依赖和质量审核；
3. Mock E2E：Shell 与三条 Skill 的状态闭环、刷新、失败和重试；
4. 浏览器 Smoke：作品 CRUD、聊天、Skill、配置卡、编辑器和审批卡；
5. 真实文本链：小说固定样本、非小说完整大纲；
6. 真实视频链：先 1 集链路探针，再多集排序、聚合、分析、Options、Brief 和创作；
7. 内容抽查：事实一致性、剧本格式、用户要求、来源边界和质量审核；
8. 导出：TXT、DOCX 与当前最终 Candidate 同源。

单集视频探针只验证 Provider 接通，不能替代多集视频用例。

## 6. 三条真实链的最低断言

### 小说

- 上传或引用材料后不自动启动 Run；
- 用户确认集数、单集时长和来源材料后才开始；
- 故事圣经、拆集、分集卡和剧本均可编辑并形成新版本；
- 体量不足时必须确认扩写策略，且不新增关键设定和主线；
- 质量审核完成后形成 Candidate，不自动设为最终稿。

### 非小说

- 三档材料完整度均能进入正确的体量判断；
- 用户事实和模型推断可区分；
- Story Seed、Series Blueprint、分集卡和剧本逐步确认；
- 批次失败只重试失败项，聚合精确引用已确认单集版本。

### 视频参考创作

- 同一作品可分多批加入视频，用户明确完成后才 Seal；
- 默认按命名自然排序，允许人工排序；缺集继续必须显式确认；
- 每个视频独立 Task，逐集剧本可保存、编辑和重生成；
- 整剧分析只读取已确认的逐集聚合；
- 改编 Options 可组合，集数和时长必填，确认后形成不可变 Decision/Config Snapshot；
- Brief 必须确认后才进入共享非小说后续链，Capability ID 不切换；
- 来源标记和禁止照搬规则在最终剧本中可追踪。

## 7. 内容质量检查

内容质量不使用单一自动分数。人工按固定顺序记录：

1. 输出结构和必填字段；
2. 上下游事实一致；
3. 人物、关系、集数和事件无明显冲突；
4. 剧本场次、动作行、对白和来源信息可用；
5. 用户已确认要求是否执行；
6. 质量审核是否绑定精确剧本版本；
7. 主观内容表现。

视频还原另外记录：画面遗漏、字幕遗漏、音频台词遗漏、说话人错误、时间码偏差和无依据新增。第一版不承诺自动逐字无遗漏，也不预先增加独立 OCR/ASR 管线。

## 8. 缺陷规则

| 等级 | 定义 | 处理 |
|---|---|---|
| P0 | 数据错误、跨作品污染、主链无法继续、确认点可绕过、凭据泄露 | 阻断 Demo，修复并全量回归 |
| P1 | 核心操作明显错误但有可接受绕行，或内容质量不满足内部使用 | 默认阻断对应链；产品明确接受风险后才能放行 |
| P2 | 非核心视觉、文案或效率问题 | 记录进入迭代，不阻断 Demo |

每条执行结果必须记录 Build、环境、schema 版本、Capability 版本、Provider、Fixture 哈希、Case ID、结果、证据和缺陷 ID。模板为 `../acceptance/stage-9-demo-result.template.json`。
