# Stage 5 T6 视频参考创作验收

更新时间：2026-08-05

## 当前状态

T6 技术方案门禁已通过。现行实现只有一条视频转剧本路径：

```text
单集视频
-> FFmpeg 格式、大小、时长标准化
-> MediaKit Subtitle 模式提取对白字幕与时间码
-> 豆包读取完整视频，并结合字幕证据生成高还原剧本
-> 确定性字幕覆盖校验
-> 用户编辑、重新生成或确认单集剧本
```

不存在备用处理路径、Provider 切换或静默降级。

## 职责边界

### MediaKit

- 输入完整的单集视频；
- 仅使用 `Subtitle` 模式；
- 输出对白字幕、开始时间和结束时间；
- 不负责人物归属、OS/VO、动作、场景、人物标签、系统面板、商品卡或其他画面文字。

### 豆包

- 输入完整的单集视频；
- 同时读取 MediaKit 字幕证据；
- 负责剧情、人物、说话人、OS/VO、动作、场景和其他视觉信息的理解；
- 输出 `video_script_unit`，不输出剧本分析或改编建议。

### Worker

- MediaKit 或豆包任一环节失败时，任务明确失败并保留重试入口；
- 不允许回退到旧路径；
- 将明显超长重复 OCR、其重复碎片及紧邻脏段的单字符标记为 `ocr_text_candidate`，交由完整视频确认；
- 校验其余 `dialogue_subtitle` 是否逐字进入对白、OS、VO 或旁白对应的 `dialogue` 块；
- 字幕只被改写成动作描述时，触发一次结构化修复；修复后仍失败则返回 `OUTPUT_REPAIR_FAILED`。

## 本地验收范围

1. Media Processor 只做格式、大小、时长检查与必要转码，不生成图片帧。
2. MediaKit Client 固定提交 `mode=Subtitle`，完成上传、提交、轮询和错误分类。
3. Video Execution Graph 强制同时注入视频 Provider 与 MediaKit Client。
4. Prompt 只包含 MediaKit 字幕时间线，不包含第二套字幕证据。
5. 生成结果必须通过 Provider 合同、Artifact Schema、视频语义和字幕覆盖四类校验。
6. 单集失败不删除已完成集；系列任务仍按自然集序展示并支持失败集重试。
7. 环境配置中不存在旧方案开关。

## 真实多集记录

样本：`我帮始皇造火箭` 第 1-3 集，均为 H.264/AAC、720x1280、约 60 秒、9.35-9.50 MB 的处理副本。

- 3 Worker：约 559.93 秒后失败；2 集成功保存，1 集在自动重试后仍返回 HTTP 504；
- 2 Worker：约 462.35 秒后出现 HTTP 504，并暴露成功任务提交时被提前失败的 Run 拒绝为 `ATTEMPT_STALE`；
- 1 Worker：约 800.94 秒后失败；第 1 集一次成功，第 2 集首次 504 后自动重试成功，第 3 集连续两次 504；
- 第 3 集隔离：约 349.95 秒，连续两次 HTTP 504，排除并发竞争；
- 第 3 集 MediaKit 隔离：58.70 秒成功，61.485 秒视频得到 16 段、84 字字幕，排除字幕证据过多；
- 第 1-3 集时长、分辨率、编码和码率接近，第 3 集仅文件体积略大，因此仍需在受支持的转码环境验证更低处理副本体积；
- Runtime 已修复 `preserve_success_retry_failed`：失败项不会终止仍在执行的兄弟任务，整批收敛后才失败，人工重试只重置失败项并保留成功 Artifact；
- 媒体、素材上下文和 MediaKit 错误码已纳入 Runtime 执行失败协议，不再错误返回 `REQUEST_VALIDATION_FAILED`；
- Video Worker 部署默认并发已从 3 调为 1，仍可通过 `CONTENT_AGENT_VIDEO_WORKER_CONCURRENCY` 配置；
- 处理副本默认目标为 8 MiB、硬边界为 10 MiB，可通过 `CONTENT_AGENT_VIDEO_PREPARED_MAX_BYTES` 在 1-10 MiB 间配置。

当前结论：多集排序、逐集保存、失败隔离和失败项重试机制通过自动化及真实失败场景验证。豆包网关连续多集稳定性未通过，登记为阶段 7 Provider 接入 P0 风险；第 3 集和 40 集真实验收保留到阶段 9，不再阻塞阶段 5 技术方案收口。

## 阶段 7/9 延续门禁

进入阶段 10 发布前，必须用用户提供的真实连续剧样本完成以下验收：

1. 单集：MediaKit 字幕结果、豆包剧本结果和人工对照可接受。
2. 多集：命名排序、人工排序、缺集确认和逐集状态正确。
3. 失败恢复：至少验证一次 MediaKit 失败、豆包失败和字幕覆盖失败后的重试。
4. 编辑确认：单集剧本可保存、编辑、重新生成并在整批步骤统一确认。
5. 性能：记录单集与多集总耗时，以当前唯一链路形成新基线。

## 真实单集记录

样本：`穷剑修1-修改.mp4`

- 标准化视频：60.533 秒，9,325,589 字节；
- MediaKit `Subtitle`：26 段；
- 风险标记：2 段超长重复错拼、2 段重复碎片、1 段紧邻脏段的单字符，共 5 段 `ocr_text_candidate`；
- 强校验字幕：其余 21 段 `dialogue_subtitle` 按时间顺序逐段覆盖；
- 最终 Run：154.09 秒到达 `waiting_approval`；
- 豆包调用：1 次，`repair_count=0`；
- 内容结果：两段乱码弹幕未进入对白，单字“劈”及后续正常对白保留，人物、渡劫动作和结尾状态与视频截图一致；
- 当前结论：单集技术验收通过；连续多集验收已开始但网关稳定性未通过。

T6 在本地自动化、真实单集、真实多集故障场景和确定性恢复语义均有证据后完成。连续 40 集内容、性能、SSE 和工作台验收属于阶段 9；未通过时不得进入阶段 10 发布。
