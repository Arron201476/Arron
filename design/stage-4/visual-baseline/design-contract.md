# 阶段 4 视觉系统设计合约

## 目标

目标 Artifact：内容生产 Agent 桌面网页的 Foundations、核心组件质量试验板和三栏工作台高保真页面。

目标用户：公司内部、Agent 使用经验有限、需要从多种来源获得漫剧剧本的内容生产人员。

本轮已在 ApprovalCard、删除确认 Dialog 和 Agent Composer 三个真实场景完成组件视觉探索、否决式审计、正式组件重建和业务页面回刷。旧 Figma v2.4 组件只作为已否决的历史证据，不作为实现输入。

最终采用经产品负责人确认的组件方向：操作附着在内容容器边界，Primary 通过区域关系、文字权重和结果图标建立层级；尾部不得形成不存在的第二点击目标暗示。正式组件源和 Node ID 以 `implementation-handoff.md` 与 `figma-final-state.json` 为准。

## 最终设计立场

采用“安静的内容工作室”：低对比工具轨道包围一张高可读稿纸，Agent 以生产时间线而非聊天气泡工作。界面保持紧凑、连续和克制，但克制不等于默认控件。组件必须通过比例、字体、图标、表面、状态和上下文关系形成专业完成度，关键操作不能只靠一块深绿色填充获得优先级。

## 后续实现风险

- 50 集目录已在 Figma 验证纵向滚动和末集可达，阶段 6 仍需在真实 DOM 中回归滚动、虚拟化和焦点保持。
- 已完成 12 集视频逐集任务密集状态；几十集真实样本的性能和失败恢复属于阶段 8/9 验收。
- 当前没有正式公司设计系统，字体与色板为本产品基线；后续替换必须保持组件比例和状态语义。
- Flova、OiiOii 和 Figma Simple Design System 只提供参考，不作为相似度验收标准。

- [x] 正式核心组件通过阶段 4 组件硬门禁。
- [x] 第一眼像专业内容编辑器，而不是后台 Dashboard。

- [x] 用户能区分手动编辑、上下文 Agent 修改、重新生成和 Agent 流内确认，且这些操作不在每一步重复常驻。
