# 内容生产 Agent 视觉基线

## 1. Visual Theme & Atmosphere

产品采用“安静的内容工作室”方向：密集但不拥挤，专业但不冰冷，核心体验接近编辑器和制作台，而不是通用后台。

- 左右两侧是低对比工具轨道，中间是清晰的稿纸工作面。
- 视觉重点始终落在当前 Artifact 和剧本文字，不落在装饰、品牌横幅或大面积状态色。
- 借鉴 Flova 的三栏生产密度和连续工作区，但改为适合长时间中文阅读的浅色环境。
- 借鉴 OiiOii 的结构化追问与产物联动，但不复制其页面结构、品牌样式或具体控件。
- 第一版只做 Light Mode。

## 2. Color

绑定色板：

| Token | Value | 用途 |
|---|---|---|
| `canvas` | `#F2F4F5` | 工作台背景 |
| `rail` | `#E9EDEE` | 左右工具轨道 |
| `paper` | `#FFFFFF` | 剧本和 Artifact 阅读面 |
| `ink` | `#171B1E` | 主文本 |
| `text-secondary` | `#667079` | 元信息 |
| `line` | `#D8DEE2` | 分隔线和边界 |
| `teal` | `#0F766E` | 主操作、运行和已连接状态 |
| `teal-soft` | `#DDF4EF` | 选中、轻提示 |
| `blue` | `#2F6FED` | 定位和信息链接 |
| `amber` | `#A15C00` | 待确认和风险 |
| `red` | `#C23B3B` | 失败和破坏性操作 |

规则：

- 状态色只用于文字、图标、左侧标记或极浅背景，不做整张高饱和色卡。
- 不使用渐变、发光、紫蓝色氛围、彩色装饰块。
- 中心稿纸必须保持最高明度和最佳正文对比度。

## 3. Typography

- 中文主字体：`Noto Sans SC`；实现回退为 `Microsoft YaHei UI`, `PingFang SC`, sans-serif。
- 页面标题：20/28，600。
- 面板标题：14/22，600。
- 区段标题：13/20，600。
- UI 正文：14/22，400。
- 元信息：12/18，400。
- 剧本正文：15/28，400。
- 剧本角色名和场次：15/26，600。
- 字间距固定为 0。
- 不随视口宽度缩放字号。

剧本文字优先保持稳定行长、充分行距和明确的场次层级。正文阅读宽度控制在 680-760px。

## 4. Spacing & Grid

- 基础单位：4px。
- 常用间距：4 / 8 / 12 / 16 / 24 / 32。
- 顶栏高度：52px。
- 1440px 标准宽度：左栏 252px，右栏 392px，中间自适应。
- 1280px：左栏 220px，右栏 348px，中间不得低于 560px。
- 1920px：左栏 272px，右栏 420px，中间稿纸仍限制最大阅读宽度。
- 面板内边距以 16px 为主；紧凑工具条可用 8-12px。
- 控件高度：紧凑 30px，默认 36px，主输入区不低于 96px。
- 圆角：工具控件 4-6px，浮层和关键确认 8px；禁止大面积 12px 以上圆角。

## 5. Layout & Composition

- 固定三栏：流程与产物目录 / Active Workspace / General Agent。
- 三栏使用连续分隔面，不把每个栏位做成浮动卡片。
- 左栏用于扫描和定位，保持紧凑行高与清晰状态标记。
- 中间优先呈现一张连续稿纸或结构化编辑面，不堆嵌套卡片。
- 右栏是生产时间线：顶部状态、连续事件、底部 Composer。
- Agent Composer 固定底部；时间线独立滚动。
- 用户选区和 Artifact 引用只进入右侧唯一 Agent 上下文，不产生第二套聊天。
- 顶栏只保留作品定位、运行状态、候选/最终稿、导出和栏位控制。

## 6. Components

### 导航与工具

- 目录项使用文字、轻量状态和 2px 选中标记，不使用大色块。
- 更多操作必须是锚定菜单；只有阻断性确认使用 Dialog。
- 按钮以文字和图标为主，主按钮只在当前屏幕保留一个。
- Chip 仅表达上下文、附件和具体 Skill 引用；数量多时折叠为摘要，不形成药丸墙。

### 组件完成度

- Button 家族至少区分 Primary、Secondary、Ghost、Destructive 和 IconButton；高度、圆角、字体、图标和内边距形成同一比例体系。
- Primary 通过字重、边界、表面层次和上下文位置共同建立优先级，不能只是一块深绿色加白字。
- Button 不强制增加图标、阴影或装饰；图标只用于能提高识别速度的动作，表面处理只用于表达层级和状态。
- Input、Select、Chip、Card、Composer 与 Button 共享同一字体、图标、边界和 focus 语言，不能像来自不同组件库。
- hover、pressed、focus-visible、loading、disabled 和 error 在 100% 比例下可辨认，状态切换不改变组件外框尺寸。
- 核心组件必须在白色稿纸、浅灰轨道和语义浅色模块中分别验证，不能只在孤立组件页中成立。

### 图标

- 使用同一线性图标系统，默认 16px 光学尺寸、1.5-2px 视觉描边，按图形复杂度做光学修正。
- 熟悉的紧凑动作使用 IconButton 并提供 Tooltip；结果性和风险性命令保留文字。
- 同一动作只使用一个图标语义，禁止用 `+` 以外的文字字符模拟图标。

### Artifact 与剧本

- 结构化 Artifact 采用字段组、分隔线和可编辑行，不使用卡片套卡片。
- 剧本编辑器采用稿纸、场次锚点、段落类型和选区浮动命令条。
- 手动编辑、Agent 修改、重新生成是三个清晰动作，并各自生成版本记录。

### Agent

- 用户消息可以使用弱背景气泡；Agent 输出默认采用无气泡时间线。
- 运行进度使用左侧轨道、步骤标题、紧凑进度和控制，不使用大面积信息卡。
- 只有澄清、审批、失败和最终产物需要有边界的结构化模块。
- 状态模块用左边框、图标和轻背景区分，不靠整块黄绿红底。
- 产物引用必须可点击并定位中间对象。

## 7. Motion & Interaction

- Hover、Focus 和面板展开：120-180ms，ease-out。
- 左右栏收起时保持中间稿纸位置稳定，避免大幅跳动。
- Agent 新事件出现使用轻微淡入和 4px 上移，不使用弹跳。
- 进度变化只更新局部数字和进度线。
- 菜单从锚点展开；Dialog 使用背景遮罩并锁定底层交互。
- 用户编辑期间不自动替换内容；AI Patch 必须显式接受后形成新版本。
- Button 提交中保持原宽度并展示 loading，不允许重复提交。
- 流式输出只更新消息正文和状态，不推动 Composer 或主要工作区跳动。
- 暂停、恢复、失败和重试使用局部状态变化，不使用整页遮罩代替真实进度。

## 8. Voice & Brand

- 文案直接说明当前对象、发生了什么、用户下一步能做什么。
- 不展示 Prompt、Rule、Worker、内部 Step ID 或模型名。
- 不使用营销口号、拟人化夸张语气和技术炫耀。
- 状态词统一：待处理、生成中、待确认、已生成、已确认、已暂停、失败、已失效。
- 破坏性操作必须明确说明影响范围和不可撤销性。
- Composer 工具栏统一显示“能力”，菜单和上下文显示具体 Skill 名称；用户界面使用“作品、步骤、版本、候选稿、最终稿”等业务术语。Capability、Run、Rule 和 Worker 只用于内部文档。
- Button 使用结果导向文案，例如“确认并继续”“重试第 7 集”，避免脱离上下文的“确定”“处理”。

## 9. Anti-patterns

- 禁止做成通用 SaaS Dashboard 或营销落地页。
- 禁止每段内容都套卡片、卡片再套卡片。
- 禁止大面积浅黄、浅绿、浅红状态卡。
- 禁止整页只有一套青色或蓝色层级。
- 禁止使用紫色渐变、发光球、玻璃拟态和装饰性阴影。
- 禁止过多圆角矩形文字按钮；熟悉动作优先图标并提供 Tooltip。
- 禁止用超大标题和空白稀释内容生产密度。
- 禁止 Agent 每条消息都表现为聊天气泡。
- 禁止右侧 Agent 面板缩放后裁切 Composer 或产生横向滚动。
- 禁止 1280px 下正文宽度低于 560px。
- 禁止用组件库默认样式、单纯换色或统一圆角矩形冒充视觉系统。
- 禁止为了显得精致而机械添加图标、阴影、渐变或高光。
