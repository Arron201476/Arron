# 工作台前端交互实测审计

日期：2026-08-11  
环境：`http://127.0.0.1:8860`，桌面视口 `1278 x 912`  
范围：小说链单集/完整剧本、视频链完整剧本/剧本分析、左侧产物目录、中间阅读与编辑、版本历史、右侧 Agent 对话与过程记录。

## P0

### 1. Agent 上下文定位产生不存在的“第 0 集”

- 复现：进入视频链的“完整剧本”或“剧本分析”。
- 现象：输入框上方显示“当前：完整剧本 · 第 0 集”或“当前：剧本分析 · 第 0 集”。
- 影响：这是错误的上下文目标，不只是显示问题；后续“让 Agent 修改”可能把非分集产物错误定位到第 0 集。
- 证据：`07-video-complete.png`、`08-video-analysis.png`。

### 2. 结构化产物编辑器暴露并允许修改内部协议字段

- 复现：剧本分析 -> 手动编辑 -> 展开分析项依据。
- 现象：用户可直接编辑 `asset_id`、`asset_snapshot_id`、`artifact_version_id`、`json_pointer`、`source_type` 和毫秒时间范围等技术字段。
- 影响：普通内容用户无法理解这些字段，误改会破坏证据引用、Artifact 关系和 Agent 上下文定位。
- 证据：`09-analysis-edit.png`、`10-analysis-internal-fields.png`。

## P1

### 3. 剧本阅读态与编辑态不是同一工作面

- 复现：单集剧本 -> 手动编辑 -> 取消或保存。
- 现象：正文从 645px 阅读区切换成 581px 编辑页，内容起点从 y=201 跳到 y=237，文档高度从 867px 变为 1035px；焦点还会回到 `body`。
- 影响：点击时出现明显闪动和宽度收缩，保存/取消时再次闪动；用户失去当前位置。
- 证据：`03-before-edit.png`、`04-after-edit.png`。

### 4. 版本历史抽屉直接覆盖正文

- 复现：单集剧本 -> 版本历史。
- 现象：约 313px 宽的抽屉压在 710px 的中央工作区上，正文不重排、无遮罩且被截断。
- 影响：用户无法边看当前内容边判断版本，也容易误以为正文被裁切或布局损坏。
- 证据：`05-version-history.png`。

### 5. 左侧分集展开缺少清晰的收起提示，并制造额外滚动层

- 复现：展开“单集剧本 12/12”。
- 现象：12 集直接插入主流程目录；分集组自身没有明显的展开/收起图标。左侧列表高度 754px、内容 850px，出现 15px 系统滚动条，并把后续“完整剧本”推到视口外。
- 影响：用户不知道点击同一行可以收起；流程导航和分集导航互相争夺空间。
- 证据：`02-episode-expanded.png`。

### 6. 完整剧本目录使用横向滚动条承载 12 集

- 复现：打开完整剧本。
- 现象：目录可视宽度 645px、内容宽度 753px，出现 16px 高的横向系统滚动条，第 11、12 集被藏在右侧。
- 影响：集数导航不可扫视，横向滚动又与正文纵向滚动叠加。
- 证据：`01-current-expanded.png`、`07-video-complete.png`。

### 7. 页面同时存在三个强纵向滚动区

- 现象：左侧目录、中央产物、右侧 Agent 分别独立滚动；展开分集后三个滚动条同时可见，中央完整剧本高度可达 9904px，右侧过程记录可达 3531px。
- 影响：滚轮归属依赖鼠标位置，用户容易滚错区域；默认 Windows 滚动条视觉权重过高。
- 证据：`02-episode-expanded.png`、`07-video-complete.png`。

### 8. “查看历史”是不可操作的伪入口

- 复现：查看右侧 Agent 标题栏。
- 现象：“查看历史”使用普通 `span`，无点击、键盘和按钮语义。
- 影响：视觉上承诺了入口，实际无法操作，属于明确的交互欺骗。
- 证据：所有工作台截图右上角。

### 9. Agent 对话混合不同 Skill/Run，缺少分组与时间

- 复现：点击“显示作品对话 8 条（跨生成记录）”。
- 现象：小说和非小说 Skill 的消息混排；重复出现配置引导；只有消息内容，没有时间、Run 标识或阶段归属。
- 影响：用户无法判断一条回复属于哪次生成，也无法据此继续操作。
- 证据：`06-agent-chat-shown.png`。

### 10. 过程记录展示 Runtime 原始事件，而不是用户任务进度

- 现象：同一步骤连续展示“已开始/等待确认/已确认/已完成/已暂停/已恢复”，失败时“处理失败”和“运行失败”重复出现；完成的视频 Run 默认展开后高达 3531px。
- 影响：系统日志淹没真正需要用户关注的结果、异常和下一步动作。
- 证据：`06-agent-chat-shown.png`、`07-video-complete.png`。

### 11. 结构化产物的全量编辑模式不可用

- 复现：剧本分析 -> 手动编辑。
- 现象：整份分析被转换成数百个文本框、上移/下移/删除按钮；技术引用和业务内容同级展示，用户需要在超长页面中完成一次整体保存。
- 影响：不适合轻量内容修改，也大幅提高误删、误排序和破坏结构的概率。
- 证据：`09-analysis-edit.png`、`10-analysis-internal-fields.png`。

## P2

### 12. 展开对话会把过程记录继续向下推，不提供视图切换

- 现象：作品对话和过程记录串在同一个滚动容器中，用户只能“显示/隐藏对话”，不能在“对话/进度/历史”之间切换。
- 影响：右栏在长 Run 中很难定位，滚动位置也不稳定。

### 13. 当前状态与可操作动作不够明确

- 现象：历史产物可浏览时，作品仍显示“处理中”；底部又显示“当前无可用操作”，只保留结束运行。正在运行的是哪次 Run、为什么不能输入、多久后可操作没有在首屏形成一条清晰状态链。
- 影响：用户容易把历史产物状态、当前 Run 状态和作品最终稿状态混为一谈。

### 14. 通用“手动编辑”入口没有按 Artifact 类型设计

- 现象：剧本、剧本分析等不同产物共用同一个入口，但进入后分别切换为富文本编辑器或全量 Schema 表单。
- 影响：表面统一，实际行为差异很大；用户无法预期点击后的编辑能力和风险。

## 结论

当前问题不是若干按钮或滚动条的样式问题，而是四个基础交互模型尚未收敛：

1. 工作台的滚动归属没有统一规则。
2. Artifact 阅读、编辑、版本历史没有共用稳定工作面。
3. Agent 对话、Run 进度、作品历史混在同一时间线中。
4. Agent 上下文定位和 Artifact 编辑仍暴露 Runtime/Schema 实现细节。

在修复这些基础模型前，继续做按钮质感或局部视觉润色不会解决当前体验问题。
