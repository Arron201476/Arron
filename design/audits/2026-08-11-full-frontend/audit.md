# 前端全局审计：三条剧本生产链路

审计日期：2026-08-11  
视口：1440 x 900  
样本：小说转剧本、非小说文本转剧本、视频参考创作三个真实已生成作品。

## 总体判断

后端流程与产物已经能够支撑三条链路，但前端仍以“通用 Artifact 调试器”为核心，尚未形成面向内容用户的生产工作台。当前最重要的不是继续调整颜色和间距，而是统一运行上下文、集合产物、剧本目录和编辑器。

## 整改结果

2026-08-11 已按本审计完成首轮结构整改：

- 多 Run 作品明确当前查看的生成记录；跨 Run 作品对话默认折叠，过程记录只展开当前 Run。
- `单集剧本` 与 `视频还原剧本` 在左侧展开二级分集目录，中间横向分集条已删除。
- `完整剧本` 与 `参考剧本合集` 读取真实单集版本，按集数合并展示正文。
- 剧本编辑器恢复撤销、重做、加粗、斜体、下划线、删除线、保存状态与固定保存区，保存仍走 Artifact 新版本协议。
- 普通工作台移除原始 JSON 与技术字段入口，补充人物和材料字段中文映射。
- 无活动 Run 时，顶部使用作品真实状态，不再统一显示“待处理”。

自动化证据见 `after/report.json`，视觉证据见 `after/00-script-editor.png` 至 `after/04-video-1280.png`。

## 已确认问题

### P0-1 多 Run 上下文错位

证据：`02-novel-overview.png`。

- 左侧显示小说转剧本产物，作品当前状态来自后续非小说 Run，右侧同时展示多个 Skill 的输入、配置与过程记录。
- 用户无法判断中间产物、顶部状态和右侧过程是否属于同一次生成。
- 整改：明确“当前查看的生成记录”，Agent 过程记录默认展开对应 Run；其他 Run 折叠，不把历史 Run 当作当前状态。

### P0-2 剧本目录位置和扩展性错误

证据：`05-novel-script-read.png`、`10-nonnovel-script.png`、`16-video-generated-script.png`。

- 左侧只有“单集剧本 12/12”，分集目录被放在中间顶部横向滚动。
- 集数增加到 40 集后，查找和跳转成本过高。
- 整改：在左侧“单集剧本/视频还原剧本”下展开二级分集目录，删除中间横向目录。

### P0-3 集合产物不能查看实际内容

证据：`11-video-overview.png`、`13-video-reference-scripts.png`、`02-novel-overview.png`。

- “参考剧本合集”和“完整剧本”只显示数量、完整度和引用字段。
- 用户点击集合后看不到逐集内容，集合更像后台管理记录。
- 整改：集合产物进入统一剧本阅读工作台，读取对应 `video_script_unit` 或 `script_unit` 子产物。

### P0-4 剧本编辑器被降级

证据：`06-novel-script-edit.png` 与旧版对照图 `../2026-08-11-editor-reuse/editor-comparison.png`。

- 当前编辑器已有稿纸、常驻保存和未保存保护，但仍是纯文本输入区。
- 缺少旧版已验证的正文编辑工具栏和内容格式状态。
- 整改：恢复撤销、重做、加粗、斜体、下划线、删除线、保存状态和结构化保存；继续使用当前 Artifact 版本协议。

### P1-1 过程产物暴露 Schema

证据：`03-novel-story-bible.png`、`08-nonnovel-material-bank.png`、`13-video-reference-scripts.png`。

- 页面直接出现 `core`、`age`、`identity`、`traits`、`continue with incomplete` 等内部字段。
- “原始数据（调试）”和技术来源在普通工作台外显。
- 整改：补充领域字段映射；默认隐藏技术信息，移除普通用户的原始 JSON 入口。

### P1-2 状态文案失真

证据：`07-nonnovel-overview.png`、`11-video-overview.png`。

- 已完成作品顶部仍显示“待处理”。
- “已生成”“已确认”“最终稿已更新”没有明确对应 Run、Artifact 或作品层级。
- 整改：顶部显示最近 Run 的真实状态；Artifact 状态保留在产物区域；最终稿状态只在候选控制中呈现。

### P1-3 Agent 历史没有信息分层

证据：`02-novel-overview.png` 与 `07-nonnovel-overview.png` 对照。

- 单 Run 时较清楚，多 Run 时所有消息、配置卡、过程记录连续堆叠。
- 整改：历史消息默认折叠，仅保留最近协作内容；过程记录按 Run 分组，并优先展开当前查看 Run。

## 可访问性风险

- 固定 `min-width: 1180px`，桌面缩放后可能产生横向滚动；第一版不支持移动端，但仍需覆盖 125%/150% 缩放。
- 剧本正文编辑区此前移除了可见焦点，需要在稿纸容器提供明确的 `focus-within` 状态。
- 当前多数图标按钮有 `aria-label`，状态也同时使用文字，属于已确认优点。

## 证据边界

- 本轮验证了已完成三条链路的主页面、过程产物、集合产物、剧本阅读与编辑。
- 未找到同一真实样本中的待确认、失败和版本冲突状态；这些状态继续由现有自动化测试覆盖，不能据此宣称完成视觉验收。
- 未进行屏幕阅读器实测，不宣称满足完整 WCAG。
