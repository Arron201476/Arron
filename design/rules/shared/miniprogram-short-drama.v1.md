# 07_小程序短剧适配

## 名称
07_小程序短剧适配

## 用途描述
用于 Step2 拆集节奏、Step3 分集节奏和 Step4 小程序短剧表达适配。

## 准则

### 平台适配边界

1. 本规则模块 是平台适配层，只约束小程序短剧的观看体感、信息密度、留存压力和表达速度。
2. 开头、冲突、爽点、尾钩的具体结构设计归 `03_结构规划_开头_冲突_爽点_尾钩.md`。
3. 对白写法归 `05_对白规则.md`；转场、闪回、格式归 `06_转场_闪回_连续性_格式.md`。
4. 本规则模块 不能以平台节奏为理由新增关键事实、改人物关系、跳过因果链或替代上游规划决策。

### 小程序短剧默认目标配置


### 参考范围

默认启用场景：

- 用户没有另行指定平台
- 当前产品流程默认服务小说或灵感转小程序短剧
- 故事圣经 需要确定故事理解的目标方向
- 分集规划 需要确定分集节奏、爽点和尾钩密度
- 剧本生成 需要确定剧本正文的进入速度、对白密度和场面化程度

不适用场景：

- 用户明确指定精品短剧、横屏剧、长剧、电影或海外短剧
- 用户要求先做多个平台方向对比
- 用户要求做投稿或市场报告

### 使用原则

1. 用户明确指定平台时，以用户指定为准。
2. 未指定时，默认按小程序竖屏短剧处理。
3. 目标配置只约束表达方式、节奏和规划重点，不新增剧情事实。
4. 不用市场标签替代人物、冲突和因果判断。
5. 不为了迎合热门题材新增原文没有的系统、重生、战神、神豪、隐藏身份或关键关系。

### 默认目标

#### 1. 观看体验

小程序短剧优先满足：

- 开头快进入人物困境
- 冲突表达直观
- 关系张力清楚
- 每集都有推进
- 爽点、虐点、反转或悬念高频出现
- 结尾停在观众想继续看的变化点前后

#### 2. 分集策略

分集规划 规划时优先保证：

- 每集有明确行动目标
- 每集有可见阻力
- 每集有局势变化
- 前几集尽快建立主角困境、核心关系和追看问题
- 尾钩不是空喊悬念，而是绑定下一集的关键变化
- 不把大量世界观、背景或心理解释堆在开头

#### 3. 剧本表达

剧本生成 生成时优先保证：

- 场景切入要快
- 台词短、直接、有动作目的
- 情绪尽量通过动作、对话和局势变化呈现
- 反击、误会、真相、选择、危机要有明确画面承载
- 可以保留必要的铺垫，但铺垫必须服务本集推进

### 引用边界

如果用户明确切换目标平台，应改用，改用用户指定的平台目标。

### 禁止越权

1. 不覆盖用户指定的目标平台和受众。
2. 不根据平台目标强行改变原作核心人物关系。
3. 不为了追求强刺激新增关键设定、关键证据或关键人物。
4. 不让节奏规则破坏因果链、人物行动逻辑和场景连续性。

### 小程序短剧适配


### 参考范围

小程序短剧、竖屏付费短剧、强转化短剧或默认未指定平台。

### 核心目标

小程序短剧优先服务：

- 快速进入
- 强冲突
- 强追看
- 高爽点密度
- 明确情绪回报
- 明确单集尾钩
- 付费点前卡

### 使用原则

1. 情绪必须直观，关系必须清楚。
2. 每集要有推进，不能只铺垫。
3. 开头要快，中段要有局势变化，结尾要有事件型钩子。
4. 爽点和虐点要服务主线，不机械堆叠。
5. 逻辑可以压缩，但因果不能断。
6. 连续性和可拍性高于刺激强度。

### 故事理解阶段适配

在故事理解阶段，补充：

- 核心追更机制
- 主要爽点类型
- 主角反击路径
- 目标观众
- 高点击关系
- 可前置的原文已有爆点

不得在故事理解阶段写成完整分集。

### 分集规划阶段适配

在分集规划阶段，检查每集：

- 是否有开头钩子
- 是否有主要冲突
- 是否有爽点或情绪推进
- 是否有事件型尾钩
- 是否承接上一集尾钩
- 是否避免重复同类钩子

已有分集边界时，仍必须尊重既定素材范围。

### 剧本生成阶段适配

在剧本生成阶段，强化：

- 前 3 秒高能信息
- 行动先于解释
- 对白短句化
- 冲突外化
- 情绪递进
- 反击可见
- 结尾卡在兑现前

不得为了小程序节奏跳过人物得知信息、抵达地点、做出选择的必要过程。

### 小程序风险检查

需要标记：

- 开头慢
- 单集无冲突
- 尾钩弱
- 爽点兑现太晚
- 反派手段重复
- 主角长期被动
- 对白太文学化
- 情绪只有 OS 没有行动
- 因果链被压缩断裂

### 引用边界

使用时应影响以下内容：

- 故事理解中的追更机制
- 分集规划中的开头、冲突、爽点和尾钩
- 剧本正文的节奏、对白和情绪密度
- 生成后的自查和返修方向

### 禁止越权

1. 不以小程序节奏为理由新增关键设定。
2. 不以强爽点为理由破坏原文因果。
3. 不以付费点为理由让尾钩脱离本集事件。
4. 不把所有人物写成标签化工具人。
5. 不让逻辑断裂来换取快节奏。

---

### 信息密度与集数匹配

1. 小程序短剧可以快，但不能把一个无足够信息量的原文片段硬撑成完整一集。
2. 如果单集只剩铺垫、寒暄、重复解释或弱情绪，应标记为节奏风险，优先考虑压缩表达或交给上游流程确认。
3. 目标集数与素材体量冲突时，本 Rule 只能提示风险；是否改集数、合并拆分、重排剧情，需要由 Prompt 字段和后续 Agent/Workflow 决策承接。
4. 单集内部节奏要优先保留“压力进入—冲突推进—信息变化—钩子离场”的链路，不用无功能桥段填满长度。
5. 追更节奏来自持续变化，而不是持续吵闹；每集必须让观众获得新的危险、证据、关系变化、爽点承诺或情绪债。
