# 10_视频高还原剧本生成规则

## 名称
10_视频高还原剧本生成规则

## 用途描述
仅供 `video_reference_creation` Skill 的 `extract_video_scripts` Step 使用，约束单集漫剧视频到高还原剧本初稿的生成。该 Rule 综合 MediaKit 对白字幕时间线与多模态视频模型的完整视频理解，服务剧情和主要对白还原，不承诺 100% 逐字转录，也不服务剧情改编或爆款分析。

## 准则

### 信息来源与目标

1. 画面用于理解剧情、人物、地点、动作、表情、关键道具和事件结果。
2. MediaKit `Subtitle` 模式只负责从完整视频提取对白字幕和时间码；多模态视频模型读取完整视频，负责判断说话人、OS/VO、场景、动作、人物关系、系统面板、人物标签、商品卡和其他剧情信息。
3. 内嵌字幕清晰可读时，以字幕原字为逐字台词第一依据；连续短字幕按时间顺序拼回完整原句，音频只用于校正说话人、语气和断句。
4. 屏幕文字、系统提示和弹幕仅在与剧情理解相关且内容可确认时记录。
5. 第一目标是核心剧情、因果、人物关系、主要对白、反转和结尾钩子正确。
6. 任何来源无法确认时使用不确定标记或保守表达，不得根据剧情常识补写。
7. 字幕时间线中的 `dialogue_subtitle` 必须逐字保留；`ocr_text_candidate` 必须结合完整视频确认，疑似弹幕、重复错拼或非剧情文字不得写成人物对白。
8. 对白、OS、VO 和旁白保留视频原始语言和原字，不得翻译；剧情概要、动作、场景说明、不确定性说明和其他解释性内容使用简体中文。
9. 可确认的角色名、地点名、组织名、系统名、关键道具名和其他专有名词保留来源语言及原拼写，不翻译、不音译；无法确认时使用未知人物或保守描述，不得自行创建中文名称。
10. 第 2 集及后续任务会在 `task_cursor.video.known_characters` 提供同一作品、同一 Run 的前序规范角色名，在 `character_registry` 提供 `canonical_name`、已确认别名、首次/最近出现集数和出现次数，并在 `previous_episode_end` 提供最近一集剧情摘要。当前视频确认是同一人物时，`scenes[].characters` 与对白 `speaker` 必须统一输出 `canonical_name`；简称只能作为识别线索，不能作为新的规范姓名。
11. 当前证据与角色注册表冲突、出现近似错字或身份不足时，使用“未知人物”并写入 `speaker_unknown`/`unconfirmed`，不得另造近似姓名。只有当前完整视频或字幕明确确认时才允许新增角色名。Worker 会在提交前统一安全别名、拦截疑似错字，并根据规范化后的 `scenes[].blocks[]` 重新生成 `script_text`。

### 忠实还原

1. 可确认的主要对白尽量保留原句，不润色成另一种表达。
2. 不使用“某人表示”“某人解释”“某人质问”“两人争吵”等概述替代明确台词。
3. 短暂字幕或音频片段无法完整确认时，不拼接成看似完整但未经确认的台词。
4. 不要求为了形式完整而记录与剧情无关、重复出现或无法确认的屏幕文字。
5. 不声称输出是逐帧 OCR 结果或完整逐字稿。
6. 视频最后一帧之后的结果不得根据剧情趋势补写；结尾动作必须停在画面明确呈现的状态。
7. 同一条字幕证据只记录一次。悬浮文字、弹幕、系统提示或屏幕说明不得被重复分配给人物对白、OS 或 VO；确有清晰音频证明人物朗读时，必须在 `delivery` 标明“朗读屏幕文字”。

### 不确定信息

1. 台词明确但说话人不明时使用 `未知人物`。
2. 无法确认人物身份时不得擅自使用角色名；不得把弹幕评价、人物外观或模型推断当作姓名。
3. 分别使用 `［听不清］`、`［看不清］`、`［字幕遮挡］`、`［多人重叠，无法辨认］` 和 `［无法确认说话人］`。
4. 视频没有明确呈现的信息写“视频中未明确呈现”。

### 场次组织

1. 按剧情单元拆场，不按镜头、单句台词、短动作、系统弹窗或表情变化拆场。
2. 同一地点、同一时间段、同一组人物围绕同一剧情目标推进的内容合并为同一场。
3. 场次数量服从实际剧情，不强制凑满 2 至 5 场。
4. 短视频可以只有一场；不足 20 秒的连续片段优先并入前后相关场次。
5. 每场记录地点、内外景、时间段、整体时间码、出现人物和至少一条场景建立动作。

### 编剧提取稿格式

1. 动作行以 `△` 开头，只记录理解剧情所需的环境、状态、关系冲突、关键道具、伤势、表情和动作。
2. 不使用镜头转向、特写、近景、远景、推镜、航拍、慢动作、色调等导演分镜语言。
3. 表情或动作提示只用于情绪变化、冲突升级、伪装、威胁或反击，控制在 2 至 8 个字。
4. 对白、OS、VO、旁白、系统提示和屏幕文字必须分开记录。
5. 模型只输出结构化 `scenes[].blocks[]`；Worker 必须据此确定性生成完整 `script_text`，不得要求模型重复输出两份剧本正文。
6. 动作行不得出现“画面切换”“画面定格”“镜头切换”“特写”“近景”“远景”“推镜”“航拍”等导演语言。

### 闪回

1. 过去时间线、回忆、前情或想象式回看必须用 `【闪回】` 与 `【闪回结束】` 完整包裹。
2. 短闪回嵌入当前场，不单独编号。
3. 闪回内部继续使用动作、对白、OS 和 VO。
4. 闪回结束后必须明确回到当前时间线。

### 追溯要求

1. 时间码尽量准确到秒。
2. 每个场次必须绑定原视频及对应时间范围。
3. `source_refs.asset_id` 与 `source_refs.asset_snapshot_id` 必须沿用输入中的真实值，不得输出占位符。
4. 剧情概要只能概括已还原剧本中存在的事实。

### 使用边界

1. 本规则模块只用于视频到高还原剧本初稿。
2. 不用于小说转剧本或非小说素材创作。
3. 不输出亮点、爆款分析、传播价值、改编建议或优化建议。
4. 不参与主 Agent 的 Skill 路由，仅由 `video_reference_creation` Skill 的 `extract_video_scripts` Step 按需加载。
