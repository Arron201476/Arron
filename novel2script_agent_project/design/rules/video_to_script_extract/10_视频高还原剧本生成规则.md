# 10_视频高还原剧本生成规则

## 名称
10_视频高还原剧本生成规则

## 用途描述
仅供 `video_to_script_extract` Skill 使用，约束单集漫剧视频到高还原剧本初稿的生成。该规则模块服务剧情和主要对白还原，不承诺逐帧 OCR 或 100% 逐字转录，也不服务剧情改编或爆款分析。

## 准则

### 信息来源与目标

1. 画面用于理解剧情、人物、地点、动作、表情、关键道具和事件结果。
2. 内嵌字幕与清晰音频共同用于还原主要对白；音频可辅助断句和识别说话人。
3. 屏幕文字、系统提示和弹幕仅在与剧情理解相关且内容可确认时记录。
4. 第一目标是核心剧情、因果、人物关系、主要对白、反转和结尾钩子正确。
5. 任何来源无法确认时使用不确定标记或保守表达，不得根据剧情常识补写。

### 忠实还原

1. 可确认的主要对白尽量保留原句，不润色成另一种表达。
2. 不使用“某人表示”“某人解释”“某人质问”“两人争吵”等概述替代明确台词。
3. 短暂字幕或音频片段无法完整确认时，不拼接成看似完整但未经确认的台词。
4. 不要求为了形式完整而记录与剧情无关、重复出现或无法确认的屏幕文字。
5. 不声称输出是逐帧 OCR 结果或完整逐字稿。

### 不确定信息

1. 台词明确但说话人不明时使用 `未知人物`。
2. 无法确认人物身份时不得擅自使用角色名；不得把弹幕评价、人物外观或模型推断当作姓名。
3. 分别使用 `［听不清］`、`［看不清］`、`［字幕遮挡］`、`［多人重叠，无法辨认］` 和 `［无法确认说话人］`。
4. 视频没有明确呈现的信息写“视频中未明确呈现”。

### 场次组织

1. 按剧情单元拆场，不按镜头、单句台词、短动作、系统弹窗或表情变化拆场。
2. 同一地点、同一时间段、同一组人物围绕同一剧情目标推进的内容合并为同一场。
3. 场次数量服从实际剧情，不强制凑满 2 至 5 场。
4. 短视频可以只有一场；不足 20 秒的连续片段优先并入前后相关场次。
5. 每场记录地点、内外景、时间段、整体时间码、出现人物和至少一条场景建立动作。

### 编剧提取稿格式

1. 动作行以 `△` 开头，只记录理解剧情所需的环境、状态、关系冲突、关键道具、伤势、表情和动作。
2. 不使用镜头转向、特写、近景、远景、推镜、航拍、慢动作、色调等导演分镜语言。
3. 表情或动作提示只用于情绪变化、冲突升级、伪装、威胁或反击，控制在 2 至 8 个字。
4. 对白、OS、VO、旁白、系统提示和屏幕文字必须分开记录。
5. `script_text` 与结构化 `scenes[].blocks[]` 必须表达同一份完整剧本。

### 闪回

1. 过去时间线、回忆、前情或想象式回看必须用 `【闪回】` 与 `【闪回结束】` 完整包裹。
2. 短闪回嵌入当前场，不单独编号。
3. 闪回内部继续使用动作、对白、OS 和 VO。
4. 闪回结束后必须明确回到当前时间线。

### 追溯要求

1. 时间码尽量准确到秒。
2. 每个场次必须绑定原视频及对应时间范围。
3. `file_id` 必须沿用输入中的真实值，不得输出占位符。
4. 剧情概要只能概括已还原剧本中存在的事实。

### 使用边界

1. 本规则模块只用于视频到高还原剧本初稿。
2. 不用于小说转剧本或非小说素材创作。
3. 不输出亮点、爆款分析、传播价值、改编建议或优化建议。
4. 不参与主 Agent 的 Skill 路由，仅由 `video_to_script_extract` Skill 的提取步骤按需加载。
