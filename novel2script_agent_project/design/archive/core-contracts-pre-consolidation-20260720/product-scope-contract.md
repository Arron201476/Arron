# 产品目标与边界合同

本文档定义 Novel2Script Agent 当前版本的产品目标、用户边界、输入输出、职责分工和不做范围。它是进入前后端开发前的上游产品合同。

## 一句话定义

Novel2Script Agent 是一个面向短剧创作的 AI 工作台，帮助用户把小说原文、灵感、梗概、素材或本地文件，经过 Agent 管理的中间产物和确认节点，生成可编辑的短剧剧本。

## 目标用户

第一版目标用户：

- 短剧编剧。
- 内容策划。
- IP 改编人员。
- 需要把小说或素材快速整理成短剧剧本的人。

第一版不以普通娱乐聊天用户为目标。

## 核心用户任务

```text
用户输入小说 / 灵感 / 梗概 / 文件
-> Agent 判断入口
-> 生成或整理中间产物
-> 在关键节点请求用户确认
-> 生成剧本
-> 用户继续局部修改
```

## 输入范围

### 支持

- 小说原文。
- 小说片段。
- 短剧灵感。
- 故事梗概。
- 人物设定。
- 世界观设定。
- 台词片段。
- 爽点 / 桥段 / 限制条件。
- 本地文本类文件。

### 暂不作为主输入

- 分镜图。
- 视频。
- 音频。
- 多模态素材。
- 复杂表格型生产计划。
- 团队协作批注。

## 输出范围

### 主输出

- 短剧剧本。

### 中间产物

小说链：

```text
source_input
story_bible
episode_split
episode_cards
script_context
script_unit / scripts
```

非小说链：

```text
source_input
material_bank
story_seed
series_blueprint
episode_cards
script_context
script_unit / scripts
```

### 暂不做输出

- 分镜脚本。
- 镜头卡。
- 拍摄计划。
- 演员通告。
- 商业导出模板。
- 多平台格式导出。
- 计费 / 订阅 / 权限后台。

## 当前版本做什么

1. 支持小说链和非小说链两条入口。
2. 支持 Main Agent 判断用户意图。
3. 支持闲聊不启动 run。
4. 支持 run / artifact / approval / event 结构。
5. 支持关键节点确认。
6. 支持文件作为输入引用。
7. 支持剧本前的中间产物展示。
8. 支持剧本生成。
9. 支持选区和 artifact 级局部修改协议。
10. 支持 mock runtime 先跑通闭环，后续替换为 Eino runtime。

## 当前版本不做什么

1. 不做分镜、镜头卡、视频生成。
2. 不做多人协作。
3. 不做账号体系和生产级权限。
4. 不做复杂导出。
5. 不做计费和订阅。
6. 不做完整项目管理后台。
7. 不做自动全网素材抓取。
8. 不做没有用户确认的高影响覆盖。
9. 不把 Agent 聊天做成万能聊天机器人。

## Agent 职责

Agent 负责：

- 识别意图。
- 判断小说 / 非小说入口。
- 读取项目状态和 artifact。
- 决定下一步 action。
- 拼装 prompt job。
- 调用 runtime / model。
- 管理 approval。
- 解释错误和恢复路径。
- 处理局部修改范围。

Agent 不负责：

- 绕过用户确认覆盖关键产物。
- 在没有明确生成意图时启动流程。
- 把模型补全伪装成用户素材。
- 把内部字段直接展示给用户。

## 前端职责

前端负责：

- 展示三栏工作台。
- 展示 Agent 对话。
- 展示 artifact 内容。
- 展示 run 状态、approval、错误、完成态。
- 提供文件上传入口。
- 提供选区上下文。
- 调用后端 API。

前端不负责：

- 本地判断是否启动生成。
- 本地推进 workflow。
- 本地创建假 artifact。
- 直接调用模型。
- 保存 API key。

## 后端职责

后端负责：

- Project / Run / Artifact / Message / Approval / Event / File 的事实来源。
- Main Agent。
- Runtime Adapter。
- Artifact store。
- Run event stream。
- 文件解析与引用。
- 模型配置与调用。
- 安全与日志脱敏。

后端不负责：

- 输出未经校验的 raw LLM 结果作为正式 artifact。
- 绕过 schema 写入产物。
- 让前端决定 workflow 分支。

## 模型职责

控制模型负责：

- 意图识别。
- source_mode 判断。
- next_action 辅助决策。
- 用户补充说明理解。
- 局部修改范围辅助判断。

生成模型负责：

- 中间产物生成。
- 剧本生成。
- 局部内容改写。

模型不负责：

- 项目状态持久化。
- 用户权限。
- 是否跳过 approval。
- 是否覆盖 confirmed artifact。

## 成功标准

第一版产品设计合格标准：

1. 用户闲聊不会启动 run。
2. 小说和非小说入口能区分。
3. 两条链路都能走到分集卡。
4. 分集卡前后有明确 checkpoint。
5. 用户确认后能生成剧本。
6. 用户补充说明不会误开新 run。
7. 用户可以暂停、继续、失败重试。
8. 局部修改不会默认重写整部剧。
9. 前端能清晰展示当前状态和产物。
10. 后端能通过统一 API 支撑前端渲染。

## 开发准入判定

进入前后端正式开发前，至少要有：

- 本产品边界合同。
- 状态机合同。
- 信息架构合同。
- API / schema / Agent / runner / runtime / 安全 / 验收合同。
- 多状态 UI 稿。

如果产品边界发生变化，必须同步更新状态机、信息架构、API 和验收用例。
