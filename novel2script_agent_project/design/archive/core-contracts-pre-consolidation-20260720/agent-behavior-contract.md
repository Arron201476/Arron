# Agent 行为协议

本文档定义 Novel2Script Main Agent 的用户侧行为边界。完整运行模型见 `main-agent-model-runtime.md`。

## 核心原则

1. 用户输入先进入 Main Agent，不直接触发固定 workflow。
2. Main Agent 每轮只决定下一步最小动作。
3. 用户表达是开放集合，不能用关键词枚举判断意图。
4. 模型根据用户消息、附件、选区、run、events、artifacts、approval、active_task 共同判断意图。
5. 代码只校验有限动作是否合法，不承担自然语言语义分类。
6. 闲聊不创建 run，不生成 artifact。
7. 上传或粘贴素材不等于生成请求。
8. 等待确认时，补充说明默认作用到当前 checkpoint，不直接继续。
9. 失败恢复必须从失败 task 继续，不从整个 step 开头盲目重跑。
10. 局部修改必须有选区、artifact 或明确上下文。
11. Agent 回复文本不能反向触发执行；执行动作只能来自用户本轮明确语义或尚未解决的修改确认。
12. 历史选区是一次性执行上下文，修改成功、审批、启动新任务或切换产物后失效。
13. 有待确认产物时，不同 artifact 的修改不得替换当前审批。
14. 只定位到内容但没有修改方向时必须追问，不得自行补写要求。
15. 上游修改默认保留下游；只有用户在影响确认卡中选择后，才重新生成受影响内容。
11. Agent 对用户说产品语言，不暴露内部字段、工具名、schema 堆栈或模型推理。

## 用户输入分类

### chat_idle

问候、闲聊、问当前状态、问产品怎么用。

行为：

- 只回复。
- 不创建 run。
- 不改变 artifact。

### inspect_source

用户明确要求分析、总结、解释或评价当前作品中已上传的附件。

行为：

- Main Agent 只根据文件索引和截断预览识别意图并定位目标文件。
- 内容 Worker 按 `target_file_ids` 读取目标正文并直接回复用户。
- 不创建 run，不创建或修改 artifact，不改变作品的 source mode。
- 单附件的自然指代可自动解析；多附件无法定位时先追问，不提前读取全部正文。
- 不根据上传动作自动认定文件是小说，文件类型由正文证据和用户意图决定。

### generate_from_novel

用户语义上要求把小说原文改编为剧本。

行为：

- 创建 run。
- `source_mode = novel`。
- 进入小说链：故事圣经 -> 原文拆集 -> 分集卡 -> 剧本生成。
- 每个关键产物生成后停下让用户确认。

### generate_from_material

用户语义上要求根据灵感、梗概、素材、人设生成剧本。

行为：

- 创建 run。
- `source_mode = non_novel`。
- 进入非小说链：素材库 -> 故事种子 -> 剧集蓝图 -> 分集卡 -> 剧本生成。
- 每个关键产物生成后停下让用户确认。

### revise_checkpoint

run 正在等待确认或暂停，用户提出对当前产物的补充、调整、改写意见。

行为：

- 不跳过确认。
- 不直接进入下一步。
- 把补充说明作用到当前待确认产物。
- 修改后重新请求用户确认。

### approve_checkpoint

run 正在等待确认或暂停，用户语义上明确确认继续。

行为：

- resolve 当前 approval。
- 继续下游 step。
- 不创建新 run。
- 历史确认卡片应失效，不允许重复点击旧确认。

### pause_run

用户语义上要求暂停、先别继续、等等。

行为：

- run 进入 paused。
- 保留当前 artifact 和 approval。
- 后续用户补充说明不自动继续，除非语义上明确要求继续。

### rerun_step

run 失败后，用户语义上要求继续、重试、重新执行失败部分，或指出刚才没有真正重跑。

行为：

- 调用失败恢复。
- 从 `active_task` 继续。
- 如果第 3 集剧本生成失败，从第 3 集继续生成，再跑后续集。
- 不从第 1 集或整个 step 开头重跑已成功任务。

### explain_current_state

用户问当前到哪、为什么停、哪里失败、日志或状态。

行为：

- 解释状态。
- 不自动继续或重跑。

## 明确不做的事

- 不把问候、问号、闲聊识别成生成。
- 不把上传文件本身识别成生成。
- 不用本地关键词枚举替代模型语义判断。
- 不在分集卡未确认时生成剧本。
- 不在失败后只发“我会重跑”但不调用 runtime。
- 不从第 1 集重新生成已经成功的后续任务。
- 不让前端按钮决定完整业务流程。
- `inspect_artifact` 没有后续异步执行器；查看、解释或分析产物时必须在本轮回复中直接给出结论，或提出一个精确的澄清问题，不能只回复“稍等”或“之后再告诉你”。

## 关键确认点

当前关键产物都应 checkpoint：

- 小说链：故事圣经、原文拆集、分集卡、分集剧本。
- 非小说链：素材库、故事种子、剧集蓝图、分集卡、分集剧本。
- 高影响局部修改：改集数、改主线、改人物关系、改分集结构、重写整集。

`script_context` 是剧本生成前的内部归一化产物，不在用户目录中展示，也不单独要求确认。

## 失败恢复

失败恢复的判断分两层：

1. Main Agent 根据上下文判断用户是要解释失败，还是恢复执行。
2. Runtime 根据 `active_task` 决定从哪个 task 继续。

示例：

```text
step = script_unit
active_task = task_generate_script_episode_3
episode_id = 3
task_cursor = 2
task_total = 8
```

用户语义上要求继续或质疑没有重跑时：

- Main Agent 输出 `next_action = rerun_step`。
- Runtime 从 `task_cursor = 2` 继续。
- 先重跑第 3 集。
- 成功后继续第 4 集、第 5 集，直到当前 step 完成。

## 前端职责

前端只做：

- 展示聊天。
- 展示 artifact。
- 展示 run / event / approval 状态。
- 收集用户输入、附件、选区。
- 把用户操作交给后端。

前端不做：

- 不自行判断是否启动生成。
- 不自行决定下一步流程。
- 不把暂停中的用户输入插入旧流程。
- 不硬编码小说链或非小说链执行顺序。
