# 前端 UI/UE 核心合同

## 当前阶段

前端三栏工作区、作品入口、过程产物阅读与编辑、剧本编辑器和 Agent 对话已经进入正式实现与验收阶段。当前交互以本文档、`information-architecture-contract.md`、`agent-behavior-contract.md`、`frontend-visual-refresh-implementation.md` 和真实 React 实现共同对齐。

## 使用原则

- 真实 React 工作区是界面实现依据，历史 Figma、静态稿和过程审计仅用于追溯。
- 修改交互时必须同时验证作品切换、刷新恢复、运行中状态、产物编辑和 Agent 对话。
- 视觉调整不能改变 Agent 意图、流程状态、Artifact 结构或审批协议。

## 保留

- 保留左中右三栏：左侧工作区目录，中间承载输入、过程产物、剧本和运行记录，右侧 Agent 聊天。
- 保留右侧 Agent 作为最大入口，用户的生成、修改、补充、确认、暂停都从这里发生。
- 保留剧本页的分集目录加正文编辑器结构，剧本是最重编辑对象。
- 保留中间产物可结构化阅读和 JSON 编辑能力，但默认阅读态必须先给用户看懂。
- 保留每个关键产物完成后的确认机制，确认卡必须嵌在聊天流里，不做脱离聊天的悬浮确认区。

## 改掉

- 清理“演示 demo”逻辑：任何界面文案、状态、产物都必须来自当前项目状态或当前 artifact，不允许用固定假数据冒充真实结果。
- 清理混链路目录：小说链路只展示小说步骤，非小说链路只展示非小说步骤，未识别前只展示输入材料、过程产物、剧本、运行记录。
- 清理错误状态顺序：未确认上游产物时，下游不能显示生成中或已生成。
- 清理技术内参泄露：意图识别、剧本上下文等内部步骤可出现在运行记录，不作为普通用户主视图 tab 暴露。
- 清理按钮和输入框错位：所有按钮文字和图标必须水平、垂直居中，按钮不能贴边、不能文本截断，icon-only 按钮必须有 `aria-label`。
- 清理不可读 artifact 展示：默认阅读态用中文字段名和层级展示，英文 key 只作为辅助标记；不能只丢一大块 JSON 给用户。

## 不复制

- 不复制旧 Figma 中局部 frame 的固定项目名、自动保存、小说改编徽标、无效进度条、无来源文件列表。
- 不复制当前 mock 里“用户添加附件就等于已保存输入”的逻辑。附件只有随消息发送后，才进入输入材料。
- 不复制把所有执行步骤一次性展示为已完成的旧展示方式。步骤必须随真实事件流逐个出现。
- 不复制把所有失败都靠“继续/重试”关键字硬触发的逻辑。失败恢复应由主 Agent 根据上下文识别用户意图。

## 左中右职责

左侧工作区：
- 只展示当前链路下用户需要理解的节点。
- 状态只表达物料状态：待生成、生成中、待确认、已生成、修改中、失败。
- 不展示内部模型任务，如识别意图、准备上下文、prompt 拼装。

中间工作区：
- 输入材料：只读预览已发送内容和附件解析内容，不支持直接编辑；修改输入必须通过 Agent 或重新发送材料。
- 过程产物：默认结构化阅读，支持 JSON 编辑；对某个字段的修改需求可从右侧 Agent 发起。
- 分集卡：可以按集卡片展示；如果内容足够多，可增加目录，但目录不能和编辑器工具栏混为一个模块。
- 剧本：使用正文编辑器，支持分集切换、选区、基础格式化、局部修改建议和保存。
- 运行记录：只展示执行日志，不承载业务产物正文。

右侧 Agent：
- 承载聊天、附件、配置确认、产物确认、失败恢复、局部修改建议。
- 历史确认卡必须保留上下文但不可操作。
- 当前确认卡只能有一个可操作焦点。
- Agent 的回复必须说明当前在做什么、为什么需要用户确认、下一步会发生什么。

## 组件约束

- Button：固定高度、inline-flex、居中、不可换行；primary/secondary/ghost/destructive 语义清晰；禁用态可见但不可点。
- IconButton：只放图标，必须有 `aria-label`，图标几何中心与按钮中心一致。
- StatusBadge：只表达对象状态，不表达用户确认动作；“已确认”只在确实发生用户确认后出现。
- AgentMessage：用户、Agent、工具步骤、确认卡、建议修改卡都在同一聊天流内。
- AttachmentChip：附件必须显示文件名、大小和可移除按钮；只在消息发送后进入 artifact。
- ArtifactCard：中文标题优先，英文 key 辅助；字段、数组、对象层级清晰。
- ScriptEditor：工具栏只属于正文编辑器，宽度与正文编辑区对齐；分集目录是独立侧栏。

## 状态约束

- 每条生成链路启动前必须确认生成配置：目标集数、单集时长；小说链路额外有“保留原分集”，默认不勾选。
- 每个关键 artifact 完成后进入待确认；用户确认后才能进入下游。
- 用户在待确认阶段提出修改，必须优先识别为“修改当前 artifact”，不能启动新 run。
- 失败后恢复要从失败 task 继续，不默认重跑整个 step；如果缺少精确 task 能力，前端必须展示为“当前只能重跑该步骤”。
- 运行记录可以展示内部任务，但普通工作区 tab 不展示内部任务。

## Artifact 展示契约

- 前端必须展示模型返回给后端的全部字段，不能静默丢字段。
- 展示顺序优先使用产品阅读顺序；未知字段也要落入“其他字段”区。
- 空数组、空对象必须显示为空，不能看起来像加载失败。
- 编辑 JSON 保存后，后续步骤必须使用最新 artifact 版本。
- 从 Agent 修改 artifact 时，修改成功后必须刷新中间工作区当前 artifact。

## 剧本编辑器契约

- 剧本正文编辑器是最终产物编辑区，不是展示模板。
- 支持分集目录切换，切换时保留当前集未保存编辑态或明确提示保存。
- 支持选区，选区会作为 `selection_context` 发送给 Agent。
- 支持基础格式：正文、标题、批注块、加粗、斜体、下划线、删除线、清除格式。
- Agent 建议修改后，用户接受才写回正文；拒绝不改变正文。

## 质量门禁

进入正式前端开发前，至少通过以下检查：

- 所有按钮和 icon button 截图检查居中。
- 生成配置卡在小说和非小说生成意图下必出。
- 小说链路和非小说链路的左侧目录互不串线。
- 每个 artifact 的所有字段都能显示，未知字段不丢失。
- 输入材料预览展示已发送文本和附件解析内容。
- 剧本编辑器能选中、删除一段文字、切换集、执行基础格式命令。
- 历史确认卡不可点，当前确认卡可点。
- 失败恢复能解释失败点，并能从失败点或失败步骤继续。
- `npm run build` 通过。
- `design/preview.html` 已重建并包含本文档。
