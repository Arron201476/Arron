# 中间产物可读可编辑方案

本文定义 Novel2Script Agent 的过程产物在前端如何展示、编辑、保存，以及 Agent 介入修改后如何刷新。

## 1. 核心原则

- 用户默认不看 JSON，不看英文 schema 字段名。
- 产物展示必须用中文业务标签、分组标题和可读段落。
- JSON 只作为开发调试入口，不作为普通用户编辑方式。
- 每一步进入下一步前，后端必须读取该 artifact 的最新版本，包括用户手动编辑和 Agent 修改后的结果。
- 用户手动编辑和 Agent 修改使用同一套 artifact version 机制，不能出现“页面改了但下一步仍用旧数据”。
- 输入材料只读预览，过程产物可编辑，剧本用正文编辑器。

## 2. 前端展示层

每个 artifact 不直接把 payload 展开给用户，而是先转换成 `ArtifactViewModel`：

```json
{
  "artifact_type": "story_bible",
  "version": 3,
  "status": "pending_approval",
  "sections": [
    {
      "section_id": "characters",
      "title": "人物",
      "summary": "主要角色、目标、关系位置和声口。",
      "editable": true,
      "items": []
    }
  ]
}
```

ViewModel 负责三件事：

1. 中文命名：把 `characters[].goal` 显示成“人物目标”。
2. 结构降噪：隐藏空字段、内部字段和英文 key。
3. 编辑映射：每个可编辑块都保留内部 `field_path`，保存时能回写到原 payload。

## 3. 编辑方式

### 导航与空间规则

- 左侧作品目录只负责 artifact 流程切换，中间内容区不得再重复一套横向 artifact 目录。
- 当前 artifact 内部使用独立的“产物大纲”，只负责人物、关系、世界规则等段落定位。
- 桌面端产物大纲固定在正文左侧；窄屏使用“大纲”按钮打开纵向浮层，选择段落后自动关闭。
- 查看态与编辑态必须共用同一个产物大纲、章节顺序和章节 DOM 定位，禁止进入编辑后替换成另一套横向字段目录。
- 进入编辑态不得自动关闭作品目录或 Agent，也不得重置当前滚动位置。

### 普通编辑

用户点击“编辑内容”后，不打开 JSON，也不跳转到独立表单页；当前章节内容在原阅读结构中就地变为结构化控件：

- 文本字段：多行文本框。
- 数字字段：数字输入。
- 是否项：勾选框。
- 人物、分集、场景等列表项：展开成一张张可编辑卡片。
- 空数组：显示“暂无内容”，允许后续增加项。
- 一级章节仍可展开、收起，并通过同一个产物大纲定位。
- 保存、取消固定在产物标题栏；未修改时保存按钮不可用。

保存时前端提交完整更新后的 payload，后端创建新版本 artifact。

### Agent 修改

用户在右侧提出修改时，Agent 必须先判断修改粒度：

- field：只改一个字段，例如“把主角目标写清楚”。
- entity：改一个实体，例如“重写主角信息”。
- section：改一个区块，例如“人物关系整体不对”。
- artifact：重写整个产物，例如“故事圣经重做”。
- selection：改选中的剧本文字。

Agent 修改完成后：

1. 后端写入新版本 artifact。
2. 前端收到 artifact update 后刷新中间区域。
3. 右侧聊天解释“改了哪里”；过程产物不强制展示 diff，剧本继续使用已有选区建议/对比能力。
4. 已有下游先保持可见和原状态；用户明确选择重新生成后，实际受影响项才标记 stale。

定位与 patch 规则：

- 字段路径可使用数字下标或稳定命名选择器，例如 `characters[0].goal`、`characters[主角].goal`、`characters[name=主角].goal`。
- Main Agent 确认的 artifact、字段、实体、场景和集数是执行边界，内容模型不得返回另一个目标。
- entity 修改支持替换、新增、删除；任何操作都必须保留未命中的兄弟实体。
- 目标 payload 中真实存在的扩展字段允许修改；不存在且无法映射的路径必须追问或拒绝。
- patch 无法应用时不得保存稀疏或残缺 payload，新版本保持未创建。

## 4. 两条链路的产物展示

### 小说链路

| 产物 | 用户看到 | 默认编辑粒度 | 下一步读取 |
| --- | --- | --- | --- |
| 输入材料 | 文件名、正文预览、生成配置 | 只读 | 最新 source_input |
| 故事圣经 | 故事目标、核心冲突、人物、关系、必保留事实、改编风险 | 字段 / 人物 / 区块 / 整体 | 最新 story_bible |
| 原文拆集 | 每集原文范围、核心事件、切分理由、边界检查、覆盖检查 | 单集 / 边界 / 整体 | 最新 episode_split |
| 分集卡 | 每集开场、冲突、爽点、人物转折、尾钩、场景规划 | 单集 / 字段 / 整体 | 最新 episode_cards |
| 剧本上下文 | 默认不在左侧展示，仅用于生成剧本 | 内部产物 | 最新 script_context |
| 剧本 | 分集目录 + 正文编辑器 | 选区 / 场景 / 单集 / 整体 | 最新 script_unit / scripts |

### 非小说链路

| 产物 | 用户看到 | 默认编辑粒度 | 下一步读取 |
| --- | --- | --- | --- |
| 输入材料 | 灵感、文件、用户补充说明、生成配置 | 只读 | 最新 source_input |
| 素材库 | 人物素材、冲突素材、情绪驱动、钩子候选、缺口问题 | 字段 / 素材项 / 区块 / 整体 | 最新 material_bank |
| 故事种子 | 核心前提、主角、中心冲突、类型、主线 | 字段 / 人物 / 区块 / 整体 | 最新 story_seed |
| 剧集蓝图 | 分阶段规划、高潮位置、爽点分布、人物推进 | 阶段 / 区块 / 整体 | 最新 series_blueprint |
| 分集卡 | 每集功能、开场状态、主冲突、反转、尾钩、场景规划 | 单集 / 字段 / 整体 | 最新 episode_cards |
| 剧本上下文 | 默认不在左侧展示，仅用于生成剧本 | 内部产物 | 最新 script_context |
| 剧本 | 分集目录 + 正文编辑器 | 选区 / 场景 / 单集 / 整体 | 最新 script_unit / scripts |

## 5. 刷新和版本规则

- 用户保存表单：立即创建新 artifact version。
- Agent patch：只刷新被改字段、实体或区块，但落库时仍保存完整 payload。
- Agent regenerate：生成新版本 artifact，旧版本 superseded。
- 修改上游 artifact 后，下游 artifact 不自动静默重写；已有下游先请求处理确认，仅在用户选择重生成后标记 stale 并重跑。
- 当前确认卡只能操作当前版本，历史确认卡不可点。
- 下一步执行永远读取 `latest confirmed or pending_approval artifact`，不得读取旧版本。

## 6. 需要前端继续落地的组件

- `ArtifactViewModelMapper`：payload 到中文展示模型。
- `ArtifactFormRenderer`：按 ViewModel 渲染表单。
- `ArtifactPatchPreview`：Agent 修改前后对比卡。
- `ArtifactVersionBar`：显示当前版本、保存状态、是否有下游影响。
- `InternalJsonDrawer`：仅开发调试使用，默认隐藏。

## 7. 当前实现阶段

当前前端已先完成第一层修正：

- 默认隐藏英文 key。
- 普通用户入口统一为“编辑内容”。
- 查看与编辑共用纵向产物大纲和章节结构，编辑控件在原章节内就地出现。
- 桌面大纲常驻；窄屏通过“大纲”浮层定位，避免横向字段目录占满页面。
- 左侧作品目录是唯一流程目录，中间内容区不再重复 artifact 横向切换条。

后续应继续把通用递归表单升级为 artifact 专属 ViewModel，这样故事圣经、素材库、分集卡等可以拥有更贴合编剧语言的展示组件。
