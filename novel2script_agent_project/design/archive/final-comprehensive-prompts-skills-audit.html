一、此前你反复强调过的审计标准

  1. Skills 只是准则。 Skill 只能有名称、用途描述、准则；不能放输入、输出、参数、JSON、字段协议。
  2. Prompts 是可执行步骤。 Prompt 才负责角色、任务、引用 skills、输入、执行规则、输出、禁止事项。
  3. 引用必须被消费。 Prompt 引用某个 skill，必须能在执行规则或输出 artifact 中找到实际消费路径；完全不消费就不要引用。
  4. 部分消费要写清边界。 例如 Step3 引用转场 skill 只能消费视觉/闪回/转场策略，不能把剧本格式规则也带进规划层。
  5. Skill 准则不能悬空。 如果 skill 里有判断维度，prompt/artifact 要有承接字段；否则这条准则只是噪音。
  6. 小说链 Step1/Step2 已重排。 Step1 做全文理解/故事圣经，Step2 再拆集；Step1 不拆集、不重排、不生成剧本。
  7. 拆集策略要保守。 可以识别风险，但不能为了钩子或节奏擅自改原文关键事实、乱合并、乱新增。
  8. 上下文靠 artifact，不靠 prompt 祈祷。 Step3/Step4 必须消费最新 story_bible、episode_split_final、episode_cards、context_pack、continuity_delta。
  9. 小说/非小说双链路，剧本生成共用。 最后一段 script_generate 应是公共能力，小说和非小说只是拼参不同。
  10. 不依赖前端也要能跑。 前端只是编辑、审批、展示；prompt/artifact 自己要足够让工程自动调度。
  11. 不要在 prompt/skill 里解释历史。 不写“旧流程”“为什么这样改”“之前如何”等说明性文本。
  12. 反馈问题要分层。 能靠 prompt/skill 解决的处理；需要前端、agent、审批、局部重跑的标未处理，不硬塞进 prompt/skill。
