# 产品检查清单

本文档给产品视角使用，不要求懂前端、后端或 SDK。检查时只看用户体验和 Agent 行为是否合理。

## 你要检查什么

不用检查字段名和代码结构，只看下面 8 个问题。

### 1. 用户输入后，Agent 是否先判断入口

合格表现：

```text
用户贴小说 -> Agent 说这是小说改编
用户写灵感 -> Agent 说这是非小说开发
用户选中一段 -> Agent 说会只改这一段
用户只是聊天 -> Agent 不启动生成流程
```

不合格表现：

```text
不管用户输入什么，都直接生成剧本
把灵感当小说原文
用户只想改一句，Agent 重写整集
```

### 2. Agent 是否先读现状，再动手

合格表现：

```text
改已有内容前，先说明它会读取当前 artifact 和上下文
续写前，先看上一集/上一场/当前角色状态
局部修改前，先识别选区来源
```

不合格表现：

```text
不看当前项目，直接凭空续写
不知道用户选中的是剧本、大纲还是分集卡
改完后上下文断裂
```

### 3. 是否会保护用户确认过的内容

合格表现：

```text
覆盖故事圣经、拆集方案、分集卡前会询问
改集数、改主线、重排结构前会停下来确认
重跑上游步骤后，下游只标记需复查，不自动覆盖
```

不合格表现：

```text
悄悄覆盖已确认的分集方案
用户改了一个设定，Agent 自动重写所有剧本
旧版本找不回来
```

### 4. 是否支持暂停、继续、重跑

合格表现：

```text
用户可以在关键节点点“暂停”
继续时知道上次跑到哪一步
重跑某一步会生成新版本
失败后可以 retry 或改指令再跑
```

不合格表现：

```text
暂停后丢状态
失败后只能从头开始
重跑直接覆盖旧产物
```

### 5. 剧本是否逐步生成，而不是突然刷满

合格表现：

```text
右侧能看到 Building story bible - done
Writing dialogue beat - done
Inserting episode hook - done
中间剧本区域逐批出现内容
```

不合格表现：

```text
用户等很久，然后整集剧本突然出现
不知道 Agent 正在做什么
生成失败时不知道失败在哪一步
```

### 6. 局部修改是否足够克制

合格表现：

```text
用户选中一句对白，Agent 只改这句或这组对白
用户指定第 5 集尾钩，Agent 不改前 4 集
只有影响连续性时，才提示后续集需要复查
```

不合格表现：

```text
局部修改变成全文重写
改一句对白导致故事圣经也被改
Agent 不解释影响范围
```

### 7. Agent 是否用人话回复

合格表现：

```text
“第 3 集尾钩改强了。”
“我会先确认拆集方案，再继续写剧本。”
“刚才选中的那段对白已经压短。”
```

不合格表现：

```text
“artifact_id 已 invalidated。”
“selection_ref offset 更新完成。”
“tool_call 执行失败。”
```

### 8. 从用户输入到剧本输出是否闭环

小说链应能走通：

```text
小说原文
-> 故事圣经
-> 拆集方案
-> 分集卡
-> 剧本
```

非小说链应能走通：

```text
灵感/梗概/素材
-> 素材库
-> 故事种子
-> 剧集蓝图
-> 分集卡
-> 剧本
```

## 你不用检查什么

```text
不用检查 Go 接口怎么命名
不用检查 TypeScript 组件怎么拆
不用检查 Claude SDK 怎么调用
不用检查 JSON schema 是否每个字段都完美
不用检查分镜、镜头卡、计费、订阅流程
```

## 一句话验收标准

如果你作为产品方能清楚看到：

```text
Agent 知道用户想干什么
Agent 不乱覆盖
Agent 关键节点会停下来问
Agent 能局部改
Agent 能继续跑
Agent 最后能稳定产出剧本
```

那第一版主流程设计就是合格的。
