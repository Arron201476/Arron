# AI 项目前后端开发前置文档清单（通用）

本文档用于判断一个新的 AI 产品项目，什么时候可以进入正式前后端开发。它不绑定 Novel2Script，适用于 Agent、AI 生成工具、AI 工作台、AI Copilot、AI 内容生产平台等项目。

核心原则：先把产品、状态、数据、Agent 行为、接口、UI 稿、验收用例说清楚，再进入工程实现。否则前后端会边写边猜，模型接入后问题会被放大。

## 必备文档

### 1. 产品目标与边界文档

说明这个 AI 产品到底做什么、不做什么。

必须包含：

- 目标用户是谁。
- 用户输入什么。
- AI 输出什么。
- 核心任务路径是什么。
- 本期范围和暂不做范围。
- 哪些事情由 AI/Agent 做，哪些事情由普通 UI 做。
- 成功标准是什么。

没有这份文档，团队会把产品做成“什么都能聊一点，但什么流程都不稳定”的聊天框。

### 2. 用户流程与状态机文档

说明用户从进入产品到拿到结果，会经历哪些状态。

必须包含：

- 初始态。
- 普通闲聊态。
- 创建任务态。
- 运行中。
- 等待用户确认。
- 暂停。
- 失败。
- 完成。
- 用户补充信息。
- 用户取消或重试。

还要说明每个状态下：

- 用户能做什么。
- 用户不能做什么。
- 系统自动做什么。
- 状态如何跳转。
- 哪些状态需要持久化。

没有这份文档，最容易出现：闲聊触发任务、等待确认时误开新任务、暂停后无法继续、失败后没有恢复路径。

### 3. 信息架构文档

说明产品界面分成哪些区域，每个区域承载什么。

必须包含：

- 页面结构。
- 导航结构。
- 主内容区展示什么。
- AI/Agent 入口在哪里。
- 设置、历史、文件、结果、过程产物如何组织。
- 哪些入口是主入口，哪些只是辅助入口。

没有这份文档，前端会把流程按钮、结果内容、对话、设置、历史全部混在一起。

### 4. 静态 UI 稿 / 高保真交互稿

这是进入前端开发前必须有的，不是可选项。

必须覆盖：

- 初始态。
- 输入态。
- 上传文件态。
- AI 思考中。
- 执行步骤展示。
- 等待用户确认。
- 用户补充要求。
- 失败态。
- 完成态。
- 结果编辑态。
- 历史 / 版本 / 记录查看态。

UI 稿至少要明确：

- 页面布局。
- 组件形态。
- 按钮位置。
- 状态展示。
- 空态。
- loading。
- 错误提示。
- 移动端或窄屏策略。

没有静态 UI 稿，前端只能按工程直觉搭页面，最后会出现按钮乱放、状态乱叫、图标乱用、组件像后台模板的问题。

### 5. 组件语义与文案规范

说明组件应该怎么命名、怎么显示、怎么写文案。

必须包含：

- 按钮类型：主按钮、次按钮、危险按钮、图标按钮。
- 按钮文案规则。
- 状态命名规则。
- loading / done / failed / waiting 的展示规则。
- 图标使用规则。
- 卡片、消息、表单、附件、审批卡、任务步骤的语义。
- 哪些组件看起来可点击，哪些只是展示。

没有这份文档，UI 会反复出现“看起来能点但不能点”“done 和用户确认混用”“按钮文案像系统日志”的问题。

### 6. 数据对象 / Artifact Schema 文档

说明 AI 生产过程中会产生哪些结构化对象。

必须包含：

- 输入对象。
- 中间产物。
- 最终结果。
- 每个对象的字段。
- 字段类型。
- 字段来源。
- 字段是否可编辑。
- 字段被哪个下游使用。
- 上游变化后哪些下游失效。

没有这份文档，前端只能展示 JSON，后端也无法稳定串联上下游。

### 7. Agent 行为协议文档

说明 Agent 如何理解用户、如何执行任务、如何和用户确认。

必须包含：

- 意图分类。
- 什么时候只回复。
- 什么时候创建任务。
- 什么时候调用工具或模型。
- 什么时候请求用户确认。
- 用户补充说明如何进入当前任务。
- 局部修改如何定位上下文。
- 失败后如何解释和恢复。
- Agent 能做什么，不能做什么。

没有这份文档，Agent 会变成一个不可控聊天机器人，而不是流程管理者。

### 8. Prompt / Tool / Skill 设计文档

说明模型每一步如何工作。

必须包含：

- 每个 prompt 的任务目标。
- 输入字段。
- 输出字段。
- 约束条件。
- 可引用的知识 / skill。
- 不允许做的事。
- prompt 之间如何交接。
- 工具调用的边界。

没有这份文档，模型效果无法复现，也无法判断问题出在 prompt、上下文、工具还是 UI。

### 9. API / 事件协议文档

说明前后端如何通信。

必须包含：

- 项目 / 会话 / 任务 / 消息 / 文件 / 结果的接口。
- 请求字段。
- 响应字段。
- 错误码。
- 长任务更新方式：SSE、WebSocket、轮询或任务队列。
- 事件类型。
- 审批请求和审批结果的数据结构。
- 文件上传、引用、删除的协议。

没有这份文档，前后端会互相猜字段，页面可能看起来通了，但状态不可维护。

### 10. 模型与运行时策略文档

说明模型怎么选、怎么分工、怎么兜底。

必须包含：

- 控制模型和生成模型是否分离。
- 每类任务用哪个模型。
- 上下文如何裁剪。
- 历史如何持久化。
- 文件如何进入上下文。
- 失败、超时、限流如何处理。
- 成本和速度的基本策略。
- 是否允许 mock / fallback。

没有这份文档，接模型后会出现上下文丢失、职责混乱、成本不可控、错误难排查。

### 11. 权限、数据与安全文档

如果项目涉及用户数据、企业数据、文件上传、隐私内容，这份文档必须有。

必须包含：

- 哪些数据会被保存。
- 保存在哪里。
- 保存多久。
- 谁能访问。
- 文件是否会进入模型上下文。
- 日志是否会记录敏感内容。
- key、token、模型配置如何管理。
- 用户删除数据如何处理。

没有这份文档，AI 项目很容易在文件、日志、上下文里泄露敏感信息。

### 12. 验收用例与测试清单

说明什么叫“开发完成”。

必须包含：

- 正常主流程用例。
- 闲聊不触发任务。
- 上传文件用例。
- 等待确认用例。
- 用户补充说明用例。
- 失败重试用例。
- 暂停继续用例。
- 局部修改用例。
- 空态、loading、错误态。
- 前后端接口验收。
- 模型输出结构验收。

没有这份文档，项目只能靠人工随手点，问题会反复漏。

## 最小开发准入标准

进入前后端开发前，至少要满足：

1. 产品目标与边界已定。
2. 用户流程和状态机已定。
3. 信息架构已定。
4. 静态 UI 稿覆盖主要状态。
5. 组件语义和文案规则已定。
6. 核心数据对象 / artifact schema 已定。
7. Agent 行为协议已定。
8. API / 事件协议已有第一版。
9. 模型与运行时策略已有第一版。
10. 至少有一组端到端验收用例。

如果这些还没准备好，不建议直接进入正式前后端开发。可以先做 mock worker、静态 UI 稿、接口草案和可点击原型。
