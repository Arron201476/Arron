# 方向 1 模块取舍审计

本文档用于决定方向 1 `Quiet Manuscript Desk` 中哪些模块进入 UI/UE 定稿，哪些需要合并、条件显示或删除。方向 1 是视觉基准，但不是逐元素终稿。

## 总原则

1. 保留方向 1 的整体布局、密度、层级和安静写作工作台气质。
2. 不把方向 1 中所有模块都直接实现。
3. 同一信息可以在不同区域出现，但必须承担不同职责；如果只是重复展示，合并或降级。
4. 顶栏、左侧、中间、右侧各自只做自己的事，不跨区抢功能。
5. AI 指令入口只在右侧 Agent；中间和左侧不出现生成、改写、续写按钮。

## 顶栏

| 模块 | 处理 | 原因 |
|---|---|---|
| 产品标识 / Novel2Script Agent | 保留 | 帮助识别产品和工作台环境。 |
| 项目名 | 保留 | 当前项目上下文必须一直可见。 |
| source mode 标签 | 保留 | 小说改编 / 非小说生成影响左侧链路和后续流程。 |
| 自动保存状态 | 保留，但只在有可保存文档或 artifact 时高亮 | 对最终剧本编辑很重要；未进入编辑态时低权重即可。 |
| 项目设置 | 条件保留 | 第一版可保留入口，但不应成为主操作。 |
| 导出 | 条件显示 | scripts 生成前可禁用或低权重；不要在未生成阶段抢注意力。 |
| 用户 / 编剧助手入口 | 保留但低权重 | 可作为账号、角色、provider 状态入口，不参与主流程。 |

## 左侧项目目录

| 模块 | 处理 | 原因 |
|---|---|---|
| 项目卡 | 保留 | 项目标题、题材、集数、摘要是有用上下文。 |
| 创作流程标题 | 保留 | 分组说明左侧不是按钮面板，而是项目进度目录。 |
| 输入材料 | 保留 | 用户必须能回看源文本、附件和解析状态。 |
| 过程产物 | 合并为分组，不一定作为可点击单项 | 它是分类，不应该和具体 artifact 抢层级。 |
| 素材库 / 故事圣经 / 故事种子 / 剧集蓝图 | 按 source_mode 条件显示 | 小说链和非小说链不能同时展开完整条目。 |
| 分集卡 | 保留 | 这是进入剧本生成前的关键 checkpoint。 |
| 剧本 | 保留并靠前 | 最终产物必须容易到达。 |
| 剧本上下文 | 默认降级到过程产物内 | 对用户不是一等入口，更像技术/过程产物。需要时可在过程产物内查看。 |
| 运行记录 | 保留在最后 | 用户需要排查过程，但不能和内容产物混在一起。 |
| 整体进度卡 | 条件显示 | run 进行中时有价值；闲聊、未开始或完成后可折叠为摘要。 |
| 收起侧栏 | 保留 | 长剧本编辑时需要给中间区更多宽度。 |

### 左侧状态规则

- 左侧只显示简短状态：待添加、待生成、生成中、待确认、已生成、已确认、已失效、失败。
- 没有用户确认动作，不显示“已确认”。
- 左侧不显示完整错误堆栈、完整任务步骤或模型事件。
- 左侧不显示不存在的另一条链路。

## 中间内容区

| 模块 | 处理 | 原因 |
|---|---|---|
| Artifact 标题 / 面包屑 | 保留 | 让用户知道正在看哪个产物、哪一集或哪个版本。 |
| 状态 badge | 保留 | 当前内容是否待确认、生成中、已生成必须清楚。 |
| 结构视图 / 脚本视图切换 | 条件保留 | 分集卡和剧本编辑场景有用；普通素材库不需要。 |
| Word-like 工具栏 | 只在最终剧本编辑器显示 | 过程产物字段化编辑不需要完整富文本工具栏。 |
| 文档页编辑器 | 保留 | 最终剧本需要长时间阅读和手动编辑。 |
| 场景块 | 保留 | 场景标题、地点、时间、动作、对白需要结构区分。 |
| 连续行号 | 删除 | 会让用户误以为是代码块。 |
| 每行 pin / 更多按钮 | 降级 | 第一版不需要每个段落都有强操作；可在场景或选区层级出现。 |
| 分集目录 / Episode Outline | 必须补充 | 方向 1 缺失该模块。最终剧本和分集卡都需要快速定位。 |
| 底部字数 / 场景数 / 时长 / 最后编辑 | 保留 | 对编剧和内容生产有用。 |
| 缩放 / 大纲入口 | 条件保留 | 最终剧本编辑有用；过程产物可隐藏。 |

### 分集目录位置

推荐放在中间内容区内部：

```text
Center
  Header
  Tabs / Toolbar
  Body
    EpisodeOutlineRail
    DocumentCanvas
```

规则：
- 不放在右侧 Agent。
- 不替代左侧项目目录。
- 只负责定位，不负责流程推进。
- 窄屏可折叠成下拉或抽屉。

## 右侧 Agent

| 模块 | 处理 | 原因 |
|---|---|---|
| Agent 标题 / 思考中状态 | 保留 | 告诉用户 Agent 当前是否在工作。 |
| Agent 普通消息 | 保留 | 闲聊、解释、流程说明都从这里出现。 |
| TaskStepList | 保留但条件显示 | 只在 run 进行中或刚完成时展示；闲聊不展示。 |
| 审批卡 | 保留 | 必须嵌在对话流里，是继续下游生成的用户动作入口。 |
| 局部修改 SuggestionPatchCard | 新增 | 吸收方向 3 的关键能力，用户确认后才写入正文。 |
| 完成摘要卡 | 条件显示 | run 完成后可出现，不能替代剧本正文。 |
| 附件 chip | 新增 / 强化 | 文件名不进 textarea，附件在 composer 上方显示。 |
| ReferenceChip | 保留 / 强化 | 选中文本后要明确告诉用户 Agent 将修改哪一段。 |
| Composer | 保留 | 右侧是唯一 AI 指令入口。 |
| source mode 下拉 | 条件显示 | 未开始时可显示；项目已识别 source_mode 后应降级或隐藏。 |

### 右侧重复信息处理

- TaskStepList 和左侧整体进度不冲突：右侧是步骤，左侧是项目级进度。
- 审批卡和左侧“待确认”不冲突：左侧提示状态，右侧承载动作。
- Agent 完成摘要和中间剧本不冲突：摘要说明结果，正文仍在中间。
- 运行记录和右侧事件摘要不冲突：右侧只展示人话摘要，完整 payload 去运行记录。

## 必删或降级项

这些不应进入第一版定稿：

- 中间区域的 AI 生成 / 改写 / 版本对比按钮。
- 正文连续行号。
- 代码编辑器式 gutter。
- 每个段落默认显示强操作按钮。
- 同时展开小说链和非小说链完整目录。
- 文件名进入 textarea。
- 审批卡脱离对话流。
- 右侧把每个低级 run_event 都刷成消息卡。
- 未生成 scripts 前强亮“导出”。

## 下一步定稿依据

高保真稿应基于方向 1，但按本文取舍：

1. 保留方向 1 的顶栏、左侧、中心、右侧布局。
2. 删除正文行号。
3. 中间补分集目录。
4. 右侧补 SuggestionPatchCard。
5. composer 上方强化 AttachmentChip 和 ReferenceChip。
6. 对条件模块做状态化显示，不把所有模块同时堆在一个屏幕里。
