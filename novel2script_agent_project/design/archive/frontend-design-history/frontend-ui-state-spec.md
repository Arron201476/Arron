# 前端 UI 多状态规格

本文档定义 Novel2Script Agent 前端高保真状态稿需要覆盖的页面状态。它承接 `frontend-interaction-audit.md`、`frontend-component-language.md`、`agent-behavior-contract.md`、`api-event-contract.md` 和 `acceptance-test-contract.md`。

当前主入口为 `frontend-ui-state-gallery.html`。该文件是 UI/UE 定稿候选，不是前端实现代码。

## 总原则

1. 左侧是项目工作区目录，不是流程按钮面板。
2. 中间是当前 artifact、当前剧本或当前主内容，不放 AI 指令按钮。
3. 右侧 Agent 是用户需求、审批、补充说明、执行反馈的主入口。
4. 每个状态必须明确用户能做什么、不能做什么。
5. UI 稿不展示裸 JSON；结构化产物用字段化内容展示。
6. 只有当前链路相关目录展开：小说链不展示非小说产物，非小说链不展示小说产物。
7. 确认卡、局部修改建议、任务步骤都嵌入 Agent 消息流。
8. 剧本正文编辑器不能像代码编辑器：不显示连续行号、代码 gutter、等宽代码块背景或代码 diff 行号。
9. 多状态稿用于指导 TypeScript 前端实现，不是营销页面。
10. 按钮文案默认水平、垂直居中；菜单项、列表项、表格行、树节点等明确左对齐控件除外。
11. 分集卡阶段主区默认用一集一张卡展示关键字段；剧本正文阶段才强制使用 Word-like 正文编辑器和分集目录。
12. 组件源头先自测，再回填状态页；不能只在单个 frame 上修补视觉问题。

## 当前状态清单

### 01. 空项目 / 等待输入

触发：
- 新项目尚未添加文本、文件或生成指令。

左侧：
- 项目工作区显示项目名。
- 输入材料：待添加。
- 过程产物：待生成。
- 剧本：待生成。
- 运行记录：0。

中间：
- 显示轻量空态，说明可以添加原文、梗概、灵感或本地文件。
- 不展示不存在的故事圣经、素材库、分集卡。

右侧：
- Agent 欢迎语。
- 输入框。
- 附件入口。

禁止：
- 不显示分集卡确认卡。
- 不显示生成进度。
- 不同时展开小说链和非小说链。

### 02. 上传文件后

触发：
- 用户添加本地文件，但尚未发送生成指令。

左侧：
- 输入材料显示已添加。
- 其他过程产物仍为待生成。

中间：
- 展示文件名、大小、解析状态、文本预览和下一步提示。

右侧：
- composer 上方显示附件 chip。
- textarea 不插入文件名。
- Agent 提示用户说明如何使用这些文件。

禁止：
- 上传文件不自动创建 run。
- 上传文件不自动进入模型上下文，必须随消息或明确生成请求一起提交。

### 03. 普通聊天

触发：
- 用户输入“你好”“？”“你能做什么”等闲聊或咨询。

左侧：
- 保持当前项目目录，不推进流程。

中间：
- 保持空项目或当前内容。

右侧：
- 用户消息和 Agent 普通回复。
- 不出现 task list。
- 不出现 approval card。

禁止：
- 不创建 run。
- 不生成 artifact。
- 不误判成短剧生成流程。

### 04. 开始运行 / 路径已选择

触发：
- 用户明确表达生成、改编或局部修改意图，Main Agent 已选择小说链、非小说链或局部修改路径，并开始创建 run。

左侧：
- 输入材料显示已添加。
- 只显示当前路径真实会产生的 artifact。
- 当前第一个可见产物显示生成中，例如小说链的故事圣经，或非小说链的素材库。
- 运行记录显示 1 条或少量用户可理解的启动事件。

中间：
- 展示输入已保存、第一个可见产物生成中，以及后续产物顺序。
- 不展示分集卡或剧本内容。
- 不展示“意图识别结果”或内部路由字段。

右侧：
- Agent 用人话说明将按哪条路径处理，以及马上会生成什么。
- 低权重展示“理解请求、保存输入、整理素材库 / 生成故事圣经”等用户可理解步骤。

禁止：
- 不直接跳到剧本。
- 不展示“意图识别完成”“intent_detected”“router_decided”等内部状态。
- 不在左侧新增“意图识别”目录项。

### 05A. 小说链运行中

触发：
- 用户明确要求把小说原文改编成短剧。

左侧：
- 展开小说链：输入材料、故事圣经、原文拆集、分集卡、剧本、运行记录。
- 当前步骤显示生成中或待确认。
- 非小说链产物不显示。

中间：
- 展示当前正在生成或已生成的小说链 artifact。
- 小说链到分集卡阶段时，主区默认按集展示分集卡；进入剧本视图后必须出现分集目录。
- 未完成内容使用 skeleton 或局部结果，不显示空白框。

右侧：
- Agent 说明小说链执行顺序。
- 低权重展示故事圣经、原文拆集、分集卡等任务步骤。
- 用户可补充说明或暂停。

禁止：
- 不把内部事件刷成满屏卡片。
- 不在中间放继续生成按钮。

### 05B. 非小说链运行中

触发：
- 用户明确要求根据灵感、梗概、设定或素材生成短剧。

左侧：
- 展开非小说链：输入材料、素材库、故事种子、剧集蓝图、分集卡、剧本、运行记录。
- 当前步骤显示生成中。
- 小说链产物不显示。

中间：
- 展示当前正在生成或已生成的非小说链 artifact。
- 结构化内容以字段卡片呈现，不展示 JSON。

右侧：
- Agent 说明非小说链顺序。
- 任务步骤展示“理解请求、整理素材库、提炼故事种子、规划剧集蓝图”等。

禁止：
- 不把“故事圣经 / 原文拆集”放进非小说链目录。

### 06. 等待确认

触发：
- 到达分集卡、拆集、整集重生成、上游高影响修改等 checkpoint。

左侧：
- 当前 artifact 显示待确认。
- 下游 artifact 显示待生成或已失效。

中间：
- 展示需要确认的 artifact。
- 顶部显示待确认状态。
- 分集卡视图必须能一集一集读懂：可以使用轻量分集卡列表；若使用分集目录，目录样式必须和剧本编辑器一致。

右侧：
- Agent 消息内嵌 ApprovalCard。
- ApprovalCard 说明确认原因、影响范围、确认继续、暂停处理。
- 用户可以在输入框补充修改要求。

禁止：
- 审批卡不脱离对话流。
- 补充要求不创建新的 run，除非用户明确要求新任务。

### 07. 剧本编辑态

触发：
- scripts 已生成，用户正在查看或编辑剧本。

左侧：
- 当前选中剧本。
- 可切换到输入材料、过程产物、分集卡、运行记录。

中间：
- Word 类正文编辑器，正式底座为 Lexical。
- 有正文类型、字体、字号、加粗、斜体、下划线、删除线、批注、查找等基础工具。
- 按集、场景、动作、对白、转场分层展示。
- 有分集目录。
- 工具栏只属于正文编辑器，必须与正文纸面的左边界和宽度对齐；分集目录是独立定位模块，不放在工具栏下面，也不进入工具栏宽度计算。
- 正文视觉是文档纸面，不使用多层场景卡片、代码行号或代码 gutter。

右侧：
- Agent 说明可继续做局部修改、声口检查、节奏检查或导出前检查。
- 用户选中文本后，composer 显示引用 chip。

禁止：
- 不显示连续行号。
- 不使用代码编辑器 gutter。
- 不把正文做成单个 textarea。

### 08. 局部修改建议

触发：
- 用户选中文本或指定 artifact 节点后提出修改。

左侧：
- 当前 artifact 保持高亮。
- 如果修改会影响下游，相关下游显示待更新或已失效。

中间：
- 在正文内高亮选区，选区不能遮挡文本，也不能做成独立按钮。
- 标记选区来源：episode、scene、文本范围或 artifact 节点。

右侧：
- Agent 说明修改范围。
- 建议修改卡展示原句和候选句。
- 用户接受后才写入正文；拒绝后保留原文。
- 高影响修改请求 approval。

禁止：
- 不用代码 diff 行号主导视觉。
- 不只传 selected_text，必须带前后文和 artifact 来源。

### 09. 完成 / 导出前

触发：
- scripts 生成完成并保存。

左侧：
- 剧本显示已完成。
- 过程产物显示已生成或已确认。
- 运行记录显示完整事件数。

中间：
- 默认展示剧本或完成摘要。
- 仍可进入剧本编辑器。
- 导出只是次级动作，不压过继续编辑。

右侧：
- Agent 完成摘要。
- 说明可继续局部修改、单集调整、质量复核或导出。

禁止：
- 不把完成态做成营销成功页。
- 不隐藏可继续编辑入口。

### 10. 错误 / 可重试

触发：
- 模型调用失败、schema 校验失败、文件解析失败、网络失败等。

左侧：
- 当前步骤显示失败。
- 已生成 artifact 保留。

中间：
- 保持最后可用 artifact。
- 当前失败步骤给出错误空态和恢复路径。

右侧：
- Agent 错误卡说明人话原因。
- 提供重试当前步骤、分集生成、暂停处理等恢复路径。
- 技术 payload 折叠到运行记录。

禁止：
- 不展示 raw stack trace。
- 不清空已生成产物。
- 不让用户误以为项目已经损坏。

## 多状态 HTML 稿要求

`frontend-ui-state-gallery.html` 必须：

1. 以状态为导航，而不是以组件为导航。
2. 每个状态都是完整三栏，不是局部截图。
3. 同一组件在不同状态保持一致命名、密度和视觉语言。
4. 采用方向 1 的左侧、中间、右侧工作台结构。
5. 吸收方向 3 的附件 chip 和 Agent 内嵌局部修改确认卡。
6. 避免临时符号、emoji 图标和代码编辑器视觉。
7. `frontend-visual-mock.html` 只作为历史参考，不再作为最终 UI 稿主入口。
