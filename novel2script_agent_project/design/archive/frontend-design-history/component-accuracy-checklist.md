# 组件准确性检查表

本文档是进入 Figma 重建前的组件准入标准。后续规则固定为：先组件，后 frame。任何 frame 不能用散件硬摆，也不能用尚未验收通过的组件拼装。

## 0. 组件先行硬规则

| 检查项 | 必须满足 | 禁止出现 |
| --- | --- | --- |
| 构建顺序 | 先完成基础组件、工作台组件、Agent 组件、编辑器组件，再开始状态 frame。 | 直接在 frame 里手画按钮、chip、卡片、输入框。 |
| 对齐方式 | 按钮、icon、chip、toolbar、composer action 必须由组件约束保证居中。 | 靠手动拖坐标做视觉居中。 |
| 组件来源 | frame 只能使用已验收组件实例。 | 同一种 UI 在多个 frame 中各画一遍。 |
| 文案来源 | 组件只承载固定 UI 文案；状态文案由 frame 规格传入。 | 组件内写死小说名、项目名、自动保存等 mock 信息。 |
| 图标 | 未确定图标库前宁可留空或用明确几何图标。 | 用正方形占位、文本符号假装图标、未居中图标。 |
| 右侧 Agent | 确认卡、修改建议、报错、任务进度都必须嵌在聊天流里。 | 卡片漂在聊天流外，或和对话记录分离。 |
| 中间编辑区 | 过程产物用结构化编辑器；最终剧本用 Word 式正文编辑器。 | 用裸 JSON、代码块、行号、厚重场景卡片替代正文编辑器。 |
| 上传文件 | 附件在发送前只出现在 composer 待发送区。 | 选择文件后自动进入聊天记录或运行记录。 |
| 进度 | 只有定义清楚计算口径才展示进度。 | 完成态还显示 78% 之类进度。 |

进度条默认不作为必备组件。只有同时满足以下条件才允许进入 frame：

- 能从 run_state / step_status 计算清楚进度。
- 完成态能明确显示 100% 或直接移除进度条。
- 不会和左侧产物状态重复表达。

## 1. 基础组件

### 1.1 Button

| 项 | 标准 |
| --- | --- |
| 用途 | 所有明确命令：发送、确认继续、暂停、接受修改、拒绝修改、重试。 |
| variants | primary / secondary / ghost / danger / disabled / loading。 |
| 尺寸 | 同一组按钮高度一致；主次按钮基线一致。 |
| 对齐 | 文案默认水平、垂直居中。除菜单项、列表项、表格行外，不允许左对齐。 |
| 文案 | `发送`，不写 `发送给 Agent`。确认类用 `确认继续` 或 `确认并开始生成`。 |
| 禁止 | 文案贴边、上下不居中、同一按钮组高度不一致、按钮内换行。 |

### 1.2 IconButton

| 项 | 标准 |
| --- | --- |
| 用途 | 上传、关闭、更多、折叠、撤回等轻量操作。 |
| 图形 | 使用图标节点、矢量节点或几何线段。上传入口使用几何 `+`。 |
| 对齐 | 图形中心必须与点击区域中心重合。 |
| 可访问性 | 必须有 tooltip / aria-label 语义。 |
| 禁止 | 用文本 `+`、`x`、`...` 假装图标；图标偏上、偏下、贴边、被裁切。 |

### 1.3 Chip

| 项 | 标准 |
| --- | --- |
| 用途 | 附件、引用、版本、保存状态、来源提示。 |
| 结构 | optional icon/dot + label + optional close。 |
| 对齐 | 圆点、文字、关闭按钮必须垂直居中。 |
| 溢出 | 长文件名截断，保留 tooltip。 |
| 禁止 | 文件名进入 textarea；chip 文字溢出；关闭按钮贴边；圆点不居中。 |

### 1.4 StatusBadge

| 项 | 标准 |
| --- | --- |
| 状态 | 待输入、待发送、已保存、识别中、待生成、生成中、已生成、待确认、已确认、修改中、失败、可能需刷新。 |
| 语义 | `已确认` 只能来自用户真实确认。 |
| 颜色 | pending 使用灰；running 使用蓝；approval 使用琥珀；generated/confirmed 使用低权重青绿；failed 使用红。 |
| 禁止 | 用绿色勾替代状态文字；未确认产物显示已确认；完成态继续显示生成中。 |

## 2. 工作台组件

### 2.1 AppHeader

| 项 | 标准 |
| --- | --- |
| 内容 | 只保留产品名和必要全局入口。 |
| 禁止 | 小说名、项目名、小说改编、自动保存时间、模型名、prompt 调试入口。 |

### 2.2 SidebarNav

| 状态 | 必须展示 |
| --- | --- |
| 识别前 | 输入材料、过程产物、剧本、运行记录。 |
| 小说线 | 输入材料、故事圣经、原文拆集、分集卡、剧本、运行记录。 |
| 非小说线 | 输入材料、素材库、故事种子、剧集蓝图、分集卡、剧本、运行记录。 |

规则：

- 当前选中项必须驱动中间标题。
- 点击运行记录只切换中间到运行记录，不改变产物状态。
- 识别前不能出现故事圣经、原文拆集、素材库、故事种子、剧集蓝图、分集卡。
- 小说线不能出现素材库、故事种子、剧集蓝图。
- 非小说线不能出现故事圣经、原文拆集。
- 未配置图标前不使用正方形占位。

### 2.3 ArtifactEditor

| 产物 | 表达方式 |
| --- | --- |
| 输入材料 | 文本/附件摘要，可编辑、可删除、可补充。 |
| 故事圣经 | 结构化字段：主线、人物、关系、世界设定、核心冲突、来源引用。 |
| 原文拆集 | 集数列表、原文章节/段落归属、拆分理由。 |
| 素材库 | 素材条目、人物、冲突、卖点、可用片段。 |
| 故事种子 | 主角、目标、阻碍、核心爽点、可选方向。 |
| 剧集蓝图 | 阶段结构、反转、人物推进、节奏提示。 |
| 分集卡 | 一集一张卡，含核心冲突、人物状态、尾钩、来源提示。 |

规则：

- 每一步生成完都可手动编辑。
- 每一步生成完都可在右侧向 AI 提问或请求修改。
- 编辑上游产物后，下游显示可能需刷新，不自动重跑。
- 过程产物不使用最终剧本的 Word 正文编辑器。

### 2.4 RunLog

| 项 | 标准 |
| --- | --- |
| 内容 | 简洁事件流：用户发送、识别结果、产物生成、确认、失败、重试。 |
| 展示时机 | 只有点击运行记录才显示。 |
| 禁止 | prompt、模型、内部 event payload、堆栈、过重过程细节。 |

## 3. Agent 组件

### 3.1 AgentPanel

| 区域 | 标准 |
| --- | --- |
| Header | 固定 `Agent 助手`，不展示内部状态名。 |
| MessageList | 所有聊天、任务、确认、修改建议、报错都在消息流内。 |
| Composer | 输入框、上传 `+`、待发送 chip、发送按钮。 |

禁止：

- 右侧无聊天记录却命名为普通闲聊。
- 确认卡和聊天记录分离。
- 报错、确认、建议卡脱离消息流。

### 3.2 MessageBubble

| role | 用途 |
| --- | --- |
| user | 用户文本、附件、引用。 |
| assistant | Agent 文本回复。 |
| assistant_with_tasks | Agent 文本 + TaskStepList。 |
| assistant_with_approval | Agent 文本 + ApprovalCard。 |
| assistant_with_patch | Agent 文本 + SuggestionPatchCard。 |
| assistant_error | Agent 报错与恢复建议。 |
| assistant_completion | Agent 完成摘要。 |

规则：

- 普通问答必须真实显示用户问题和 Agent 回复。
- 生成意图未确认前不产生运行记录。
- 暂停后补充说明是新的用户消息，不插回旧消息中间。

### 3.3 AgentComposer

| 项 | 标准 |
| --- | --- |
| 上传入口 | 左下角单个 `+` IconButton。 |
| 附件 | 发送前显示在 composer 内 chip row。 |
| 引用 | 选中文本后显示引用 chip，不进入 textarea。 |
| 发送 | 按钮文案 `发送`，右下对齐但保留安全边距。 |
| 键盘 | Enter 发送，Shift+Enter 换行。 |

禁止：

- 附件文字写进输入框。
- 只选择文件就出现在聊天记录。
- 发送按钮贴边、被裁切、文案不居中。

### 3.4 TaskStepList

| 项 | 标准 |
| --- | --- |
| 内容 | 用户可理解的步骤名，如理解原文、生成故事圣经、规划分集卡。 |
| 粒度 | 只展示当前任务相关步骤。 |
| 禁止 | 暴露 prompt、模型、router、runner、内部 event 名。 |

### 3.5 ApprovalCard

| 项 | 标准 |
| --- | --- |
| 位置 | 嵌在右侧 Agent 消息流内。 |
| 触发 | 进入下一大步前，例如故事圣经后生成原文拆集、分集卡后生成剧本。 |
| 按钮 | 确认继续 / 暂停或补充说明。 |
| 禁止 | 用户未确认就推进下一步；确认卡漂浮在消息流外。 |

### 3.6 SuggestionPatchCard

| 项 | 标准 |
| --- | --- |
| 位置 | 嵌在右侧 Agent 消息流内。 |
| 内容 | 修改范围、原句、建议句、接受修改、拒绝修改。 |
| 文本 | 删除/新增内容自动换行，不溢出色块。 |
| 禁止 | 在中间编辑区放修改指令输入浮层；建议卡脱离聊天。 |

### 3.7 ErrorCard

| 项 | 标准 |
| --- | --- |
| 位置 | 只在右侧 Agent 显示。 |
| 内容 | 失败说明、重试、补充说明。 |
| 中间 | 保持当前产物可查看，不做报错大屏。 |
| 禁止 | 暴露内部堆栈、模型 endpoint、原始异常。 |

### 3.8 CompletionCard

| 项 | 标准 |
| --- | --- |
| 位置 | 嵌在右侧 Agent 消息流内。 |
| 内容 | 当前步骤完成摘要、下一步可做什么、是否可继续修改。 |
| 使用场景 | 故事圣经已生成、分集卡已生成、剧本初稿完成等完成态。 |
| 禁止 | 完成态仍显示生成中任务或未完成进度；脱离聊天流单独漂浮。 |

## 4. 编辑器组件

### 4.1 ScriptEditor

| 项 | 标准 |
| --- | --- |
| 用途 | 只用于最终剧本。 |
| 视觉 | Word 式正文编辑器。 |
| 工具栏 | 只属于正文编辑器，宽度和正文画布对齐。 |
| 分集目录 | 位于编辑器左侧，和工具栏不是同一模块。 |
| 禁止 | 代码行号、代码 gutter、每个场景厚重卡片、工具栏跨到目录上方。 |

### 4.2 ScriptEditorToolbar

| 项 | 标准 |
| --- | --- |
| 内容 | 撤销、重做、正文、B、I、U、S、批注、查找等基础 Word 操作。 |
| 对齐 | 与 ScriptDocumentCanvas 对齐，不包含分集目录宽度。 |
| 禁止 | AI 生成、AI 改写、版本对比等按钮放在中间工具栏。 |

### 4.3 ScriptDocumentCanvas

| 项 | 标准 |
| --- | --- |
| 内容 | 集标题、场景标题、动作、对白、转场。 |
| 选区 | 选中文本只高亮正文，不另放中间指令框。 |
| 修改 | 用户到右侧 Agent 输入修改要求。 |
| 禁止 | 选区提示遮挡正文；正文和右侧 Agent 贴边。 |

## 5. 组件页验收

每个组件页进入 frame 前必须回答：

1. 组件是否有明确用途和禁止用法？
2. 组件是否通过约束保证上下左右居中？
3. 组件是否有足够状态 variants？
4. 组件是否没有项目名、小说名、自动保存等 mock 文案？
5. 组件是否能被 frame 复用，而不是只能服务某一张静态图？
6. 组件截图里是否有溢出、贴边、裁切、错位？
7. 组件是否符合“右侧 Agent 是唯一 AI 指令入口”？
8. 组件是否支持“生成后可手动编辑，也可向 AI 修改”？
9. 组件是否支持小说线和非小说线分流，不混用节点？
10. 组件未通过时，禁止进入 frame 重建。
