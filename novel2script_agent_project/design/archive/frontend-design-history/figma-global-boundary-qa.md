# Figma 全局边界 QA

> 2026-06-29 当前有效结论：本轮 QA 已覆盖 `02-05` 组件页和 `06 State Frames` 的 29 张中文状态 frame。旧文档中的历史状态帧数量不再作为当前交付范围。

## 当前阶段

UI 定稿前的全局复验。目标不是继续点修截图问题，而是确认组件页和状态帧可以作为前端开发依据。

## QA 门槛

### 1. 组件先于状态帧

- 先修 `02 Components`、`03 Workbench Components`、`04 Agent Components`、`05 Script Editor Components`。
- `06 State Frames` 只能使用已通过 QA 的组件结构，不能在 frame 里临时拼散件。
- 如果源组件失败，依赖它的状态帧自动失败。

### 2. 双轴居中

- 所有按钮文案默认水平、垂直居中。
- 所有 icon-only 控件的 icon 必须水平、垂直居中。
- 选中、禁用、悬停等状态不能改变控件外框尺寸，不能造成相邻元素位移。
- icon-only 控件使用几何线段或图标节点，不用文本符号模拟。

### 3. 边界与裁切

- 任何页面、组件、状态帧不得出现内容越界、被裁切、贴边、压线、覆盖。
- 右侧 Agent 面板必须保持清晰边界：顶部标题、聊天流、嵌入式卡片、底部输入区各自有安全间距。
- 输入区不得被卡片挤压或裁切。

### 4. 模块归属

- 左侧项目导航、分集目录、编辑器工具栏、正文编辑器、右侧 Agent 是不同模块。
- 编辑器工具栏只属于正文编辑器，宽度与正文编辑器对齐。
- 分集目录不放在编辑器工具栏下面，也不混入正文编辑器组件。

### 5. 用户可见逻辑

- 不向用户暴露内部意图识别、模型控制、prompt 调度、内部错误栈等内部步骤。
- 运行过程只展示用户能理解的任务动作，例如“理解需求”“整理素材”“规划分集”“生成剧本”。
- 确认卡片、局部修改建议必须嵌在对话流中，而不是漂浮在聊天外。

### 6. 写作产品适配

- 最终剧本区域是 Word-like 正文编辑器，不是代码编辑器。
- 剧本视图需要分集目录；分集卡阶段要么使用同类目录，要么展示一集一集的卡片，不混用不清楚的中间态。
- 中间内容区只承载内容查看和编辑，不放 AI 执行动作按钮；AI 动作由右侧 Agent 承载。

### 7. 开发交接

- 组件页必须清楚展示源组件、状态和使用说明，不能散乱堆放。
- 状态帧必须覆盖关键状态：空项目、添加文件、闲聊、启动运行、小说运行、非小说运行、等待确认、剧本编辑、局部修改、完成、错误重试。
- 每页/每帧都要截图复验，截图发现的问题必须先回到源组件修复。

## 已修正的关键问题

- 空项目状态不再显示旧项目名。
- 空项目、闲聊、运行态的 Composer 不再错误显示“引用：第 3 集”。
- 分集卡等待确认状态改为原始卡片尺寸的两列布局，不再压缩卡片导致文字溢出。
- 编辑状态中的正文实例已替换为新实例，不再出现文字被拉散或状态帧被撑高。
- 错误状态只展示可恢复建议，不展示内部报错信息。
- 组件页和状态帧已做结构审计：`03-06` 无禁用内部词命中，无父子越界样本。

## 当前结论

Figma 组件页和状态帧已达到进入前端实现计划确认的门槛。下一步不是继续改视觉细节，而是把 Figma 组件树落成 React 组件树、API view model 和 Playwright 视觉回归计划。
