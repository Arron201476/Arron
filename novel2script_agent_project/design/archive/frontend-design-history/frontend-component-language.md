# Novel2Script 前端组件语义与文案规范

本文档约束 Novel2Script Agent 前端的组件语义、状态命名和按钮文案。目标是避免把工作台做成临时拼装的后台页面。

## 基本原则

1. 中间区域承载内容，不承载 AI 指令入口。
2. 右侧 Agent 承载用户需求、审批、补充说明、执行反馈。
3. 左侧目录承载项目结构和 artifact 状态，不承载任务按钮。
4. 组件文案描述用户动作，不描述系统对象。例如用“发送”，不用“发送给 Agent”。
5. 图标必须表达状态或动作，不能为了装饰重复出现。
6. 视觉强度只给真正需要用户注意的东西：审批、失败、当前执行、主输入。

## 状态命名

产物状态只允许：

| 状态 | 使用场景 | 不要混用为 |
|---|---|---|
| 待添加 | 输入材料尚未提供 | 待生成 |
| 待生成 | artifact 尚未生成 | 待确认 |
| 生成中 | 当前 run 正在生成该 artifact | 已确认 |
| 待确认 | 需要用户批准或补充后才能继续 | 已生成 |
| 已生成 | artifact 已生成但未必被用户确认 | 已确认 |
| 已失效 | 上游变更导致下游不可直接复用 | 失败 |
| 失败 | 当前步骤执行失败 | 已失效 |

`已确认` 只能在存在明确用户确认动作时使用。没有确认动作的产物不能显示为已确认。

## Button

### 组件命名

实现时使用统一组件：

```text
Button
ButtonIcon
ButtonGroup
```

### Variant

| variant | 使用场景 |
|---|---|
| primary | 当前上下文唯一主操作 |
| secondary | 次要但明确的动作 |
| ghost | 轻量工具动作，例如复制、折叠 |
| danger | 删除、取消 run、覆盖高影响产物 |

### Size

| size | 使用场景 |
|---|---|
| sm | 辅助面板、审批卡次级动作 |
| md | 表单、对话输入、普通操作 |
| icon | 只有图标的工具按钮，必须有 aria-label / tooltip |

### 文案规则

- 用动词或动宾短语：发送、确认继续、暂停、重试、添加文件。
- 不写系统接收者：不要写“发送给 Agent”。
- 不写内部流程：不要写“POST run”“调用 runner”。
- 按钮文案默认水平、垂直居中；只有菜单项、列表项、表格行、树节点等明确左对齐控件例外。
- 组件实现必须由布局约束保证居中，不能靠单独调文本坐标。Button、IconButton、Chip、ToolbarButton 都应有固定高度、明确 padding 和 center 对齐。
- IconButton 必须使用图标节点、SVG 或矢量几何；不使用 `+`、`×`、`…` 这类文本符号模拟图标。图形必须在命中区内上下左右居中。
- 主按钮不允许自动换行。
- 同一区域只允许一个 primary。
- 等待确认时，确认动作在审批卡里；输入框发送按钮仍叫“发送”。

### 禁止示例

| 禁止文案 | 原因 | 建议 |
|---|---|---|
| 发送给 Agent | 重复区域语义，按钮过长 | 发送 |
| 自动识别 | 如果只是模式，不是动作，不应做成按钮 | 模式：自动识别 |
| 继续流程 | 太抽象 | 确认继续 |
| 生成 | 不说明对象且容易误触 | 生成剧本 / 生成分集卡，但应由 Agent 审批卡承载 |

## Agent 输入框

输入框由四个部分组成：

1. 可选附件 chip。
2. 当前引用上下文 chip，例如“引用：第 1 集 Scene 02”。
3. 文本输入框。
4. 底部工具行。

底部工具行规则：

- 左侧只放 `+` 图标按钮，作为添加文件 / 引用选区的统一入口；引用上下文用 chip 展示，不再单独放“引”按钮，也不要把“添加文件 / 引用选区”写成一段长文本。
- 右侧只放发送按钮。
- `Enter 发送 · Shift Enter 换行` 是提示文案，不是按钮。
- 文件名显示在附件 chip，不插入 textarea 文本。
- 等待确认时，用户在输入框输入的是补充说明，不自动创建新 run。
- 发送按钮必须在输入区容器内保留安全边距，文案水平、垂直居中。
- 输入框底部动作区必须是独立 action row；`+` 和“发送”都在该行中上下左右居中，不允许覆盖 textarea、贴边或被父容器裁切。

## TaskStepList

TaskStepList 只展示 Agent 内部执行过程，不能长得像可点击按钮。

### 状态

| 状态 | 显示 |
|---|---|
| pending | 浅灰点 + 步骤名 |
| running | 小 spinner + 正在... |
| done | 低权重“已完成”文本或浅色点 |
| failed | 错误色文本 + 可重试入口 |

### 图标规则

- 不给每个 done 步骤显示绿色圈勾。
- 绿色勾只用于用户已完成的确认、成功提交、导出完成等强成功事件。
- 内部步骤完成不是用户确认，不使用确认图标。
- TaskStepList 不显示边框按钮样式，不使用 hover pointer。

## ApprovalCard

ApprovalCard 是真正需要用户动作的组件，必须嵌在 Agent 对话流里。

必备字段：

- 标题
- 为什么需要确认
- 继续后影响哪些产物
- 主操作：确认继续
- 次操作：补充要求、暂停、重生成这一步

审批卡可以使用更高视觉权重，但不能脱离对话流单独浮在侧边栏。

## ArtifactContent

中间内容区域根据 artifact 类型切换展示：

| artifact | 展示形态 |
|---|---|
| source_input | 原文 / 素材编辑器 |
| story_bible | 结构化字段文档 |
| episode_split | 分集边界列表 |
| material_bank | 素材分组 |
| story_seed | 方向卡 |
| series_blueprint | 阶段地图 |
| episode_cards | 分集卡列表；默认一集一张卡，字段格式化展示 |
| scripts | 剧本编辑器 |

ArtifactContent 可以有基础编辑状态，例如已保存草稿、未保存、已失效，但不能放 AI 操作按钮。

分集卡内容区规则：

- 分集卡阶段不使用剧本正文编辑器。
- 默认按集展示卡片，每张卡包含集数、标题、核心冲突、尾钩、人物状态和可编辑字段提示。
- 如果需要目录，目录样式必须和剧本编辑器的分集目录一致；不能在同一视图里混用两个不同目录体系。
- 不展示裸 JSON，也不只放“故事圣经 / 分集卡”两个抽象入口。

## Copy Checklist

每次新增按钮或状态文案前检查：

- 用户看得懂这个动作会发生什么吗？
- 这个动作应该在中间、左侧，还是右侧 Agent？
- 文案是否超过 6 个中文字符仍需要做成主按钮？
- 它是不是把系统对象写进了文案？
- 它的状态图标是否和用户确认混淆？
- 它是否看起来可点击但实际不可点击？
