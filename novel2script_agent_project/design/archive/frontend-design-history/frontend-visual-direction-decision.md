# 前端视觉方向选择记录

本文档记录 UI/UE 定稿前的视觉方向选择。它不是最终 UI 稿，但会约束下一轮高保真稿和后续 React 实现。

方向 1 的具体模块取舍见 `frontend-direction1-module-audit.md`。方向 1 是视觉基准，不代表其中每个模块都进入第一版实现。

## 当前选择

基础方向采用视觉方向 1：`Quiet Manuscript Desk`。

注意：后续生成的“修正版方向图”如果改变了方向 1 的顶栏、左侧目录、中间编辑器、右侧 Agent 的基本结构，不作为定稿依据。当前以用户截图中的方向 1 为视觉基准，只做局部增强，不重新解释整体布局。

保留方向 1 的：
- 顶栏结构：产品标识、项目名、模式标签、自动保存状态、项目设置、导出、用户/助手入口。
- 左侧目录结构和安静的项目导航感。
- 左侧项目卡、创作流程、整体进度、收起侧栏等工作台元素。
- 中间内容区的文档编辑器气质。
- 中间顶部的 artifact 标题、状态、结构视图 / 脚本视图切换。
- 中间 Word-like 工具栏和文档页编辑器布局。
- 右侧 Agent 对话区的整体布局。
- 右侧 Agent 任务步骤卡：理解请求、识别意图、检索素材与记忆、生成脚本草稿、质量检查、等待用户确认。
- 审批卡在右侧对话流内。
- composer 固定在右下，附件 chip 在 composer 上方。
- 低装饰、低阴影、轻边框、高可读性的工作台风格。

吸收方向 3 的：
- 右侧局部修改后的 suggestion patch 确认能力。
- 选区引用后，Agent 在对话里展示“建议修改 / 接受修改 / 拒绝修改”。
- 本地文件上传的 `AttachmentChip` 样式：文件类型图标、文件名、大小、移除按钮。

必须补齐方向 1 缺失的：
- 分集目录 / Episode Outline。
- 剧本正文编辑器禁止显示代码式行号。

## 关于分集目录

方向 1 里没有分集目录是视觉生成遗漏，不是产品规则。

正式规则：
- 当当前内容是最终剧本或分集卡时，中间区必须提供分集目录。
- 分集目录可以位于中间内容区左侧的轻量 rail，也可以作为剧本文档内部的 sticky outline。
- 分集目录不放在右侧 Agent 内。
- 分集目录不承担流程推进，只负责定位和浏览。
- 分集目录项显示：集数、标题/一句话摘要、状态、当前选中态。
- 场景目录可以作为第二层折叠，但第一版不强制展开所有场景，避免左侧和中间都过重。

推荐布局：

```text
Center
  ArtifactHeader / ScriptToolbar
  ContentBody
    EpisodeOutlineRail
    ScriptDocumentCanvas
```

## 关于正文编辑器行号

剧本正文编辑器不能像代码编辑器。

禁止：
- 连续行号。
- 代码块式等宽字体正文。
- 代码编辑器 gutter。
- 代码高亮式背景。
- 把 `line_id`、`scene_id`、`episode_id` 直接展示给用户。

允许：
- 集标题。
- 场景标题。
- 动作、对白、转场的块样式差异。
- 选区高亮。
- 批注标记。
- 轻量段落锚点或“第 2 集 / 第 3 场”定位标签。

数据层仍然保留 `line_id`、`scene_id`、`episode_id`，但只用于保存、选区定位、局部修改和 patch 合并，不直接暴露在正文视觉里。

## 关于局部修改确认

局部修改后需要用户确认，但确认位置必须在右侧 Agent 对话流里。

流程：

```text
用户选中文本
-> 中间正文出现选区高亮
-> 右侧 composer 上方出现 ReferenceChip
-> 用户输入修改要求
-> Agent 返回 suggestion patch
-> MessageBubble 内嵌 SuggestionPatchCard
-> 用户点击接受修改或拒绝修改
-> 接受后写入 ScriptEditor 并保存新 artifact version
```

SuggestionPatchCard 展示：
- 修改范围：例如“第 2 集 / 第 3 场 / 女主对白”。
- 删除内容：浅红底，不使用代码 diff 行号。
- 新增内容：浅绿或 primary-soft 底，不使用代码 diff 行号。
- 主按钮：接受修改。
- 次按钮：拒绝修改。

禁止：
- 直接覆盖正文。
- 把 patch 放到中间正文顶部当弹窗。
- 用代码 diff 的 `+ / -` 行号风格主导视觉。
- 让用户以为这是开发代码 review。

## 关于本地文件上传

采用方向 3 中更清楚的附件 chip 形态。

AttachmentChip 显示：
- 文件类型图标。
- 文件名。
- 文件大小。
- 解析状态。
- 移除按钮。

规则：
- 附件 chip 放在 Agent composer 上方。
- 文件名不进入 textarea。
- 上传文件不自动启动 run。
- 上传文件不自动进入模型上下文。
- 用户发送消息时，message 携带 `file_ids`。

## 下一轮高保真稿要求

下一轮只需要出一个修正版方向，不再三选一。

修正版必须包含：
- 方向 1 的整体左中右布局，不重排顶栏、左侧、中心、右侧的基本结构。
- 保留方向 1 的顶栏、左侧目录、整体进度、中心工具栏、右侧任务步骤卡和 composer 位置。
- 中间区分集目录。
- 中间区无代码式行号。
- 右侧本地文件 attachment chip。
- 右侧局部修改 suggestion patch confirmation。
- 审批卡仍嵌入 Agent 消息流。
- 中间没有生成、改写、版本对比等 AI 操作按钮。

修正版不得：
- 把方向 1 的整体界面替换成新的后台布局。
- 删除顶栏中的自动保存、项目设置、导出、用户/助手入口。
- 删除左侧整体进度。
- 删除右侧任务步骤卡。
- 把 suggestion patch 做成代码 review 风格。
- 让正文编辑器出现连续行号。
