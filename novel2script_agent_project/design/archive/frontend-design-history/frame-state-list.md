# Frame 状态清单

本文档定义进入 Figma 前必须绘制的 frame 清单。所有 frame 使用中文命名。每张图必须满足：左侧当前选中项 = 中间标题 = 中间内容所属产物，右侧 Agent 只展示当前状态相关的聊天、任务、确认、修改或报错。

## 0. 总体数量

| 分组 | 数量 | 说明 |
| --- | ---: | --- |
| 入口线 | 4 | 发送前不识别，识别前不分小说/非小说。 |
| 小说线 | 8 | 从识别为小说后开始。 |
| 非小说线 | 10 | 从识别为非小说后开始。 |
| 闲聊线 | 3 | 不改变流程状态。 |
| 通用线 | 4 | 运行记录、AI 修改、应用修改、报错重试。 |
| 合计 | 29 | Figma frame 重建目标数。 |

## 1. 入口线

### 入口线 01｜空项目

| 区域 | 规格 |
| --- | --- |
| 左侧 | 通用目录：输入材料、过程产物、剧本、运行记录。当前选中输入材料。所有产物待生成，运行记录 0。 |
| 中间 | 标题：输入材料。展示空输入区、上传入口、文本输入提示。 |
| 右侧 | Agent 空对话，只显示输入框和上传 `+`。 |
| 可编辑性 | 输入区可输入。 |
| AI 操作 | 可问 Agent 项目流程，但不会启动生成。 |
| 推进条件 | 用户输入文本或选择附件但未发送时进入 `入口线 02`；用户直接发送有效内容时进入 `入口线 03`。 |
| 禁止 | 小说/非小说目录、项目名、小说名、自动保存、聊天记录、运行记录。 |

### 入口线 02｜内容待发送

| 区域 | 规格 |
| --- | --- |
| 左侧 | 通用目录不变。所有产物仍待生成，运行记录 0。 |
| 中间 | 标题：输入材料。保持空态或待提交提示，不展示已保存附件列表。 |
| 右侧 | composer 内出现待发送文本/附件 chip；聊天记录不新增。 |
| 可编辑性 | 可删除附件、修改待发送文本。 |
| AI 操作 | 还未发送，Agent 不处理。 |
| 推进条件 | 用户点击发送后进入 `入口线 03`；用户取消则回到 `入口线 01`。 |
| 禁止 | 已添加文件、已保存文件、用户消息、Agent 回复、运行记录、任务进度；待发送内容不得同时在聊天记录中出现。 |

### 入口线 03｜内容已发送，识别中

| 区域 | 规格 |
| --- | --- |
| 左侧 | 输入材料已保存；过程产物识别中；剧本待生成。当前选中输入材料。 |
| 中间 | 标题：输入材料。展示已保存素材摘要、附件列表。 |
| 右侧 | 出现用户消息和附件；Agent 消息：正在判断输入类型。 |
| 可编辑性 | 输入材料可补充，补充后会重新识别。 |
| AI 操作 | 可问 Agent 是否素材足够。 |
| 推进条件 | 识别完成后进入 `入口线 04`。 |
| 禁止 | 故事圣经、素材库、分集卡、剧本、具体链路目录。 |

### 入口线 04｜识别结果待确认

| 区域 | 规格 |
| --- | --- |
| 左侧 | 通用目录保持。输入材料已保存；过程产物待生成或识别完成待确认。 |
| 中间 | 标题：输入材料。展示输入摘要和识别结果。 |
| 右侧 | Agent 识别结果确认卡：识别为小说 / 识别为非小说；允许用户改判。 |
| 可编辑性 | 输入材料仍可编辑。 |
| AI 操作 | 可追问为什么这样识别。 |
| 推进条件 | 用户确认小说后进入 `小说线 01`；确认非小说后进入 `非小说线 01`。 |
| 禁止 | 未确认就切目录、未确认就生成产物。 |

## 5. 通用线

### 通用 01｜运行记录

| 区域 | 规格 |
| --- | --- |
| 左侧 | 当前选中运行记录；其他产物状态保持真实状态。 |
| 中间 | 标题：运行记录。展示简洁事件流。 |
| 右侧 | 保持当前 Agent 聊天，不清空、不换任务。 |
| 可编辑性 | 运行记录只读。 |
| AI 操作 | 可问某条记录是什么意思。 |
| 推进条件 | 无。 |
| 禁止 | 过重内部步骤、prompt、模型日志、堆栈、改变产物状态。 |

### 通用 02｜AI 修改建议

| 区域 | 规格 |
| --- | --- |
| 左侧 | 当前选中真实产物，如故事圣经、分集卡、剧本。 |
| 中间 | 标题等于当前产物。显示选中文本或当前字段，高亮但不遮挡。 |
| 右侧 | 用户在 composer 输入修改要求；Agent 给出修改建议卡。 |
| 可编辑性 | 中间产物仍可查看；接受前不写入。 |
| AI 操作 | 生成修改建议。 |
| 推进条件 | 用户接受修改后进入 `通用 03`；拒绝后保持原状态。 |
| 禁止 | 中间额外输入修改要求、建议卡脱离聊天、文本溢出红/绿块。 |

### 通用 03｜应用修改后

| 区域 | 规格 |
| --- | --- |
| 左侧 | 当前产物可显示已修改；下游产物可显示可能需刷新。 |
| 中间 | 标题等于当前产物。展示已应用修改。 |
| 右侧 | Agent 显示已应用，可撤回或继续修改。 |
| 可编辑性 | 可继续手动编辑。 |
| AI 操作 | 可继续局部修改。 |
| 推进条件 | 用户确认是否刷新下游，才触发重跑。 |
| 禁止 | 自动重跑所有下游、中心标题写成局部修改。 |

### 通用 04｜生成报错重试

| 区域 | 规格 |
| --- | --- |
| 左侧 | 当前选中保持出错前产物，状态失败。 |
| 中间 | 标题保持当前产物，内容保持可查看。 |
| 右侧 | 报错说明、重试、补充说明。 |
| 可编辑性 | 可查看和补充说明。 |
| AI 操作 | 重试或根据补充说明继续。 |
| 推进条件 | 用户点击重试或发送补充说明后再继续。 |
| 禁止 | 自动跳运行记录、报错大屏覆盖编辑区、内部堆栈和模型细节。 |

## 6. Frame 重建顺序

1. 先完成 `component-accuracy-checklist.md` 对应组件页。
2. 截图检查组件页，没有溢出、贴边、错位后再开始 frame。
3. 按入口线、小说线、非小说线、闲聊线、通用线顺序重建。
4. 每张 frame 用本文档对应小节逐项验收。
5. 任一 frame 失败，先判断是组件问题还是 frame 拼装问题；组件问题回到组件页修，不在 frame 内打补丁。
