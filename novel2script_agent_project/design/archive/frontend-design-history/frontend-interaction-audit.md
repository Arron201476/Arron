# 前端交互审计与重构清单

本文档用于指导 Novel2Script Agent 前端重构。目标不是列 UI 美化项，而是先定义用户在每个状态下应该看到什么、能做什么、Agent 如何反馈、哪些动作必须请求确认。

## 总原则

1. 前端是工作台，不是流程按钮面板。
2. 右侧最大入口是 Agent 对话，审批、执行进度、失败说明都应嵌入对话流。
3. 左侧是项目目录，只显示当前链路相关产物，不把小说链和非小说链同时摊开。
4. 中间是当前产物的编辑 / 阅读区，不是 JSON 预览区。
5. 产物状态只能叫待生成、生成中、待确认、已生成、已失效、失败；不能把没有用户动作的产物叫已确认。
6. 用户任何输入都先进入 Main Agent 意图识别；只有明确生成、改编、继续、修改时才启动或推进流程。
7. 长耗时生成不能卡死在一个请求里；前端应显示 run 状态并通过事件流或轮询更新。

组件语义、按钮文案、图标状态以 `frontend-component-language.md` 为准。交互审计定义“应该发生什么”，组件规范定义“应该怎么显示和命名”。

## 推荐前端技术组合

| 层 | 推荐 | 用途 |
|---|---|---|
| 应用框架 | React + TypeScript + Vite | 重构当前静态前端壳 |
| 基础 UI | shadcn/ui + Radix UI | Button、Tabs、Dialog、Select、Tooltip、ScrollArea、Resizable Panel |
| 写作编辑器 | Plate / Plate UI | 分集卡、剧本、故事圣经、结构化富文本编辑 |
| 原文编辑器 | CodeMirror 6 | 左侧长文本输入、原文定位、选区引用 |
| Agent 面板 | AI Elements 参考组件 | Message、Attachment、Task、Confirmation、Checkpoint、Prompt Input |

说明：Go 后端不受影响。前端只消费现有 run、artifact、approval、message 接口；必要时反推后端补字段。

## 三栏信息架构

### 左侧：项目目录

左侧不是输入框，也不是完整流程图。它是当前项目已有或可生成产物的目录。

默认未开始：

| 顺序 | 条目 | 状态 |
|---|---|---|
| 1 | 剧本 | 待生成 |
| 2 | 输入材料 | 待添加 |
| 3 | 过程产物 | 按识别结果展开 |
| 4 | 运行记录 | 0 |

小说链路：

| 顺序 | 条目 | 状态来源 |
|---|---|---|
| 1 | 剧本 | scripts |
| 2 | 输入材料 | source_input |
| 3 | 故事圣经 | story_bible |
| 4 | 原文拆集 | episode_split |
| 5 | 分集卡 | episode_cards |
| 6 | 剧本上下文 | script_context |
| 7 | 运行记录 | run_events |

非小说链路：

| 顺序 | 条目 | 状态来源 |
|---|---|---|
| 1 | 剧本 | scripts |
| 2 | 输入材料 | source_input |
| 3 | 素材库 | material_bank |
| 4 | 故事种子 | story_seed |
| 5 | 剧集蓝图 | series_blueprint |
| 6 | 分集卡 | episode_cards |
| 7 | 剧本上下文 | script_context |
| 8 | 运行记录 | run_events |

左侧规则：

- 未识别链路前，不展示两条链的全部产物。
- 用户手动选择小说 / 非小说时，目录可预展开对应链路。
- run 创建后，以 `run.source_mode` 为准，不再被下拉选择覆盖。
- 如果上游产物被修改导致下游失效，下游状态显示已失效，不自动覆盖。
- 点击目录只切换中间内容，不直接触发生成。
- 运行记录放最后，避免抢占主产物位置。

## 中间：产物编辑 / 阅读区

中间区域承载“当前用户正在看的东西”。不同产物必须有不同编辑形态。

中间区域不承担 AI 指令入口：

- 不放“生成剧本”“局部改写”“版本对比”“重生成”这类 AI 操作按钮。
- 这些需求统一通过右侧 Agent 对话发起，Agent 根据当前 artifact、选区、版本和上下文判断动作范围。
- 中间只保留内容阅读、字段编辑、选区、基础保存状态、当前产物状态。

### 输入材料

小说输入：

- 使用 CodeMirror 6。
- 支持长文本、搜索、选区、行号或段落号。
- 支持从本地文件导入。
- 选中文本后右侧 Agent 能收到 selection context。

非小说输入：

- 支持自由文本、文件附件、结构化素材块。
- 用户可以输入灵感、梗概、人设、台词、限制条件。
- 前端不强迫用户先填表。

### 故事圣经

展示为结构化文档：

- 一句话故事
- 世界观 / 背景
- 主线冲突
- 主要人物
- 人物关系
- 必须保留事实
- 改编风险

交互：

- 可编辑字段。
- 改动后标记“未保存 / 已修改”。
- 若已被下游使用，保存前提示会影响拆集、分集卡、剧本。

### 原文拆集

展示为集数列表：

- 第几集
- 原文范围
- 信息密度
- 本集事件
- 尾钩
- 节奏风险

交互：

- 可调整分集边界。
- 调整边界属于高影响动作，必须请求确认。
- 确认后将当前 `episode_split` 版本标记为 `confirmed`，下游只读确认版本。

### 素材库

展示为素材分组：

- 用户明确提供的信息
- 模型推断的可能设定
- 缺失信息
- 禁止擅自扩写的信息

交互：

- 用户可以把某条推断改为确认事实。
- 用户可以删除不认可的推断。
- 缺失信息可由 Agent 追问。

### 故事种子

展示为开发方向：

- 一句话故事
- 核心钩子
- 主角欲望
- 对抗关系
- 情绪引擎
- 可扩写空间

交互：

- 可选择方向。
- 多方向候选时必须让用户确认主方向。

### 剧集蓝图

展示为阶段地图：

- 开局阶段
- 升级阶段
- 反转阶段
- 高潮阶段
- 结局阶段
- 每阶段核心爽点

交互：

- 改集数、合并阶段、重排主线属于高影响动作，必须审批。

### 分集卡

展示为分集卡片列表：

- 集数
- 标题
- 开场压力
- 主要冲突
- 场景计划
- 人物状态变化
- 本集尾钩
- 风险提示

交互：

- 这是写剧本前的关键 checkpoint。
- 确认卡必须在右侧 Agent 对话里出现，同时中间分集卡顶部显示待确认状态。
- 用户可对单集补充要求。
- 用户可要求重生成单集分集卡。
- 用户确认后，剧本生成才能继续。

### 剧本

展示为剧本编辑器：

- 按集展示。
- 按场景分块。
- 对白、动作、转场、旁白视觉区分。
- 可折叠场景。
- 可定位到角色台词、场景、尾钩。

交互：

- 支持选中一句、一个场景、一集后让 Agent 局部修改。
- 支持单集重生成。
- 支持比较新旧版本。
- 不能因为用户改一句话就默认重写全剧。

### 运行记录

默认不作为主视图展示，只在用户点击时查看。

内容：

- run started
- intent detected
- artifact created / updated
- approval requested / resolved
- step failed
- run completed

显示规则：

- 对用户展示人话。
- 技术字段放详情面板，不放在主对话里。

## 右侧：Agent 对话区

右侧是主入口。所有流程动作都应能从对话触发或解释。

### 消息类型

| 类型 | 显示方式 |
|---|---|
| 用户文本 | 右侧用户气泡 |
| 用户附件 | 用户气泡内附件 chip |
| Agent 回复 | 左侧 Agent 气泡 |
| 正在思考 | `正在思考` 行 |
| 执行步骤 | Agent 气泡内 compact task list |
| 审批请求 | Agent 气泡内 confirmation card |
| 错误 | Agent 气泡内错误卡 |
| 完成摘要 | Agent 气泡内完成卡 |

### 审批卡

审批卡不能脱离对话流。

审批卡字段：

- 标题
- 当前阶段
- 为什么需要确认
- 影响哪些产物
- 用户可选动作

常见按钮：

- 确认继续
- 补充要求
- 暂停
- 重生成这一步
- 后续自动执行

### 输入框

输入框必须支持：

- Enter 发送
- Shift + Enter 换行
- 添加本地文件
- 显示附件 chip
- 引用当前选区
- 引用当前 artifact
- 发送时锁定当前上下文快照

输入框不应该：

- 把文件名直接塞进文本内容。
- 在暂停状态下把用户输入插回旧消息中。
- 在等待确认时把普通补充误判为新 run。

## 关键状态矩阵

### 未开始

用户看到：

- 左侧只显示基础目录。
- 中间是空剧本提示。
- 右侧 Agent 欢迎语。

可做：

- 聊天。
- 上传 / 粘贴小说。
- 上传 / 粘贴梗概或灵感。
- 手动选择小说 / 非小说。

不可做：

- 确认分集卡。
- 查看不存在的故事圣经或素材库。

### 闲聊

用户输入“你好”“？”“今天怎么样”时：

- Agent 只回复。
- 不创建 run。
- 不改目录。
- 不生成 artifact。

### 启动生成

用户明确要求生成或改编时：

- Agent 先说明识别结果。
- 创建 run。
- 左侧展开对应链路。
- 中间切到当前关键产物。
- 右侧显示执行步骤。

### 运行中

用户看到：

- 右侧有正在思考 / 正在执行。
- 中间随着 artifact 更新切换或刷新。
- 左侧对应条目标记生成中 / 已生成。

可做：

- 查看已生成产物。
- 发送补充说明。
- 暂停。

限制：

- 长生成必须后台运行，不应让整个页面像卡死。

### 等待确认

用户看到：

- 右侧 Agent 消息内有审批卡。
- 中间展示需要确认的产物。
- 左侧产物状态为待确认。

可做：

- 确认继续。
- 补充修改要求。
- 暂停。
- 重跑当前步骤。

不可做：

- 直接跳过确认写剧本。
- 把补充说明插入旧消息中。

### 暂停

用户看到：

- run 状态为已暂停。
- 当前审批卡或暂停卡保留。

可做：

- 继续补充要求。
- 确认继续。
- 取消本次 run。

### 完成

用户看到：

- 左侧剧本已生成。
- 中间自动切到剧本。
- 右侧给出完成摘要。

可做：

- 查看分集卡、素材库、运行记录。
- 选中局部让 Agent 修改。
- 单集重生成。

## 局部修改交互

局部修改是核心能力，不应做成一堆固定按钮。

前端需要传给 Agent：

- artifact_type
- artifact_id
- version
- node_id 或 block_id
- selection_start / selection_end
- episode_id
- scene_id
- selected_text
- before_context
- after_context

Agent 需要先判断修改范围：

- selection_only：只改选区
- node_level：改当前块
- scene_level：改当前场景
- episode_level：改当前集
- artifact_level：改整个产物
- upstream_change：需要改上游并影响下游

高影响修改必须审批：

- 改集数
- 重排主线
- 改人物关系
- 覆盖已确认分集卡
- 重生成整集或整部剧本

## 前端重构验收清单

### 左侧

- 未开始时不展示两条链全部产物。
- 小说链和非小说链不会混在一起。
- 状态名准确：待生成、生成中、待确认、已生成、已失效、失败。
- 点击目录只切视图，不触发生成。

### 中间

- 每类 artifact 都有可读的字段化展示。
- 剧本不是 JSON，也不是普通 pre。
- 分集卡可逐集阅读。
- 选中文本能形成 selection context。

### 右侧

- Agent 对话是最大入口。
- 确认卡嵌在对话里。
- 执行过程是 compact task list，不是满屏技术事件。
- 附件显示为 chip。
- Enter 发送、Shift Enter 换行。

### 状态机

- 闲聊不启动 run。
- 等待确认时补充说明不会创建新 run。
- 暂停后可以继续。
- 失败能解释并允许重试。
- 长任务不阻塞整个界面。

## 第一轮重构范围

第一轮只解决基础体验，不做所有高级功能。

必须做：

1. React + TypeScript + Vite 前端壳。
2. shadcn/ui 基础组件。
3. 左侧动态目录。
4. 右侧 Agent 消息、附件、审批卡、任务步骤。
5. 中间 artifact 字段化展示。
6. CodeMirror 6 原文 / 素材输入。
7. 保留现有 Go 后端接口。

暂不做：

1. 多人协作。
2. 复杂导出。
3. 完整版本 diff。
4. 所有局部修改执行闭环。
5. 生产级权限系统。
