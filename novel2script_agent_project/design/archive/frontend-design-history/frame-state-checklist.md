# Frame 状态检查表

本文档用于重建 Figma frame 前的验收检查。每一张 frame 都必须先通过本文档检查，再进入视觉绘制。

## 最终交付提醒

用户已经明确给出本轮 Figma 交付的期望：希望明早看到的是一次通过的结果，而不是继续由用户逐张截图筛问题。执行者必须反复自检、逐页截图、逐条追问“这里是否真的 ok”，直到组件页和 frame 页都达到可以进入开发的状态。电脑会保持运行，额度不是限制；限制只有交付质量。

## 0. 全局硬规则

| 检查项 | 必须满足 | 禁止出现 |
| --- | --- | --- |
| 顶部栏 | 只保留产品名与必要全局入口。 | 小说名、项目名、改编类型、自动保存时间等 mock 信息。 |
| 中间标题 | 必须等于左侧当前选中的导航项。 | 当前选中运行记录，中间却写分集卡/剧本/项目名。 |
| 左侧目录 | 识别前只显示通用目录；识别后才展开小说或非小说链路。 | 初始状态直接展示故事圣经、素材库、故事种子等具体链路节点。 |
| 运行记录 | 只有用户点运行记录时，中间才展示运行记录。 | 因为上传、闲聊或生成过程自动切到运行记录。 |
| 附件 | 未发送前只作为 composer 内待发送内容。 | 用户只选择文件就生成聊天记录、运行记录或产物。 |
| 右侧 Agent | 只显示聊天、任务进度、确认卡、修改建议、报错重试。 | 右侧状态和左中区域无关。 |
| 生成推进 | 上一步未确认前，下一步只能是待生成。 | 分集卡待确认时剧本生成中。 |
| 生成完成 | 完成态不显示 78% 之类未完成进度。 | 已完成但仍显示未完成进度条。 |
| 进度条 | 只有进度计算口径明确时才展示；完成态必须 100% 或不展示。 | 用固定 78% 之类 mock 进度占位。 |
| 修改交互 | 用户在右侧输入修改要求；建议卡嵌入右侧聊天。 | 中间额外放一个“输入修改要求”的浮层。 |
| 报错 | 报错优先在右侧 Agent 显示，中心保持当前产物。 | 中间做独立报错大屏，打断编辑区。 |

## 7. 逐帧验收口径

每张 frame 交付前必须回答以下问题：

1. 图名是否为中文，且能说明当前业务状态？
2. 左侧当前选中项和中间标题是否一致？
3. 中间内容是否只展示当前选中项对应的产物？
4. 右侧 Agent 是否只展示当前状态相关的聊天、任务、确认或修改建议？
5. 是否有任何未确认就推进下一步的状态？
6. 是否有小说线和非小说线产物混用？
7. 是否有用户未发送内容就产生运行记录或任务记录？
8. 是否有完成态仍显示未完成进度？
9. 是否有顶部 mock 信息污染状态？
10. 是否有报错或修改建议污染中间编辑区？
