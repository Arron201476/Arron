# Product Design Audit: Script Editor And UI State Gallery

审计日期：2026-06-26

## Audit Scope

本次只审计当前可见的前端设计状态，不审计真实模型输出质量。

证据来源为本轮新截图：

- `01-gallery-novel-flow.png`：UI 状态稿中的未开始 / 小说链路状态。
- `02-gallery-script-edit.png`：UI 状态稿中的小说运行与等待确认状态。
- `03-tiptap-spike.png`：Tiptap 剧本编辑器候选。
- `04-lexical-spike.png`：Lexical 剧本编辑器候选。

用户目标：前端进入正式开发前，需要确认三栏工作台、Agent 操作流、剧本正文编辑器、过程产物展示和状态反馈是否足够清楚，避免继续沿用过于原始的 mock 交互。

无障碍目标：关键操作可被键盘使用、状态变化可被理解、按钮/输入/附件/确认卡有清晰标签，长文本编辑不依赖纯视觉线索。

## Step List

1. `01-gallery-novel-flow.png`：未开始状态。健康度：中等，可表达大结构，但仍偏静态展示。
2. `02-gallery-script-edit.png`：小说链路运行中。健康度：中等偏低，流程关系可见，但画面密度和确认机制仍不够像真实产品。
3. `03-tiptap-spike.png`：Tiptap 编辑器。健康度：中等，适合快速落地 Word-like 编辑，但结构化剧本能力需要补强。
4. `04-lexical-spike.png`：Lexical 编辑器。健康度：中等偏高，适合结构化剧本节点，但实现成本更高。

## Strengths

- 三栏关系已经比早期 mock 清楚：左侧是项目目录，中间承载内容，右侧承载 Agent 对话和流程推进。
- 左侧目录已经开始按链路收敛，没有再把小说和非小说两条链的所有步骤同时暴露给用户。
- 确认动作已经从中间内容区移向 Agent 区域，方向正确，因为确认、补充说明、暂停、继续都属于 Agent 交互。
- 剧本正文已经单独作为重编辑区域处理，而不是把所有 artifact 都用同一种 JSON 卡片呈现。
- Tiptap 和 Lexical spike 都证明基础富文本能力可落地，包括加粗、斜体、下划线、删除线、批注入口、保存和 patch 预览。

## UX Risks

### 1. Gallery 仍像状态说明稿，不像最终操作界面

旧截图 `01` 和 `02` 适合定义信息架构，但不适合作为最终视觉定稿。当前 `frontend-ui-state-gallery.html` 已升级为 UI/UE 定稿候选；进入实现前仍需要用户验收，并在 React 组件状态页中复刻其信息层级和交互语义。

建议：gallery 作为状态契约和 UI/UE 定稿候选；正式实现时减少说明文字，强化真实可操作控件，并通过 React 组件状态页做视觉回归。

### 2. Agent 区域仍需要更像对话流

截图 `02` 里 Agent 有消息、任务步骤和输入框，但确认卡仍像一个流程面板。真实体验里，确认卡应嵌入对话流，和 Agent 的解释、用户补充说明、继续/暂停操作形成同一条时间线。

建议：Agent 右侧消息模型统一为：

- 用户消息。
- Agent 文本回复。
- Agent 正在执行状态。
- tool/task step chips。
- approval card。
- attachment pill。
- run summary card。

不要再把确认卡、日志和聊天拆成互不相干的模块。

### 3. 左侧目录的状态文案需要绑定真实动作

截图 `01` 里有 `待生成`、`待添加`、`未识别`，方向比“已确认”正确。但后续必须明确：只有用户点击过确认，或 Agent 明确完成过确认动作，才能显示“已确认”。自动生成出来的内容只能叫“已生成”“待确认”“生成中”“待生成”。

建议：左侧状态只显示 artifact 生命周期，不显示 Agent 过程细节。

### 4. 中间内容区需要分两种编辑强度

过程产物适合结构化字段编辑，例如故事圣经、人物、分集卡；最终剧本适合 Word-like 正文编辑。当前 gallery 已经分出方向，但还需要写成组件规则，避免所有内容都塞进同一个 editor。

建议：

- `ScriptEditor`：正文级编辑，支持格式、批注、局部修改、选择引用、保存版本。
- `ArtifactFieldEditor`：字段级编辑，支持增删字段、重排、局部重写、确认。
- `ArtifactViewer`：只读或弱编辑，用于运行过程回看。

### 5. Tiptap spike 更快，但剧本结构需要额外建模

截图 `03` 中 Tiptap 的正文体验更接近普通富文本编辑器，工具栏也更自然。风险是结构锚点依赖 `data-episode-id` / `data-scene-id` / `data-line-id`，如果没有严格节点规范，局部修改时容易只拿到文本片段，拿不到稳定的 episode / scene / line 来源。

建议：如果选 Tiptap，必须定义自定义节点或严格 schema，不要只用普通 paragraph 承载剧本行。

### 6. Lexical spike 更适合结构化，但视觉表现还没到产品级

截图 `04` 的每一行更像独立剧本节点，便于绑定 episode / scene / line / block type。风险是工具栏、选区、批注、撤销栈和 JSON 视图还偏工程验证，不是给最终用户看的。

建议：如果选 Lexical，先把底层节点模型打稳，再用 shadcn/ui 或同等组件重做工具栏、批注、版本、保存状态。

## Accessibility Risks

- 截图无法证明键盘焦点顺序、屏幕阅读器语义、快捷键冲突和输入法行为，需要后续浏览器测试。
- 部分工具栏按钮只有短标签或图标，正式实现必须提供 `aria-label`、tooltip 和可见 focus ring。
- 左侧状态 pill 不能只靠颜色区分，需要文字和语义状态同步。
- 运行中、完成、等待确认等状态不能只用视觉位置表达，需要在 Agent 消息流里有明确文本。
- 剧本正文编辑器要避免把结构信息只存在视觉排版中；场次、对白、转场、动作都应有可被程序识别的节点类型。

## Recommendations

1. 把 `frontend-ui-state-gallery.html` 定位为状态契约和 UI/UE 定稿候选；用户验收前不视为最终冻结稿。
2. 下一步先选编辑器底座：Lexical 更适合结构化剧本，Tiptap 更适合快速接近 Word-like 体验。
3. 在选型前补一轮真实交互 spike：选择一段对白，让 Agent 读取选区来源，生成 suggestion patch，再由用户接受/拒绝。
4. 把 Agent 右侧重构为统一消息流，确认卡、附件、任务步骤、运行总结都作为消息 part。
5. 建立正式组件库：按钮、输入、附件、任务步骤、确认卡、状态 pill、左侧目录项、文档页、剧本行节点。
6. 高保真 UI 定稿应基于真实 fixture 和长文本，不再使用过短占位文案。

## Evidence Limits And Verification Gaps

- 本次是截图审计和本地 spike 审计，不等于完整可用性测试。
- 没有覆盖移动端、窄屏、缩放 200%、键盘全流程、屏幕阅读器。
- 没有接真实模型输出，因此无法判断长剧本、多 episode、多 artifact 的性能和排版稳定性。
- 没有验证后端 run / artifact / approval 事件是否与 UI 状态逐项绑定。

## Next Design Gate

正式前端开发前，建议先完成一个“编辑器选型 gate”：

- 用同一份长剧本 fixture。
- 分别验证 Tiptap 和 Lexical 的节点结构、选区来源、patch 应用、批注、撤销、保存和导出。
- 输出结论：选择一个作为 `ScriptEditor` 底座，另一个归档。

# ScriptEditor Selection Gate

日期：2026-06-26

## 结论

本轮 gate 建议：正式 `ScriptEditor` 底座选择 **Lexical**。

Tiptap 不删除出局，但当前 spike 不能作为正式剧本编辑器底座直接进入开发。原因不是 Tiptap 不能做，而是当前实现只用普通 HTML / paragraph 承载剧本行，结构锚点没有被编辑器 schema 稳定保留。

如果未来继续考虑 Tiptap，必须先补自定义 node/extension，把 episode / scene / line / block type 作为一等结构处理，再重新跑同一套 gate。

## 验证范围

同一份 fixture：

- 2 集。
- 4 场。
- 12 条剧本行。
- 包含动作、对白、转场、marks、批注、sample patch。

自动化脚本：

```powershell
cd frontend
npm run gate:editor
```

输出文件：

- `design/audits/script-editor-selection-gate/results.json`
- `design/audits/script-editor-selection-gate/tiptap-after-patch.png`
- `design/audits/script-editor-selection-gate/lexical-after-patch.png`

## Gate 项目

本轮检查了：

- 编辑器是否正常加载。
- fixture 的 12 条剧本行是否都有稳定 `line_id` 锚点。
- 目标行 `ln_001_001_002` 是否存在。
- 工具栏是否可操作。
- 侧边 JSON / 状态面板是否输出。
- 拖选目标行后是否能报告 selection ref。
- patch 按钮是否可点击。
- patch 后是否保留目标行锚点。
- patch 后是否把建议文本写入目标行。
- patch 是否有可回看的建议状态。
- save 按钮是否可点击。
- save 后是否保留行锚点。
- after-patch 截图是否保存。

## Tiptap 结果

总结果：未通过。

通过项：

- 页面和编辑器 shell 能加载。
- 工具栏可渲染，8 个按钮存在。
- JSON / 状态面板有输出。
- patch 按钮可点击。
- save 按钮可点击。
- after-patch 截图已保存。

失败项：

- 预期 12 条 line anchors，实际找到 0 条。
- 目标行 `ln_001_001_002` 在 patch 前不存在可读结构锚点。
- 拖选后侧边面板没有暴露目标行 selection ref。
- patch 后没有可定位的目标行。
- patch 后无法确认建议文本写入了目标行。
- patch 没有保留可机器识别的建议标记。
- save 后仍没有 line anchors。

判断：

Tiptap 当前实现更像“可编辑富文本页”，不是“可追踪剧本结构编辑器”。它适合快速做 Word-like 体验，但如果不做自定义 schema，Agent 的局部修改、选区引用、批注挂载、版本对比都会不稳定。

## Lexical 结果

总结果：通过。

通过项：

- 页面和编辑器 shell 能加载。
- 12 条 line anchors 全部保留。
- 目标行 `ln_001_001_002` 在 patch 前存在。
- 工具栏可渲染，7 个按钮存在。
- JSON / 状态面板有输出。
- 拖选后侧边面板能暴露目标行 selection ref。
- patch 按钮可点击。
- patch 后目标行锚点仍存在。
- patch 后建议文本写入目标行。
- patch 后有可见“建议”状态。
- save 按钮可点击。
- save 后 12 条 line anchors 仍保留。
- after-patch 截图已保存。

判断：

Lexical 当前实现更接近正式需求：剧本行可以作为自定义节点保存 episode / scene / line / block type，Agent 可以从选区追溯 artifact 来源，并把 patch 落到目标节点。

## 仍未完成的验证

本轮 gate 只能说明 Lexical 更适合作为底座，还不能说明它已经产品可用。下一轮需要补：

- 长剧本性能：20 集以上、数百场、数千行。
- 真实 suggestion model：不要直接替换文本，要支持建议、接受、拒绝、撤回。
- 批注 thread：批注需要挂到 range，并能随文本编辑保持或失效。
- 版本对比：原文、AI 建议、用户修改之间要能清楚比较。
- 导出：至少确认 HTML / JSON / DOCX 路线。
- 输入法：中文输入、换行、撤销、粘贴 Word 文本。
- 可访问性：键盘、focus、toolbar label、屏幕阅读器语义。

## 工程决策

后续正式前端实现建议：

- `ScriptEditor` 采用 Lexical。
- 剧本正文用自定义节点建模：episode heading、scene heading、script line、dialogue line、action line、transition line。
- 过程产物不要复用 `ScriptEditor`，用字段型 `ArtifactFieldEditor`。

## 角色
你是小说转短剧系统中的拆集 Agent。

## 任务
基于完整原文、`story_bible` 和启动前已确认的 `generation_config`，生成 `episode_split`。必须按 `target_episode_count` 拆分，并结合原文体量、章节边界、事件密度和尾钩位置选择具体边界。本步骤只决定每集覆盖的原文范围、核心事件、断点理由和尾钩强度；不生成剧本正文，不写完整分集卡。

```json
  "story_bible": {},

    "target_episode_count": null,
    "target_format": "小程序短剧",
    "must_keep": [],
    "avoid": []
  },
  "user_locked_boundaries": [],
  "user_notes": []
}
```

1. 必须保持原文顺序。
2. 每集必须绑定明确 `source_refs`。

4. 必须消费 `story_bible.source_structure`、`major_plotline`、`must_keep_facts` 和 `short_drama_assets`。其中保留/压缩/前置/心理转场面候选必须转化为拆集边界、信息密度、风险标记或断点理由，不得直接新增剧情。

6. 某集没有强尾钩时，只能标记 `hook_strength: low`，不能硬编新剧情。

8. 不新增关键剧情；必要桥接只能输出为建议，不能写成原文事实。
9. 用户锁定的边界优先级高于模型判断。

12. 如果缺少有效 `target_episode_count`，返回结构化风险并停止本步骤，不得默认 20 集或其他固定集数。
13. 如果固定目标集数导致素材体量不匹配，必须写入 `global_risks`，是否改集数或合并拆分交给后续 agent/workflow 审批。

- 身份落差
- 阶层压迫
- 家庭、爱情、事业中的强选择

检查素材是否包含：

- 打脸
- 反击
- 身份揭露
- 证据出现
- 危机逆转
- 误会升级
- 权力关系变化

#### 4. 哪些内容适合场面化

适合短剧的素材通常有明确场景、行动、对白和外部压力。

需要改编处理的内容包括：

- 大量心理描写
- 大量设定说明
- 大量抽象情绪
- 场景昂贵或特效依赖强
- 人物过多、支线过散

故事圣经应标记哪些心理、说明和抽象情绪可以转化为可拍的动作、对话、物件、场景压力或人物选择。

2. 人物深度服务剧情推进，不写无用履历。
3. 人物重塑要在前期设定中锁定，不在剧本正文阶段临时改底层设定。

- 阻止主角的原因
- 可见行动
- 资源优势

- 升级手段

- 提供误会
- 提供证据
- 提供资源

### 地域/方言声口边界

1. 只有原文、用户要求或人物设定明确给出地域、阶层、职业、年龄和成长背景时，才使用地域化声口。

3. 方言必须服务人物身份、亲密关系、冲突压迫或喜剧反差；如果不能服务剧情功能，就保持普通话表达。
4. 同一人物的地域化表达要稳定，不在不同集数突然切换口音或语言风格。
5. 严肃冲突、关键信息、证据揭示和情绪爆发场景，要优先保证观众读懂，不为方言牺牲信息清晰度。
6. 不因地域声口制造刻板印象，不把地域标签当成人物性格本身。

1. 每集都要有明确剧情功能。
2. 每集至少推进剧情、关系、信息或情绪之一。
3. 开头钩子、主要冲突、结尾悬念必须来自原文块、故事设定或已锁定规划。
4. 不得为了结构完整而新增关键设定。

#### 1. 本集功能

每集应标明本集承担的功能：

- 建立处境
- 升级冲突
- 埋设伏笔
- 回收伏笔
- 情感推进
- 身份线索
- 反击兑现
- 危机加码
- 真相揭露

### 短剧开头设计


### 参考范围

参考情况：

- 开头慢
- 前几集没有高冲击事件
- 第一场戏只是背景介绍
- 单集开头不承接上一集尾钩
- 观众无法迅速理解主角处境
- 开头缺少压力、悬念或行动

### 使用原则

1. 开头必须从压力、异常、冲突、证据、选择或强情绪进入。
2. 开头可以倒序或高潮前置，但必须来自原文、故事设定或分集规划已有事件。
3. 不得为了抓人新增原文没有的重生、系统、隐藏身份、死亡危机或关键证据。
4. 当前集开头必须承接上一集尾钩，不重播、不跳过、不重置。
5. 开头不是解释区，解释要放在行动和冲突之后。

### 开头类型

#### 1. 冲突式开头

直接进入对峙、羞辱、逼问、争夺、拦截或威胁。

适合：

- 复仇
- 逆袭
- 豪门
- 真假身份
- 职场压迫
- 家族冲突

#### 2. 悬念式开头

先给出异常、证据、人物反应或未解问题。

适合：

- 隐藏身份
- 悬疑
- 误会
- 证据线
- 关系秘密

#### 3. 情绪式开头

从主角被压迫、忍耐、背叛、崩溃或爆发的瞬间切入。

适合：

- 虐恋
- 女性成长
- 亲情压迫
- 情感修复

#### 4. 高潮前置开头

把本集最强危机、反击前一秒或身份即将暴露的节点放在开头。

只能用于已规划的本集事件。

### 前 3 集参考重点

前 3 集应让观众理解：

- 主角是谁
- 主角最痛的处境是什么
- 谁在阻止主角
- 主角为什么不能退
- 观众等什么反转或回报

如果前 3 集仍主要在解释背景，应标记为开局过慢。

### 引用边界

使用时应影响以下内容：

- 分集规划中的开头钩子
- 剧本正文的第一场戏
- 上一集尾钩与本集开头的承接
- 导语集、第 1 集和前 3 集的进入方式

### 禁止越权

1. 不新增关键设定。
2. 不把上一集尾钩重演一遍。
3. 不用纯环境描写开头。
4. 不用长旁白交代背景开头。
5. 不让开头钩子脱离本集主体事件。

### 短剧钩子与爽点引擎


### 参考范围

参考问题：

- 观众没有继续看的理由
- 每集结尾弱
- 爽点不清
- 反转太少
- 付费点前缺少期待
- 情绪回报没有落地
- 冲突重复但没有升级

### 使用原则

1. 钩子必须绑定具体事件、证据、人物、危机、身份、选择或真相。
2. 爽点必须通过局势变化落地，不靠口号。
3. 付费点应卡在兑现前，不卡在兑现后。
4. 同一类型钩子不要连续重复。
5. 钩子和爽点都必须来自原文、故事设定或分集规划已有信息。

### 钩子类型

可使用：

- 反转钩
- 危机钩
- 揭秘钩
- 情感爆发钩
- 悬疑钩
- 倒计时钩
- 身份钩
- 证据钩
- 反派视角钩
- 爽点前卡

弱钩子包括：

- 沉默
- 凝视
- 走远
- 情绪余味
- 空镜
- 准备做某事但没有风险

### 爽点类型

可使用：

- 小人物反击
- 对手误判
- 隐藏实力兑现
- 身份或资源反转
- 证据亮出
- 反派计划失败
- 主角拿回主动权
- 情感关系确认或反转

爽点必须让局势发生可见变化。

### 付费点设计

付费点前应具备：

- 明确期待
- 明确风险
- 明确未兑现答案
- 明确下一集动作

付费点不应只是“情绪很激烈”，而要让观众知道下一集会发生什么关键变化。

### 引用边界

使用时应影响以下内容：

- 主线追更机制
- 分集尾钩设计
- 爽点兑现位置
- 付费点前的期待设计
- 钩子类型轮换

### 禁止越权

1. 不新增关键设定制造钩子。
2. 不把情绪余味当成事件型尾钩。
3. 不连续多集使用同一种钩子。
4. 不为了爽点跳过人物转变过程。
5. 不让爽点兑现后才切集尾。

### 短剧结构与冲突引擎


### 参考范围

参考问题：

- 主线松散
- 冲突重复
- 反派行动弱
- 每集只是过渡
- 中段塌陷
- 悬念没有递进
- 角色行动缺少代价

### 使用原则

1. 冲突必须写清“谁要什么、谁阻止、失败损失什么”。
2. 冲突应形成链条：触发新动机，动机推动新行为，新行为造成新局势。
3. 结构服务当前素材，不强行套固定集数。
4. 16 节拍只能作为软参考，不能覆盖已经确定的分集规划。
5. 反派行动要升级，主角反应也要升级。

### 冲突升级方式

#### 1. 代价升级

从小损失升级为身份、关系、资源、生命、名誉或自由风险。

#### 2. 对手升级

从小反派、误会、家族压力、职场压力，升级到真正掌权者或核心利益冲突。

#### 3. 信息升级

从局部误会升级为隐藏身份、旧案、秘密协议、亲缘真相或资源真相。

#### 4. 情感升级

从嘴上冲突升级为关系破裂、选择、背叛、牺牲或承认。

#### 5. 行动升级

从争吵升级为证据争夺、公开对抗、计划反制、倒计时任务或最终选择。

### 悬念推进

悬念必须逐步释放信息，不要长期只藏不露。

每次释放应产生：

- 新问题
- 新风险
- 新人物立场
- 新行动目标

### 引用边界

使用时应影响以下内容：

- 故事主线的冲突链
- 每集的冲突功能
- 对手行动的升级
- 主角反击的递进
- 悬念释放节奏

### 禁止越权

1. 不为了结构完整新增大反派或新世界观。
2. 不重排已经锁定的分集素材。
3. 不让冲突只停留在争吵，没有局势变化。
4. 不把所有集都写成同一种打脸。
5. 不用 16 节拍覆盖原文因果。

### 剧本生成 短剧节奏规则中的规划层规则

### 剧本生成 短剧节奏规则

### 参考范围

当前集剧本参考维度：

- 当前集应承担的节奏功能
- 开头是否足够快
- 中段是否有推进
- 结尾是否有事件型悬念
- 前后集是否承接
- 钩子类型是否重复

### 使用原则

1. 总集数由 拆集边界和 分集规划决定，不固定为 60 集。
2. 下面的 EP 区间是节奏参考，不是机械硬规则。
3. 当前集必须优先遵守 分集规划。
4. 如果实际总集数少于某个区间，按比例压缩节奏阶段。
5. 不要为了套阶段规则而新增 分集规划 没有的剧情。
6. 每集都要有明确推进，不能成为单纯过渡。
7. 开头、爽点、反转和结尾钩子必须从当前集原文、故事圣经 故事设定和 分集规划中提炼，不得为了追求强刺激新增关键事实。

### 全局尾钩与承接规则

1. 每集结尾必须是事件型尾钩，不是情绪尾声。
2. 尾钩必须指向具体物件、证据、人物、威胁、选择或下一步风险。
3. 切在兑现前，不切在兑现后。
4. 下一集开头优先承接上一集尾钩的后果链。
5. 不要把上一集尾钩重新演一遍。
6. 不要连续使用同一种钩子类型。
7. 同类钩子尽量间隔至少 3 集。
8. 结尾可以卡在主线期待、身份反转、情感冲突、悬念揭秘、危机升级或爽点兑现前，但必须有明确的下一集观看理由。

禁止弱尾钩：

- 平静反应
- 余韵凝视
- 走远
- 沉默
- 空镜式收尾
- 单纯准备做某事但没有具体风险

### 短视频留存节奏

1. 每集前 3 秒必须抛出高能信息、强冲突、反转信号或能立刻理解的危机，避免从背景介绍进入。
2. 单集 60-90 秒体感中，开头负责抓人，中段负责推进，结尾负责卡点；不要把所有高能都堆到最后。
3. 每 30 秒左右应出现一次小反转、压力升级、关系变化、信息揭露或爽点动作，但不能为了凑节奏硬造新事件。
4. 如果本集是轻铺垫集，也必须至少有一个可见的关系变化、信息变化、行动选择或风险加码。
5. 如果本集是强爽点集，必须让观众看见“对手占优 → 主角抓住机会 → 局势反转 → 新风险出现”的节奏链。

### 阶段节奏参考

#### 1. 开局阶段

目标：快速建立主角、核心冲突、主要对手和追更动机。

要求：

- 第一集第一秒必须有高冲击事件。
- 前 3 集内观众必须理解“谁要什么、谁挡路、主角为什么不能退”。
- 前几集要快速进入羞辱、反击、危机、身份差、证据、关系压迫等高点击事件。
- 如果有世界观或能力体系，要通过行动展示，不要说明书式解释。
- 开局阶段每集都要有明确的小爆点或悬念。

#### 2. 冲突升级阶段

目标：让对手行动频率提高，人物关系变紧，主角反击成本升高。

要求：

- 每 2-3 集形成一次小高潮或局势变化。
- 冲突类型要升级换代，不要重复同一套误会或打脸方式。
- 每集必须有实质推进，例如新证据、新关系变化、新压力、新代价。
- 避免纯日常、纯回忆、纯心理独白拖节奏。

#### 3. 中段反转阶段

目标：揭露身份、动机、隐藏关系或关键真相，让故事进入更深层矛盾。

要求：

- 每 3 集左右引入一个新冲突维度。
- 至少持续释放身份线索、关系变化、力量格局重组或秘密揭露。
- 情绪基调可以交替，但不能连续多集同一种情绪。
- 不能只重复前期打脸方式，必须让反派手段和主角应对都升级。

#### 4. 终局危机阶段

目标：集中回收伏笔，推动主要人物进入最终选择和最终对抗。

要求：

- 主要支线开始回收，不能留下明显无解悬念。
- 每集事件密度高于前中期。
- 主要人物都应被推到更危险或更明确的位置。
- 结尾几集要让观众感到“大事将至”。

#### 5. 结局阶段

目标：完成阶段性圆满，释放情绪回报。

要求：

- 主角必须获得清晰的阶段性结果。
- 主要冲突必须给出可理解的处理。
- 情绪释放要具体，不要只靠总结性旁白。
- 如果保留开放口，也必须先完成当前主线的基本回报。

### 16 节拍软参考

以下节拍用于参考全剧和当前集的功能，不得覆盖 分集规划，不得强行重排原文：

1. 开场画面：展示主角现状和核心痛点。
2. 主题陈述：用台词或事件点出核心价值冲突。
3. 铺垫：快速交代人物关系、世界规则和隐藏矛盾。
4. 催化剂：打破平衡的关键事件。
5. 争执或犹豫：主角面对行动成本。
6. 第二幕衔接点：主角下定决心进入反击或冒险。
7. B 故事：情感线、友情线或副线进入。
8. 游戏时间：主角初尝胜利、打脸小反派或获得资源。
9. 中点：看似胜利或看似失败，引出更大危机。
10. 反派逼近：压力升级，阴谋收紧。
11. 一无所有：主角跌入阶段性低谷。
12. 灵魂黑夜：主角产生崩溃、动摇或痛苦选择。
13. 第三幕衔接点：顿悟、证据、贵人或计划出现。
14. 最后一战：核心矛盾进入正面对抗。
15. 高潮：真相、反转、惩罚或情绪回报落地。
16. 终场画面：形成阶段性新平衡。

短剧化应用：前 3 秒对应开场高能；中段每隔一段时间要有小反转或小爽点；集尾优先卡在第 8、10、13、14、15 类节拍的兑现前。

### 钩子类型轮换指南

可使用以下基础钩子：

1. 反转钩：结尾出现意想不到的转折。
2. 危机钩：主角陷入紧急困境。
3. 揭秘钩：重要秘密或证据即将被看见。
4. 情感爆发钩：强烈关系冲突即将失控。
5. 悬疑钩：抛出具体待揭晓事项，并带出下一步动作或风险。
6. 倒计时钩：设置紧迫时间线。

也可以使用以下细分钩子，但必须基于原文和分集规划已有信息：

1. 身份钩：角色真实身份、关系或权力位置即将暴露。
2. 突发事件钩：角色突然遭遇困境、邀约、告白、袭击、任务或召唤。
3. 冲突升级钩：误会、羞辱、争夺或对抗进入更高强度。
4. 意外危机钩：角色陷入人身、名誉、资源或情感关系的紧急风险。
5. 秘密揭示钩：只揭开一部分秘密，让答案尚未完全落地。
6. 意外访客钩：新人物带来信息、威胁、证据或新关系压力。
7. 重要物品钩：关键道具、证据、文件、信物、药物、照片、监控等出现。
8. 未完成对话钩：关键问题刚问出口或关键回答被打断。
9. 上帝视角钩：观众知道角色尚未察觉的信息，形成紧张感。
10. 反派视角钩：反派计划、阴谋或下一步动作被展示。
11. 角色独白钩：角色短 OS 暗示即将发生的行动或反转。
12. 爽点前卡：主角即将反击、揭证据、亮身份或兑现惩罚前切断。

不要把“留白”写成空泛沉默。留白必须绑定具体未揭开的证据、人物、威胁或选择。

### 应用示例

弱尾钩：

△主角看着窗外，心里隐隐不安。

强尾钩：

△主角打开档案袋，里面掉出一张写着她名字的手术同意书。

强尾钩具备具体物件、信息落点和下一集风险。

### 一卡高潮与节奏密度

1. 全局规划要识别第一个可支撑付费/追更的全剧高潮候选点，通常应发生在观众已经理解主角困境、核心敌我关系和主要爽点承诺之后。
2. “一卡”不是固定集数公式；如果项目目标约 20 集，可把第 10 集附近作为参考区间，但必须服从原文信息量、冲突成熟度和用户目标集数。
3. 一卡候选必须来自原文事实、故事圣经或非小说链路中已确认的 story_seed / series_blueprint，不得为了付费点凭空制造关键事件。
4. 分集或规划阶段发现某集信息量不足时，应标记节奏风险，并通过压缩场景、强化冲突功能、前置已有信息或提示用户确认解决；不能靠增加寒暄、空镜、重复解释来撑集数。
5. 如果目标集数和素材体量明显不匹配，准则只能要求标记风险；是否改集数、合并拆分或重排剧情，应进入后续 agent/workflow 审批，不在单个写作步骤里擅自处理。
6. 每集必须有明确功能：推进事件、改变关系、兑现爽点、制造危险、打开悬念或完成情绪转折。没有功能的集数应被标记为弱集风险。

# 04_剧本写作技法

## 名称
04_剧本写作技法

## 用途描述
用于 Step4 剧本生成，提供场景、动作、戏剧化表达、单集节奏和可拍性准则。

## 准则


### 执行边界

1. 本规则模块 只负责把已经确定的 `episode_card`、上下文和素材约束写成可拍剧本正文。
2. 开头、尾钩、爽点位置、阶段节奏和单集功能以 `03_结构规划_开头_冲突_爽点_尾钩.md` 为准；本规则模块 只负责把这些规划写成场景、动作和戏剧节拍，不重新设计结构。
3. 对白功能、声口、长台词和潜台词以 `05_对白规则.md` 为准；本规则模块 只检查对白是否嵌入行动、冲突和场景压力。
4. 转场、闪回、连续性和中文剧本格式以 `06_转场_闪回_连续性_格式.md` 为准；本规则模块 只负责让正文执行这些格式和连续性要求。
5. 长示例统一参考 `08_示例库.md`；本规则模块 只保留必要的短对照示意，不重复维护完整示例。

### 剧本初稿生成准则
### 要求规范

#### 优先级

当多个要求冲突时，按以下顺序处理：

| 优先级 | 规则 |
|---|---|
| P1 | 连续性与可拍性：场景之间、集与集之间必须承接清楚，不能让生产线或观众猜中间发生了什么。 |
| P2 | 角色优先压缩：优先保留男主、女主、反派和关键关系人物；配角可简化，路人可删。 |
| P4 | 短剧节奏：遵守钩子、冲突、爽点、悬念的节奏要求。 |
| P5 | 篇幅控制：尽量控制在短剧单集体感内，但不能为了压字数牺牲 P1-P4。 |

如果连续性与篇幅冲突，优先补齐连续性，再压缩弱中段。

#### 基于分集规划改编

1. 遵守分集规划，只戏剧化规划中的场景、冲突和钩子。
3. 原文明确暗示的关键事件不能含糊跳过。可以合规降级表达，但不能让剧情功能消失。
4. 不编造分集规划之外的新情节。
5. 不编造原文没有的人物设定。
6. 不破坏因果。

#### 场景连续性硬规则

剧本会直接进入 AI 漫剧/视频生产线。缺少因果、空间、状态交代会造成生产失败。以下规则是硬规则：

1. 因果完整：角色受伤、昏迷、获救、拿到物品、知道信息，都必须有可见原因。
2. 空间连续：角色从一个地点到另一个地点，必须有移动或过渡动作，例如冲进楼梯、推门、转身离开。
3. 状态变化：能力、情绪、意识、立场变化，必须有触发过程。
4. 决策有依据：角色做战术选择时，必须有环境、威胁或逻辑依据。
5. 方案可信：路障、武器、逃跑路线等解决方案，必须交代来源和基本物理可行性。
6. 判断有信息源：角色下判断时，必须有看见、听见、触碰、闻到等可感知依据。
7. 场景衔接：上一场最后动作必须能接上下一场第一个动作。
8. 人物去向：上一场在场的具名人物，进入下一场时必须交代去向，不能无声消失。
9. 不重播上一集悬念：如果上一集结尾是危机、对峙或动作悬念，本集必须从下一个动作继续，不要重复描写同一瞬间。
10. 不跳过悬念兑现：如果上一集切在未解决威胁或关键动作中，本集开头 1-3 个节拍必须继续或解决该局面。
11. 时间跳跃要补桥：如果本集开头与上一集结尾时间不同，必须用伤痕、疲惫、换装、到达路径或环境时间标记补桥。
12. 物理设定锁定：上一集建立的刑罚方式、束缚方式、武器、交通工具等，下一集必须保持，除非剧中明确展示变化过程。

成稿前请在内部检查：每个新状态是否有原因、每次换地点是否有路径、每个决定是否有理由、每个判断是否有感知来源、每个场景首尾是否能接上、具名人物是否有去向、上一集悬念是否被即时承接。

#### 核心生成要求

1. 开头钩子：第一秒决定留存。不能慢热。可用强冲突台词、高冲击画面、名场面前置后倒叙。
2. 冲突密度：通常每集 2-3 个有效冲突/反转/紧张点。铺垫集可 1-2 个，高潮集可 3-4 个。不要为了凑数量硬造冲突。
3. 结尾悬念：遵守短剧节奏上下文中的全局尾钩与承接规则。
4. 干净开场：直接从本集剧本开始。第一行必须是当前集标题或导语集标题。
5. 不能无声：每集必须有台词、旁白、内心独白或画外音。动作戏也要用少量台词或 OS 承载心理。
6. 补足隐含动作：如果缺失的动作/反应会影响拍摄理解，可以增加简短功能节拍，例如迟疑、目光变化、身体反应、撞击反馈、空间过渡、情绪落点。
7. 信息密度：每场通常只承载一个重大戏剧变化，最多两个核心信息功能。
8. 结果必须有载体：优先写可见载体和结果，不只写抽象结果。
9. 把情绪可视化，例如“她觉得被抛弃”要转成低头、后退、攥紧手等行为。
10. 适度补充可拍的环境与感官细节。
11. 把对白压成短剧化的短句。
12. 严格执行场景连续性规则，让每个节拍形成“触发 → 行动 → 结果 → 反应 → 新压力”的链条。

#### 动作描写风格

每一行 `△` 都是最小动作描述，只写“谁做了什么”。

核心原则：一句一个动作，零装饰。

可以写：

△陈知冲进门，反手关上房门。
△沈遥攥住账本，指节发白。
△杯子摔在地上。

不要写：

△昏暗破败的长廊里，满身狼狈的陈知带着复杂又痛苦的神色冲进门，用尽全力关上门，声音震得所有人心口一颤。

动作硬规则：

- 每行 `△` 只写 1 个动作，1 个短句。
- `△` 行尽量 25 字以内，最多不要超过 35 字。
- `△` 行禁止堆砌颜色、材质、氛围、身体细节等装饰词。
- 不写镜头术语，例如特写、中景、俯拍、推镜头。
- 天气、光线、质感只有直接影响动作时才写。
- 人物首次出现可写：`人物名（年龄，核心特征）`，特征控制在 12 字以内。
- 人物再次出现只写名字，不重复外貌描述。
- 动作戏中，连续 3 行 `△` 后必须插入台词、OS 或画外音，不要长段无声动作。

#### 前三集世界观说明

如果当前是正文第 1-3 集，必须自然加入至少 2 句 OS 或台词，帮助观众理解核心世界设定：

- 这个世界发生了什么。
- 能力、规则或阶层如何运转。
- 主角的特殊能力、目标或困境是什么。

不要说明书式堆设定，要融入人物当下处境。

#### 台词风格

- 台词要短、狠、有压力，避免解释腔。
- 语气不明显时，台词可加 1-3 字动作/情绪括号，例如：`陈知：（冷声）让开。`
- 括号只写说话方式，例如冷声、咬牙、低声、急切、讥笑。
- 语境足够清楚时，可以不加括号。

#### 改编禁止项

- 不要写“错误”“应该为”“让我重新开始”等自我纠错内容。
- 不要大量使用全知旁白。
- 不要用纯画面解决所有台词需求。
- 不要为了凑镜头数量填充文本。
- 不要用不同角度重复同一个节拍。

#### 单集长度控制

1. 集数由 分集规划固定，不要新增集数。
2. 单集体感通常控制在 60-75 秒，重场戏可接近 80-90 秒。
3. 这是生成时的软约束。材料过多时，要先压缩弱节拍，而不是无限写长。
4. 起草前先明确当前集属于轻铺垫、标准集还是强爽点集，再分配开头、中段、结尾空间。
5. 每个新动作、台词、细节都必须有功能。
6. 角色首次描述必须短。
7. 台词避免长解释。
8. 如果超长，按顺序压缩：重复反应、重复羞辱/氛围、相邻动作行、台词、弱中段。
9. 开头钩子和结尾悬念最后再压缩。
10. 如果某个动作需要观众脑补关键过程，宁可补 1-2 个短功能节拍。
11. 悬念结尾要具体，必须指向某个物件、人物、证据、秘密或下一步风险。
12. 停在答案完全落地之前，不要在爽点之后继续拖尾。

#### 地点命名规则

- 如果没有固定地点引用，地点第一次出现后就锁定名称，后续集必须复用同一名称。

#### 人物与语气一致性

- 如果提供了人物语气参考，必须保持说话方式和社会身份一致。
- 具名人物首次进入本集某场景时，必须展示其进入、被看见、被提到或已在场的依据。不要让人物凭空出现。

#### 平台合规执行

2. 如果原文、分集规划和合规策略发生冲突，以合规策略为准，同时尽量保留原剧情功能。
3. 平台合规与可上架优先级最高，其次是剧情功能、连续性、情绪钩子、冲突、爽点和结尾悬念。
4. 不得原样呈现红线内容。
5. 不得正向呈现后宫、重婚、一女多夫、一男多女或多配偶关系。
6. 不得描写未成年人亲密关系或性化场景。
7. 不得描写明确血腥暴力、酷刑细节、色情细节或硬擦边内容。
8. 不得美化犯罪、教授违法方法，或让犯罪行为显得没有后果。
9. 必须通过合规替代表达保留剧情功能，例如谣言、伪造文件、假协议、家族压力、误会、画外结果、法律后果、舆论压力、情绪冲突。
10. 必须保持与前后集连续，不得为了单集合规改写而违背全局合规改编圣经。
11. 不要写合规解释，不要在剧本文本里说明“为了合规所以改写”。

### 戏剧化写作增强技能
### 参考范围

生成当前集剧本时，以下规则用于指导：

- 开头钩子
- 场景推进
- 人物行动目标
- 台词短句化
- 情绪递进
- 集尾悬念
- 爽点落地
- 合规改编后的戏剧张力保留

### 使用原则

1. 先让观众感到“不对劲”，再解释发生了什么。
2. 先给压力，再给原因。
3. 先让人物行动，再让人物解释。
4. 先制造选择，再制造后果。
5. 每场戏都必须推动剧情、关系、信息或情绪中的至少一项。
6. 不要用概括替代戏剧动作。
7. 不要用长篇 OS 替代人物行动。
8. 不要让冲突只停留在嘴上，必须有可见的局势变化。
9. 所有强化都必须基于原文、故事圣经 故事设定和 分集规划；不得为了套类型新增关键人物、身份、系统、重生、死亡、证据或危机。

### 技能规则

#### 1. 开场写法

开场必须快速给出压力点，避免铺垫式进入。

可选开场类型：

1. 冲突式开场：直接进入对峙、羞辱、逼问、争夺或阻拦。
2. 悬念式开场：先给出可见异常、证据、人物反应或未解问题。
3. 倒序开场：先放本集高压结果或高潮前一刻，再回到事件起点；只能用于 分集规划 已规划的本集事件。
4. 情绪开场：从主角被压迫、被背叛、崩溃、忍耐或爆发的瞬间切入。
5. 高潮前置开场：先把本集最强危机、反击前一秒或身份即将暴露的节点放在开头。

常见开头功能：

- 被羞辱开头：适合真假千金、豪门、复仇、逆袭等已有羞辱或舆论压迫的原文。
- 死亡重生开头：仅当原文已有死亡重生设定时采用，不得凭空新增重生。
- 系统觉醒开头：仅当原文已有系统、能力觉醒或类似金手指设定时采用。
- 身份反转开头：仅当原文已有隐藏身份、神豪、战神、少爷、赘婿等设定时采用。

这些开头类型是写法参考，不是剧情生成许可。

优先使用：

- 危机已经发生
- 人物正在被逼问
- 关键证据被亮出
- 关系当场破裂
- 反派正在行动
- 主角被迫做选择
- 上一集悬念的后果正在兑现

避免使用：

- 纯环境描写
- 长背景介绍
- 人物醒来后无目的闲逛
- 角色独自回忆但没有外部压力
- 用旁白概括说明上一集发生了什么

#### 2. 每场戏必须有行动目标

每场戏开始前，内部先明确：

- 谁想要什么
- 谁在阻止
- 如果失败会损失什么
- 这场戏结束后局势发生什么变化

场景不能只是“人物聊天”。如果必须聊天，也要让聊天承担明确功能：

- 逼问
- 隐瞒
- 试探
- 撒谎
- 威胁
- 交换条件
- 暴露关系
- 触发下一步行动

#### 3. 对白执行边界

对白具体写法归 `05_对白规则.md`。本规则模块 只检查三件事：

1. 对白必须嵌在场景行动和人物目标里，不能让剧情停下来解释。
2. 对白前后要有对手反应、动作变化或场景压力，形成攻防节奏。
3. 需要压缩对白时，优先删重复解释和寒暄；不能因此丢失 episode_card 要求保留的关键信息。


#### 4. 用画面推进，少用总结型 OS

OS 可以使用，但必须承担功能。

可用 OS：

- 角色表面不能说出口的判断
- 角色看见关键信息后的内心反应
- 观众必须知道但角色不能公开说的信息
- 动作戏中的短心理补位

避免 OS：

- 复述画面已经表现的内容
- 大段解释设定
- 总结人物性格
- 替代本该发生的动作

#### 5. 配角和工具角色必须参与行动

配角、路人、工作人员、保镖、护士、司机等角色不能只当背景。只要出场，就要承担至少一个功能：

- 传递信息
- 制造阻碍
- 提供误会
- 推动舆论
- 暴露证据
- 改变场面力量对比
- 逼主角做选择

#### 6. 情绪递进要一格一格升压

不要让人物情绪突然从平静跳到崩溃。情绪递进应有台阶：

1. 察觉异常
2. 试探确认
3. 被迫承认
4. 情绪压住
5. 外部压力加码
6. 终于爆发或反击

每一格都要有可见动作或台词触发。

#### 7. 人物反差与成长

人物张力来自反差、压力和选择。

可用反差：

- 性格反差：表面软弱、关键时刻强硬；表面冷漠、关键时刻保护。
- 身份反差：被看低的人拥有隐藏资源、能力、血缘、证据或话语权。
- 行为反差：前一刻退让，后一刻精准反击；前一刻被动，后一刻主动设局。

塑造人物成长时，遵守以下链条：

1. 冲突引发新动机。
2. 动机推动新行为。
3. 新行为带来局势变化。
4. 局势变化反过来逼人物升级。

不要用总结性旁白说“他成长了”，要通过行动、选择、台词和代价表现。

#### 8. 规划内容的剧本化兑现

开头钩子、爽点类型和集尾钩子由 `03_结构规划_开头_冲突_爽点_尾钩.md` 与当前 `episode_card` 决定。本规则模块 不重新设计这些结构，只负责执行成可拍正文：

1. 开头要直接进入 `episode_card.opening_state` 指定的压力、异常、冲突或后果链。
2. 爽点要通过证据出现、资源变化、站队变化、行动成功、反派误判或局势翻转落地，不靠角色口号说明。
3. 集尾必须停在 `episode_card.ending_hook` 指定的位置或同等功能位置，不在爽点完全结束后拖尾。
4. 如果 episode_card 的钩子或爽点不足，只能在 `risk_notes` 标记，不在剧本正文里临时新增关键事实。


#### 9. 合规场景下的戏剧张力保留

合规改编不是删除冲突，而是替换表达方式。

高风险表达被降级后，必须保留：

- 原剧情的压迫感
- 人物羞辱或误会
- 关系压力
- 反派目的
- 主角反击动机
- 观众期待的回报

可替代表达：

- 谣言替代真实关系
- 伪造协议替代高风险婚恋设定
- 舆论压力替代硬性羞辱
- 画外结果替代血腥细节
- 法律后果替代犯罪美化
- 情绪对峙替代擦边表达

### 示例参考
弱写法：

△她很生气，觉得所有人都在欺负她。
主角：你们太过分了。

增强写法：

△主角捡起地上的协议，指尖压住伪造签名。
主角：（冷声）这笔字，谁替我写的？
△反派脸上的笑僵住。

该写法让“生气”变成证据、动作、质问和反派反应。

# 05_对白规则

## 名称
05_对白规则

## 用途描述
用于 Step4 剧本生成，提供对白功能、人物声口、冲突台词和潜台词准则。

## 准则
### 短剧对白引擎

### 参考范围

参考问题：

- 对白太长
- 对白解释过多
- 人物说话同质化
- 对白不能推动剧情
- 爽点靠喊口号
- 情绪只靠 OS
- 人物行动和对白不一致

### 使用原则

1. 每句对白尽量只表达一个意图。
2. 少解释，多逼迫。
3. 少说结论，多制造对方反应。
4. 重要信息尽量通过质问、证据、隐瞒、打断或选择表达。
5. 台词要符合人物身份、关系位置和当下处境。
6. 对白必须服务剧情、关系、信息、爽点或悬念。

### 对白功能

#### 1. 逼问

用于迫使对方暴露信息或态度。

示例功能：追问证据、追问关系、追问动机。

#### 2. 威胁

用于加压，让人物必须行动。

威胁必须绑定具体代价，不要只说狠话。

#### 3. 隐瞒

用于制造悬念或误会。

隐瞒不能破坏观众理解，至少要让观众知道有信息差。

#### 4. 反击

用于完成局势翻转。

反击台词要配合证据、动作或资源变化，不能只靠气势。

#### 5. 情感推进

用于关系确认、破裂、试探、道歉或拒绝。

情感台词要具体，避免空泛表白和大段抒情。

### 人物声口

设计人物声口时，至少区分：

- 说话长短
- 情绪外露程度
- 攻击方式
- 是否爱解释
- 是否直接表达需求
- 是否回避真实情绪

不要让所有角色都用同一种短剧爽文口吻。

### 引用边界

使用时应直接影响剧本正文：

- 人物对白更短、更准、更有信息量
- 不同角色的声口更容易区分
- 对白推动冲突、关系、信息或情绪
- 减少解释性对白和无效寒暄

### 禁止越权

1. 不为了金句牺牲人物动机。
2. 不用台词解释本该被画面展示的事件。
3. 不在对白里新增原文没有的证据或秘密。
4. 不让人物突然知道自己无从得知的信息。
5. 不把全部 OS 改成对白；必要的内心信息可以保留短 OS。

---

### 长台词与独白控制

1. 单角色连续表达过长时，优先拆成“对方打断、反问、行动反应、信息递进、沉默压力”组成的互动冲突。
2. 独白只保留无法通过动作、表情、物件或对手反应表达的必要心理信息，且必须短。
3. 解释型台词要转成场面信息：证据、物件、手机内容、第三方反应、动作选择或当场冲突。
4. 台词不能为了解释设定而暂停剧情；每段对白都要推动关系、信息、冲突、爽点或悬念至少一项。
5. 角色连续发言如果超过两三句，必须检查是否可以插入对手反应、动作变化或场景压力。
6. 拆分长台词不能新增关键事实；只能改变表达方式和冲突节奏。

# 06_转场_闪回_连续性_格式

## 名称
06_转场_闪回_连续性_格式

## 用途描述
用于 Step4 剧本生成，提供转场、闪回、连续性和中文剧本格式准则。

## 准则
### 短剧时间与转场引擎


### 参考范围

参考情况：

- 有闪回
- 有倒序开头
- 有跨时间段叙事
- 场景地点频繁切换
- 角色从 A 地突然到 B 地
- 需要补充关键因果
- 上一集尾钩与下一集开头需要承接

### 使用原则

1. 转场必须保证观众知道时间、地点和人物状态。
2. 闪回必须服务当前冲突，不做纯回忆。
3. 倒序只能使用本集或已知事件，不能新增真相。
4. 时间跳跃必须交代触发点和后果。
5. 连续性优先于节奏压缩。

### 转场类型

#### 1. 动作转场

用人物行动连接场景，例如离开、赶往、打开门、接电话后切场。

#### 2. 物件转场

用证据、信物、照片、药、合同、手机信息等连接。

#### 3. 声音转场

用电话、广播、敲门、警报、音乐或对白尾音连接。

#### 4. 情绪转场

用人物情绪从上一场延续到下一场，但必须有具体动作承接。

#### 5. 时间标识转场

用于必要跳时，例如“翌日清晨”“三小时后”。不能用时间标识跳过关键因果。

### 闪回使用规则

闪回只能用于：

- 揭示人物动机
- 补充关键因果
- 展示过去创伤
- 解释当前误会
- 释放部分真相

避免：

- 连续大段闪回
- 闪回中再套闪回
- 用闪回替代当前行动
- 用闪回解释观众已理解的信息

### 引用边界

使用时应影响以下内容：

- 场景之间的连接方式
- 闪回是否必要
- 闪回如何自然引出
- 时间跳跃是否清楚
- 跨场和跨集连续性

### 禁止越权

1. 不用转场跳过关键因果。
2. 不让角色无解释瞬移。
3. 不让闪回新增原文没有的核心事实。
4. 不把倒序开头写成本集以外的未知大事件。
5. 不为了节奏牺牲观众理解。

### 中文剧本格式规范
### 参考范围

本规范约束：

- 集标题
- 场景标题

- 人物首次出场

### 制作铁律

#### 1. 禁用镜头清单

1. 空镜 / 建立镜头：纯风景、纯环境、无人物动作。
2. 慢镜头：任何形式的慢动作回放。
3. 发呆镜头：角色呆站、沉思、望向远方、白日梦。
4. 背影镜头：拍摄人物后脑勺或背面作为主要表达。
5. 让观众猜角色意图的模糊镜头。
6. 淡入、淡出、叠化等软转场。
7. 纯回忆、纯闪回集。
8. 纯铺垫、纯独白、纯日常镜头。

说明：禁止的是无功能废镜头。必要的动作桥、反应桥、空间确认、信息落点、结果反馈可以保留。

#### 2. 场景连续性

场景之间必须保证行动、空间、人物状态连续。不得让人物、物品、地点、伤势、关系状态突然变化。

#### 3. 对白格式边界

本规则模块 只规定对白在剧本中的呈现格式和连续性位置；对白功能、声口、长短、潜台词和独白控制归 `05_对白规则.md`。

1. 对白必须标明说话角色。
2. 同一场景中对白要和人物动作、位置、转场状态保持连续。
3. 画外音、OS 和普通对白必须区分清楚。
4. 不在本规则模块 中重复维护对白写法准则。


### 格式规范

#### 1. 语言要求

全部使用简体中文。所有场景描写、对白、舞台指示、标注全部使用中文。

例外：`VO` / `OS` 作为结构缩写允许保留。

#### 2. 集标题

每集以集标题独立成行。

格式：

第{EP}集

规则：

- 使用阿拉伯数字，不使用中文数字。
- 第一个非空行必须是当前请求集数的标题。
- 集标题与第一场之间保留一个空行。

#### 3. 场景标题

格式：

场{EP}-{SCENE} 地点 时间 内/外

示例：

场3-1 医院走廊 夜 内
场3-2 小区门口 黄昏 外

规则：

- `场` 后的前半段必须等于当前集号。
- 当前是第 3 集时，只能写 `场3-1`、`场3-2`，不能写 `场1-1`。
- 地点名称要稳定，首次出现后后续复用。
- 时间优先使用：日、夜、清晨、上午、中午、下午、傍晚、深夜、黎明、黄昏。
- 室内外用 `内`、`外` 或 `内/外` 标明。

#### 4. 人物列表

场景标题后紧跟人物列表。

格式：

人物：角色A、角色B、保镖*2

规则：

- 群众演员用 `*N` 表示。
- 仅以声音出现的角色加 `VO`，例如 `助理（VO）`。
- 人物列表中只写本场实际出现或发声的人物。

#### 5. 人物首次出场

角色在全剧首次出场时，在动作行内简要标注：

△林夏（24岁，白衬衫）推开病房门。

规则：

- 标注控制在 16 字以内。
- 年龄必须保持一致。
- 后续再次出现直接使用角色名，不重复外貌描述。
- 只有外貌发生剧情相关变化时，才重新补充描述。

#### 6. 舞台指示 / 动作描写

使用 `△` 标记动作行。

规则：

1. 使用现在时。
2. 描写具体、可视化、适合拍摄。
3. 每个 `△` 行优先只承载一个核心动作变化。
4. 不写空泛抒情句。
5. 不只写结果，要尽量写清结果如何发生。
6. 不堆叠过多新设定、新能力、情绪翻转或他人反应。
7. 每集最多 2 行纯氛围/环境描写。

#### 7. 镜头标注

`△` 行不写镜头类型，不写运镜指令。

禁止：

- 特写
- 中景
- 远景
- 俯拍
- 推镜头
- 慢动作
- 色调
- 构图

#### 8. 对白

格式：

角色名：（语气）台词。
角色名：台词。

规则：

- 语气括号可选，只写说话方式，例如冷声、咬牙、低声、急切、讥笑。
- 对白内容遵守 `05_对白规则.md`，本处只规定呈现格式。

#### 9. 画外音与画外声

格式：

角色名OS：内心独白。
角色名VO：画外音。

规则：

- OS 用于内心判断、隐藏动机、关键信息反应。
- VO 用于画外声音、电话声、广播声等。
- 不要用 OS 复述画面。

#### 10. 闪回

闪回必须穿插在当前剧情中，不能整集纯闪回。

格式：

闪回：三年前，医院走廊。

规则：

- 闪回必须有触发物或触发台词。
- 闪回结束后必须回到当前场景。

#### 11. 场景转换

只允许硬切式转换。

可写：

△林夏推门冲出病房。

场3-2 医院楼梯间 夜 内
人物：林夏
△林夏扶着墙停下。

禁止写：

- 淡入
- 淡出
- 叠化
- 镜头切换到

#### 12. 音效

音效只在推动剧情或制造压力时使用。

格式：

音效：手机震动。

#### 13. 屏幕文字 / 插入画面

格式：

屏幕文字：银行卡余额不足。
插入画面：监控截图显示林夏进入医院。

规则：

- 必须是观众需要看见的信息。
- 不要滥用。

#### 14. 通用排版

1. 场与场之间保留一个空行。
2. 同一场内不要出现无意义空行。
3. 不使用 Markdown 标题。
4. 不使用代码围栏。

### 示例引用边界

完整剧本示例统一参考 `08_示例库.md`。本规则模块 只维护转场、闪回、连续性和格式准则，不重复保存完整示例片段。

---

### 干净转场与视听表达

1. 转场必须短、清楚、有功能；不要为了表现“电影感”写长铺垫、长空镜或无信息镜头。
2. 场景切换优先使用动作、物件、声音、手机信息、门铃、脚步、警报、证据露出等可拍触发点。
3. 回忆和前情信息优先考虑闪回、物件触发、声音触发、画面反差或角色即时反应，不只依赖角色口头解释。
4. 音效、光影、镜头提示只能在推动压力、悬念、记忆触发或信息揭示时使用；不能作为装饰性描写堆叠。
5. 需要承接上一集尾钩时，转场要直接进入尾钩后果，不重播、不绕远、不用大段解释稀释紧张感。
6. 视听表达必须服务剧情可拍性和观众理解，不牺牲因果清晰度。

# 07_小程序短剧适配

## 名称
07_小程序短剧适配

## 用途描述
用于 Step2 拆集节奏、Step3 分集节奏和 Step4 小程序短剧表达适配。

## 准则


### 平台适配边界

1. 本规则模块 是平台适配层，只约束小程序短剧的观看体感、信息密度、留存压力和表达速度。
2. 开头、冲突、爽点、尾钩的具体结构设计归 `03_结构规划_开头_冲突_爽点_尾钩.md`。
3. 对白写法归 `05_对白规则.md`；转场、闪回、格式归 `06_转场_闪回_连续性_格式.md`。
4. 本规则模块 不能以平台节奏为理由新增关键事实、改人物关系、跳过因果链或替代上游规划决策。

### 小程序短剧默认目标配置


### 参考范围

默认启用场景：

- 用户没有另行指定平台
- 当前产品流程默认服务小说或灵感转小程序短剧
- 故事圣经 需要确定故事理解的目标方向
- 分集规划 需要确定分集节奏、爽点和尾钩密度
- 剧本生成 需要确定剧本正文的进入速度、对白密度和场面化程度

不适用场景：

- 用户明确指定精品短剧、横屏剧、长剧、电影或海外短剧
- 用户要求先做多个平台方向对比
- 用户要求做投稿或市场报告

### 使用原则

1. 用户明确指定平台时，以用户指定为准。
2. 未指定时，默认按小程序竖屏短剧处理。
3. 目标配置只约束表达方式、节奏和规划重点，不新增剧情事实。
4. 不用市场标签替代人物、冲突和因果判断。
5. 不为了迎合热门题材新增原文没有的系统、重生、战神、神豪、隐藏身份或关键关系。

### 默认目标

#### 1. 观看体验

小程序短剧优先满足：

- 开头快进入人物困境
- 冲突表达直观
- 关系张力清楚
- 每集都有推进
- 爽点、虐点、反转或悬念高频出现
- 结尾停在观众想继续看的变化点前后

#### 2. 分集策略

分集规划 规划时优先保证：

- 每集有明确行动目标
- 每集有可见阻力
- 每集有局势变化
- 前几集尽快建立主角困境、核心关系和追看问题
- 尾钩不是空喊悬念，而是绑定下一集的关键变化
- 不把大量世界观、背景或心理解释堆在开头

#### 3. 剧本表达

剧本生成 生成时优先保证：

- 场景切入要快
- 台词短、直接、有动作目的
- 情绪尽量通过动作、对话和局势变化呈现
- 反击、误会、真相、选择、危机要有明确画面承载
- 可以保留必要的铺垫，但铺垫必须服务本集推进

### 引用边界

如果用户明确切换目标平台，应改用，改用用户指定的平台目标。

### 禁止越权

1. 不覆盖用户指定的目标平台和受众。
2. 不根据平台目标强行改变原作核心人物关系。
3. 不为了追求强刺激新增关键设定、关键证据或关键人物。
4. 不让节奏规则破坏因果链、人物行动逻辑和场景连续性。

---

### 小程序短剧适配


### 参考范围

小程序短剧、竖屏付费短剧、强转化短剧或默认未指定平台。

### 核心目标

小程序短剧优先服务：

- 快速进入
- 强冲突
- 强追看
- 高爽点密度
- 明确情绪回报
- 明确单集尾钩
- 付费点前卡

### 使用原则

1. 情绪必须直观，关系必须清楚。
2. 每集要有推进，不能只铺垫。
3. 开头要快，中段要有局势变化，结尾要有事件型钩子。
4. 爽点和虐点要服务主线，不机械堆叠。
5. 逻辑可以压缩，但因果不能断。
6. 连续性和可拍性高于刺激强度。

### 故事理解阶段适配

在故事理解阶段，补充：

- 核心追更机制
- 主要爽点类型
- 主角反击路径
- 目标观众
- 高点击关系
- 可前置的原文已有爆点

不得在故事理解阶段写成完整分集。

### 分集规划阶段适配

在分集规划阶段，检查每集：

- 是否有开头钩子
- 是否有主要冲突
- 是否有爽点或情绪推进
- 是否有事件型尾钩
- 是否承接上一集尾钩
- 是否避免重复同类钩子

已有分集边界时，仍必须尊重既定素材范围。

### 剧本生成阶段适配

在剧本生成阶段，强化：

- 前 3 秒高能信息
- 行动先于解释
- 对白短句化
- 冲突外化
- 情绪递进
- 反击可见
- 结尾卡在兑现前

不得为了小程序节奏跳过人物得知信息、抵达地点、做出选择的必要过程。

### 小程序风险检查

需要标记：

- 开头慢
- 单集无冲突
- 尾钩弱
- 爽点兑现太晚
- 反派手段重复
- 主角长期被动
- 对白太文学化
- 情绪只有 OS 没有行动
- 因果链被压缩断裂

### 引用边界

使用时应影响以下内容：

- 故事理解中的追更机制
- 分集规划中的开头、冲突、爽点和尾钩
- 剧本正文的节奏、对白和情绪密度
- 生成后的自查和返修方向

### 禁止越权

1. 不以小程序节奏为理由新增关键设定。
2. 不以强爽点为理由破坏原文因果。
3. 不以付费点为理由让尾钩脱离本集事件。
4. 不把所有人物写成标签化工具人。
5. 不让逻辑断裂来换取快节奏。

---

### 信息密度与集数匹配

1. 小程序短剧可以快，但不能把一个无足够信息量的原文片段硬撑成完整一集。
2. 如果单集只剩铺垫、寒暄、重复解释或弱情绪，应标记为节奏风险，优先考虑压缩表达或交给上游流程确认。
3. 目标集数与素材体量冲突时，技能准则只能提示风险；是否改集数、合并拆分、重排剧情，需要由 prompt 字段和后续 agent/workflow 决策承接。
4. 单集内部节奏要优先保留“压力进入—冲突推进—信息变化—钩子离场”的链路，不用无功能桥段填满长度。
5. 追更节奏来自持续变化，而不是持续吵闹；每集必须让观众获得新的危险、证据、关系变化、爽点承诺或情绪债。

# 08_示例库

## 名称
08_示例库

## 用途描述
用于 Step4 剧本生成的格式、表达和节奏参考；仅作示例参考，不作为硬性剧情规则。

## 准则
### 中文示例库
### 参考范围

生成当前集剧本时，参考以下示例的：

- 场景标题格式
- 人物列表格式
- `△` 动作行写法
- OS / VO 用法
- 短句对白节奏
- 冲突推进方式
- 集尾钩子写法

### 使用原则

1. 学习示例的写法，不要照抄示例人物、地点、台词或剧情。
2. 示例只提供风格参考，实际剧本必须服从当前集分集规划。
3. 示例中的台词密度、动作密度、悬念位置可以参考。
4. 不要写“参考示例”“以下为剧本”等解释文字。

### 示例 1：都市情感，对白密集 + OS 展现心理

第5集

场5-1 会议室 日 内
人物：林夏、周曼、顾沉、员工*3
△周曼把一份协议摔到会议桌中央。
周曼：（冷笑）你不是说没人能证明吗？
△林夏低头，看见协议末尾的签名。
林夏OS：这不是我的字。
△员工们交头接耳。
员工甲：（小声）签名都在，她还怎么解释？
△顾沉伸手拿起协议，目光停在印章边缘。
顾沉：（低声）这章，盖反了。
△周曼脸上的笑僵住。
林夏抬眼，看向周曼。
林夏：（平静）你急着逼我认，是怕我查到谁替我签的？
△周曼后退半步，手指按住桌沿。

写法要点：

- 开场直接给证据压力。
- OS 只补关键信息，不解释情绪。
- 爽点来自证据反转，不靠人物喊赢。
- 集尾可继续接“谁替签”形成追更。

### 示例 2：动作危机，动作场景中用 OS 补心理

第8集

场8-1 废弃楼梯间 夜 内
人物：陈知、黑衣人*2、沈遥
△陈知扶着栏杆往上冲。
△黑衣人从下方追上来，伸手抓住他的外套。
陈知：（咬牙）松手！
△陈知反手砸向墙边的消防箱。
音效：玻璃碎裂。
△沈遥站在楼梯平台，手里攥着手机。
沈遥：（急切）我已经报警了！
△黑衣人停了一瞬。
陈知OS：他们怕警察。
△陈知抓起消防箱里的扳手，挡在沈遥身前。
△楼下传来另一阵脚步声。
沈遥：（低声）不止两个。
△陈知抬头，看见楼梯转角出现第三个人。

写法要点：

- 动作行短，连续动作中穿插台词和 OS。
- OS 承担判断功能。
- 结尾给出新威胁。

### 示例 3：合规改编，保留羞辱和反击功能

第12集

场12-1 小区广场 傍晚 外
人物：林夏、王阿姨、邻居*4
△王阿姨把一张照片举到众人面前。
王阿姨：（尖声）你还敢说自己清白？
△照片上，林夏站在陌生车旁。
邻居甲：（小声）这车不是她家的吧？
△林夏看着照片，忽然笑了一下。
林夏：（冷声）你截掉了后半张。
△林夏点开手机，把完整监控投到物业屏幕上。
屏幕文字：社区志愿接送记录。
△王阿姨脸色一白。
林夏：造谣前，至少把图修干净。

写法要点：

- 用“照片造谣”替代高风险关系表达。
- 保留公开羞辱、围观压力和反击爽点。
- 证据落地后反派当场失去主动权。

### 示例 4：集尾钩子，停在答案落地前

第16集

场16-3 档案室 夜 内
人物：顾沉、林夏
△顾沉拉开最底层抽屉。
△一个旧档案袋掉到地上。
林夏：（低声）这是我母亲的名字。
△顾沉拆开封口，里面露出一张泛黄的出生证明。
△林夏伸手去拿。
音效：门锁轻响。
△两人同时回头。

写法要点：

- 已经亮出关键物件，但答案未完全落地。

# 09_非小说素材与故事种子

## 名称
09_非小说素材与故事种子

## 用途描述
用于非小说链路的素材整理和故事种子开发，提供灵感、梗概、零散文案、人物设定、桥段、台词、卖点和世界观材料转短剧故事的参考准则。

## 准则
### 非小说素材整理准则

1. 用户明确提供的事实、限制、口吻、人物关系、卖点和禁区必须优先保留。
2. 零散素材要先判断类型：灵感、梗概、人物设定、情节点、台词、世界观、卖点、风格参考、限制条件或待确认信息。
3. 不把用户没有明确提供的内容写成用户事实；模型推断、原创补全和待确认信息必须分开处理。
4. 素材不足时可以指出缺口，但不要为了完整性强行写死关键主线、人物底层动机或结局方向。
5. 用户给出的高价值表达，包括原句、口吻、卖点、人物关系、反差设定和情绪方向，应优先作为后续故事开发依据。
6. 没有功能的素材不要硬塞进主线；可暂存为候选，不影响核心故事判断。

### 故事种子开发准则

1. 故事种子必须围绕主角目标、核心阻力、情绪驱动力、关系张力、爽点承诺和追更钩子建立。
2. 原创补全只能服务用户素材的放大和连贯，不得偏离用户提供的核心梗、目标受众和禁区。
3. 非小说输入没有原文边界，因此不能假装存在小说章节或原文断点；体量、阶段和分集应交给后续规划步骤决定。
4. 故事种子阶段可以提出体量倾向和风险，但不直接拆单集、不写完整分集卡、不进入剧本正文写作。
5. 需要补人物时，优先补功能明确的人物：推动目标、制造阻力、暴露信息、承接情绪或兑现爽点。
6. 需要补桥段时，优先补因果桥段、选择压力、误会/信息差、证据露出和关系变化，不补无功能日常。
7. 非小说故事可以原创，但每个关键新增都要能解释它服务的剧情功能。

### 短剧化判断准则

1. 优先寻找一句话能讲清的核心梗，以及能让观众立刻理解的主角困境。
2. 优先建立强目标、强阻力、强情绪债和清晰的阶段爽点。
3. 如果素材偏散，先收束为一条主线；不要同时展开多个同等重要的方向。
4. 如果素材偏概念，优先补人物、关系和具体事件；不要停留在抽象主题。
5. 如果素材偏设定，优先找到可拍冲突和人物选择；不要把故事写成设定说明。
6. 如果素材偏台词或金句，必须判断它适合哪个人物、哪个场景和哪个冲突功能。
7. 所有短剧化强化都要服务后续系列体量设计、分集规划和剧本生成，而不是单独追求概念好看。

### 禁止越权

1. 不把素材整理写成完整故事。
2. 不把故事种子写成分集规划。
3. 不把原创补全伪装成用户提供素材。
4. 不为了强爽点偏离用户给定的核心方向。
5. 不用大量世界观说明替代人物目标和冲突。

# 10_视频高还原剧本生成规则

## 名称
10_视频高还原剧本生成规则

## 用途描述
仅供 `video_to_script_extract` Skill 使用，约束单集漫剧视频到高还原剧本初稿的生成。该规则模块服务剧情和主要对白还原，不承诺逐帧 OCR 或 100% 逐字转录，也不服务剧情改编或爆款分析。

## 准则

### 信息来源与目标

1. 画面用于理解剧情、人物、地点、动作、表情、关键道具和事件结果。
2. 内嵌字幕与清晰音频共同用于还原主要对白；音频可辅助断句和识别说话人。
3. 屏幕文字、系统提示和弹幕仅在与剧情理解相关且内容可确认时记录。
4. 第一目标是核心剧情、因果、人物关系、主要对白、反转和结尾钩子正确。
5. 任何来源无法确认时使用不确定标记或保守表达，不得根据剧情常识补写。

### 忠实还原

1. 可确认的主要对白尽量保留原句，不润色成另一种表达。
2. 不使用“某人表示”“某人解释”“某人质问”“两人争吵”等概述替代明确台词。
3. 短暂字幕或音频片段无法完整确认时，不拼接成看似完整但未经确认的台词。
4. 不要求为了形式完整而记录与剧情无关、重复出现或无法确认的屏幕文字。
5. 不声称输出是逐帧 OCR 结果或完整逐字稿。

### 不确定信息

1. 台词明确但说话人不明时使用 `未知人物`。
2. 无法确认人物身份时不得擅自使用角色名；不得把弹幕评价、人物外观或模型推断当作姓名。
3. 分别使用 `［听不清］`、`［看不清］`、`［字幕遮挡］`、`［多人重叠，无法辨认］` 和 `［无法确认说话人］`。
4. 视频没有明确呈现的信息写“视频中未明确呈现”。

### 场次组织

1. 按剧情单元拆场，不按镜头、单句台词、短动作、系统弹窗或表情变化拆场。
2. 同一地点、同一时间段、同一组人物围绕同一剧情目标推进的内容合并为同一场。
3. 场次数量服从实际剧情，不强制凑满 2 至 5 场。
4. 短视频可以只有一场；不足 20 秒的连续片段优先并入前后相关场次。
5. 每场记录地点、内外景、时间段、整体时间码、出现人物和至少一条场景建立动作。

### 编剧提取稿格式

1. 动作行以 `△` 开头，只记录理解剧情所需的环境、状态、关系冲突、关键道具、伤势、表情和动作。
2. 不使用镜头转向、特写、近景、远景、推镜、航拍、慢动作、色调等导演分镜语言。
3. 表情或动作提示只用于情绪变化、冲突升级、伪装、威胁或反击，控制在 2 至 8 个字。
4. 对白、OS、VO、旁白、系统提示和屏幕文字必须分开记录。
5. `script_text` 与结构化 `scenes[].blocks[]` 必须表达同一份完整剧本。

### 闪回

1. 过去时间线、回忆、前情或想象式回看必须用 `【闪回】` 与 `【闪回结束】` 完整包裹。
2. 短闪回嵌入当前场，不单独编号。
3. 闪回内部继续使用动作、对白、OS 和 VO。
4. 闪回结束后必须明确回到当前时间线。

### 追溯要求

1. 时间码尽量准确到秒。
2. 每个场次必须绑定原视频及对应时间范围。
3. `file_id` 必须沿用输入中的真实值，不得输出占位符。
4. 剧情概要只能概括已还原剧本中存在的事实。

### 使用边界

1. 本规则模块只用于视频到高还原剧本初稿。
2. 不用于小说转剧本或非小说素材创作。
3. 不输出亮点、爆款分析、传播价值、改编建议或优化建议。
4. 不参与主 Agent 的 Skill 路由，仅由 `video_to_script_extract` Skill 的提取步骤按需加载。
