# 当前 Main Agent 与 Eino 运行规范

更新时间：2026-07-20

## 运行架构

正式运行链路为：

```text
React / TypeScript 前端
-> Go HTTP 服务
-> Eino Main Agent Graph
-> 业务 Guard
-> Eino Content Worker Graph
-> 模型 Provider
-> Go Runtime + SQLite
```

`N2S_RUNTIME` 默认是 `eino`。`native` 仅作为显式回滚选项；项目不存在“未来再接 Eino”或“先由 Mock 承载正式流程”的阶段。

Eino 负责模型节点和编排图，不接管作品、Run、Artifact、审批和事件的业务状态。业务状态只由 Go Runtime 持久化。

## 模型分工

- 控制模型：理解用户意图、判断来源模式、定位修改目标、决定下一动作和生成自然语言回复。
- 业务 Guard：校验模型决定是否符合当前 Run、审批、选区、附件和配置状态；模型回复本身不能触发执行。
- 内容模型：按指定节点生成或修改 Artifact，不负责决定产品流程。

主控与内容模型输入不同。主控只做判断和回复；内容模型接收已定位的目标、必要上游、生成配置、局部上下文和用户要求。

## 当前意图与动作

Main Agent 支持闲聊、小说生成、非小说生成、确认节点、暂停、恢复、带补充继续、修改产物、查看产物、查看附件、重试失败步骤和解释当前状态。

动作只允许为：回复、启动 Run、确认、暂停、恢复、修改、查看产物、查看附件、重试失败步骤或明确不支持。

明确且可执行的修改直接执行；目标、范围或预期效果不明确时先追问。追问期间不能后台开始修改，也不能用“我会生成新版本”替代真实执行结果。

## 上下文策略

Main Agent 每轮使用：当前用户消息、作品与 Run 状态、当前步骤和审批、用户正在查看或选中的 Artifact、选区快照、附件摘要、最近对话、最近事件和 Artifact 摘要。

内容模型按任务最小化输入：

- 局部修改：目标字段、实体、集合、段落、场景、单集或跨行选区，加必要上下文；
- 拆分某一集：目标集原文为主，补充相邻集边界和必要故事事实；
- 整体重生成：目标 Artifact 的完整必要输入和直接上游；
- 查看附件：只读取被本轮意图命中的附件；
- 不把整部原文、全部聊天和全部 Artifact 无差别传给每次调用。

选区发送时形成不可变快照，包含 Artifact、版本、行/场景定位、偏移、前后文和哈希；发送后的用户继续编辑不能改变已经发出的请求。

## 失败与超时

模型 HTTP 默认请求超时为 180 秒。识别到超时或 504 时，Run 记录公开错误码并向用户明确显示“模型服务超时”，同时保留失败任务 cursor 供重试。控制模型失败只能降级为安全回复，不能猜测执行动作。
